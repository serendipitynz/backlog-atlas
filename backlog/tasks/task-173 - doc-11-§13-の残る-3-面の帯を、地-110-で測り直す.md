## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-164 が地の 1rem を webview 既定の 110% へ上げたので、doc-11 §13 の実測表 6 行の px はすべて動いた。**同回で測り直せたのは 3 面だけである** — タスク詳細（閲覧）・タスク詳細（編集セッション）・設定モーダル。残る 3 面が残った理由は 2 通りある。

**スイムレーン**: 測り方が `position: sticky` を持つ要素を全部足す形だったので、レーンヘッダ行 3 本＋列ヘッダ行 5 本の計 8 行（284.45px）を引いた。§13 の表が数えているのは**同時に貼り付いている 2 層**なので、別の量である。**過大な引き方でも 640×480 で上限の 2.6 倍あり規則は満たす**が、表へ載せられる値ではない。**要るのは「いま現に貼り付いている固定行」だけを足す測り方**で、面の内容上端・下端との距離で判定する。

**プロジェクト登録モーダル**と**プロジェクト詳細の文書ペイン（編集）**: `_sandbox/app-check` の標本では 1280x800・640x480 のどちらでも中身が面に収まり、**スクロールする面が立たなかった。** 帯という量が生じない状態であって、規則を満たしたのでも割ったのでもない。**面を現にスクロールさせる標本を先に作る**（長い本文・多い項目）。

手順とハーネスは `_sandbox/text-scale-check/band-table.mjs`（doc-11 §10 が指している）。**この回のハーネスをそのまま使わない** — 上の 1 つ目が、そのハーネスの測り方そのものの欠けだからである。
