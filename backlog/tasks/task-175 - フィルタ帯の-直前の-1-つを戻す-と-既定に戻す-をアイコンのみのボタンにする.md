## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
フィルタ帯（doc-7 §5.2）の 直前の 1 つを戻す と 既定に戻す を、可視の文言を持つボタンからアイコンのみのボタン（doc-11 §2.4）へ替える。図形はユーザー指定で、直前の 1 つを戻す が lucide の undo、既定に戻す が refresh-ccw（2026-08-15）。帯の横幅をこの 2 つの語が占めているのを縮めるのが目的で、操作そのものと到達経路は変えない。

判断が 1 つ要る。refresh-ccw を 既定に戻す へ与えることが doc-11 §2.4 の「同じ図形を別の操作へ与えない」に反しないかである — 再読込（App.svelte の 該当行を再読込、Swimlane の 再読込）はまだ図形を持たず、将来同じ系統の図形を要求しうる。着手時に判定を書いてから図形を置く。

対応順では TASK-82 の起票した統合の実装より前に置く。小さい方を先に済ませて、統合のレイアウトを最終形の控えに対して行うためである。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 判定 (AC #3)

`refresh-ccw` を 既定に戻す へ与えてよい。判定は doc-11 §2.4 の 同じ図形を別の操作へ与えない の 3 つ目の子項に書いた。争点だった 再読込（レーンヘッダ行の 再読込、上部帯 ④ の 該当行を再読込）は**まだ図形を 1 つも持っていない**ので、同じ図形を 2 つの操作が持つ状態がそもそも無い。判定が閉じるのは 再読込 の側の将来の選択肢のほうで、あの控えに図形を与える回は `refresh-ccw` そのものに加えて `refresh-cw` も取れない — 2 つが揃った時点で向きで対になる図形、すなわち族になり、族に入る図形は族の側で判定するのが §2.4 の要求だからである。スイムレーン画面ではフィルタ帯とレーンヘッダ行が同時に出るので、共用すれば 行末の入口に `chevron-right` を共用しない と同じ形の衝突になる。

## 図形 (AC #2)

lucide-react v1.17.0 の `dist/esm/icons/undo.mjs`・`refresh-ccw.mjs` の `__iconNode` から写した。**照合は両側を import して行った**（正規表現で読むと `.mjs` の折り返しを取り逃す。最初にそれで 4 件の偽の差を出した）— `ICONS` の 23 図形すべてが v1.17.0 と一致し、差は 0 件である。

**`IconShape` の列挙は増えていない** — `undo` は `path` 2 本、`refresh-ccw` は `path` 4 本で、どちらも既存の 1 種類しか使わない。よって AC #2 の「列挙を増やすなら描画も型で止まることを確かめる」は条件が立たなかった。増やしていないことを確かめたのであって、型で止まることを確かめたのではない。

## 実測 (AC #6)

借り物 playwright / WebKit / viewport 1200×800 / `_sandbox/filter-check/`（本物の `FilterBar.svelte` が載る）。**ハーネスの妥当性は既存値の再現で先に確かめた** — 控えの高さ 24.63px は `.control` の註が記録する 22.39px の 1.1 倍で、doc-11 §2.2 が地を 110% にした後の値として合う。

| 対象 | 変更前 | 変更後 |
|---|---|---|
| 帯（既定。トークン 1 つ・1 行） | 1200 × 36.16 px | 1200 × 36.16 px |
| 帯（トークンが折り返す状態） | 1200 × 95.97 px | 1200 × 66.08 px |
| 2 つの控えが占める幅（`.actions`） | 247.44 px | 54.52 px |
| 直前の 1 つを戻す | 169.09 × 24.63 px | 24.63 × 24.63 px |
| 既定に戻す | 73.08 × 24.63 px | 24.63 × 24.63 px |

**帯の 1 行の高さは変わっていない**（doc-7 §5.2 の 帯の高さは 1 行のまま）。**トークンが折り返していた状態では帯が 29.89px 縮んだ** — 空いた 192.92px にトークンと 並び順 が 1 行で収まったためで、幅の節約がグリッドの高さとして返っている。

図形の実寸は 11.95px 角で、トークンの解除の `x` と「＋ 絞り込み」の字と同じ段（`--text-sm`）。帯の先頭の funnel だけが 13.02px と一段大きい。

## 名前と理由の到達経路 (AC #1・#4)

WebKit で属性を読んだ値。

- 直前の 1 つを戻す … `aria-label` 「直前の 1 つを戻す」（和音を含まない）、`aria-keyshortcuts` `Backspace`、可視の文言 0 字、`<svg aria-hidden="true">` で `path` 2 本。押せるときの `title` は「最後に足した条件を 1 件戻します（Backspace）」、押せないときは理由文。
- 既定に戻す … `aria-label` 「既定に戻す」、`aria-keyshortcuts` なし（doc-7 §5.2 が意図的にキーを割り当てていない）、`title` は「すべての条件を外し、保存区分を既定へ戻します」／押せないときは理由文。
- 両方とも `aria-disabled` とフォーカス可能のまま（`disabled` にしていない）で、`aria-describedby` の指す先が DOM に残り、文も一致した（doc-11 §5 の 2 つ目の形）。**帯に刷っていた可視の和音は落とした** — doc-7 §2.1 が、文言を持たない操作の隣にキーだけを刷るとアイコンのみという形が成立しないと定めている。

## 測っていないこと

実機 3 OS での見え方（この環境は `screencapture` が使えない）。**目視で見てほしいのは図形の大きさ**で、単独のボタンの既定 1rem ではなく帯の段（`--text-sm`）を取っている。根拠は doc-12 §4.3 の寸法表が この 2 つの控えに与えた大きさ で、帯の中で先に読まれるべきものを変えないためだが、11.95px が小さすぎないかは目でしか決まらない。
