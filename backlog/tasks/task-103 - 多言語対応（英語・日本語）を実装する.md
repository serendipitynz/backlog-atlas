## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
UI の文言を英語と日本語で切り替えられるようにする、その機構と 表示言語 の永続を持つ。**画面文の抽出そのものは TASK-182 が持つ**（下の 2026-08-16 の項）。

m-3 に置く根拠はユーザーの明示的な判断である（2026-08-01）。多言語対応はユーザーが v0.1.0 までに必要と列挙した項目の 1 つだが、置き場を選択肢つきで確認したところ m-3 が選ばれた。理由は、m-2 の UI 改修（TASK-61〜80）で文言そのものが動くため、文言が固まる前に抽出すると同じ箇所を 2 度触ることになり、v0.1.0 の対象利用者は日本語で、README は既に和英そろっているため。UI 改修が終わった後に 1 度だけ抽出するほうが総コストが低い。

したがって「m-2 の範囲」（ユーザーが列挙した項目と、それ以外で公開阻害に当たる項目の和）の列挙側から、多言語対応はユーザー判断により除かれている。この明記が無かったため、台帳が定義と矛盾しているとレビューで指摘された（2026-08-01）。

**2026-08-16 追記（分割）**: 着手セッションが規模を実測したところ、画面文はコメントを剥がした後で 46 ファイル・941 行あり、これに crate 側 28 本の 失敗理由符号 化と wire の作り直しが加わって 1 セッションに収まらなかった。**ユーザーの判断で、機構を持つ回と抽出を行う回に分けた。** 本タスクは機構と 表示言語 の永続を持ち、**受入条件のうち 3 件（全画面の外部化・抽出漏れの検出手段・英語レイアウト）を TASK-182 へ移した。** 残る 2 件はどちらもこの回で満たしている。

**この回で確定した判断は 2 つあり、どちらもユーザーが選んだ**（2026-08-16）。1 つ目は依存ゲートで、候補 4 つの直接依存数を実測したうえで **production dependency を増やさない**が選ばれた。2 つ目は crate が組み立てる失敗の理由の扱いで、**符号＋引数へ移してフロントエンドが文を組む**が選ばれた。**両方の根拠は decision-35 が持つ。** アプリ設定への項目追加は decision-13 の改訂で、schema_version は 4 から 5 へ上がった。

## Implementation Notes

## 実測した規模（分割の根拠）

コメントを剥がして数えた画面文は **46 ファイル・941 行**。剥がし方は screen-text.test.ts の手順をそのまま使った。最大は ProjectDetail.svelte 185・TaskDetail.svelte 105・edit.ts 88。crate 側は 4 ファイル・約 28 本（editor.rs 17・history.rs 7・external.rs 3・update.rs 1）で、CommandError の detail に載って画面がそのまま描いている（TaskDetail・GitHistory・Swimlane の 4 か所を確認）。

## 依存ゲート（AC #2）で実測した候補

npm view で直接依存数を数えた: 依存を増やさない 0／typesafe-i18n 5.27.1 が 0（生成段が増える）／svelte-i18n 4.0.1 が 7／@inlang/paraglide-js 2.24.1 が 7。**ユーザーが「増やさない」を選び、根拠は decision-35 が持つ。**

## 反応性の作り

文言表 は素の .ts に置いた。**unit の Vitest 企画は node 環境で Svelte コンパイラを持たない**ので、rune を使うと文をつづる純関数の試験がまとめてコンパイラの後ろへ回る。画面の描き直しは messages-context.ts が context へ入れる取得子が担い、素のモジュールは msg() を読む。**`{#key}` で木ごと作り直す案は採っていない** — 言語を変えた瞬間に詳細パネルの編集途中が消えるためで、doc-8 §6.4 が禁じているのと同じことになる。

## 実エンジンでの実測（WebKit、1280x800、_sandbox/app-check）

5 枝すべて pageerror なし。**言語未選択 ＋ OS ja → ja、OS en → en**（navigator.language は newContext({locale}) に追随する）。**明示選択は両向きとも OS を上書きする。** **収録していない値（de）は一覧に残り「de (not included in this build)」と印が付き、描画は OS の言語になる。** `<html lang>` も追随する。

保存の経路も測った: 下書きを英語にしただけでは切り替わらず（明示保存として正しい）、**保存すると html lang が en になり、開き直した設定画面の見出しが Language になる。**

**未測定**: 「開いたままの画面がその場で描き直る」ことは測れていない。**不可能なのではなく、いま 文言表 を読む画面が設定画面 1 つだけで、それが保存で閉じるため観測できる場所が無い。** TASK-182 が抽出を行うと観測できるようになるので、あちらの最初の実測に置く。

## 検査を壊して確かめたこと

- 英語の 文言表 から鍵を 1 つ落とすと `pnpm run check` が落ちる（decision-35 §4 の 1 段目）。
- 引数の数がずれると messages.test.ts の対応検査が落ちる（**型は捕まえない** — 引数の少ない関数は型を満たす）。
- 言語未選択 の語を 表示テーマ の 未選択 とずらすと、対を保つ検査が落ちる。
- normalize から language を外すと isDirty の検査が落ちる（**外しても型は通る** — 短い配列で型は満たされる）。

## ハーネス

_sandbox/app-check の偽 IPC に language を足し、schema_version を 5 にした。**settings_save は書かれた値を返すように直した** — 返さないと、保存で言語が切り替わることを製品側の不具合と区別して測れない。つまみは `?lang=en|ja|<未収録値>`。
