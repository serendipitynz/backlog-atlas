## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
利用者の要求（2026-09-06）。設定した絞り込みに名前を付けて保存し、後から呼び出せるようにする。v0.3.0 に入れる。

## いまの絞り込みと、その寿命

doc-7 §5.2 の絞り込みはファセットを 8 つ持つ（Type・通常ラベル・priority・assignee・テキスト・不整合・タスク保存区分・更新期間）。`src/lib/filter.ts` の `CardFilter` はそれらに加えて条件を足した順を持ち、その順が §5.2 の「直前の 1 つを戻す」の意味を決めている。

再起動をまたいで残るのは 既定の保存区分 だけである。 decision-13 がアプリ設定へ持つのは `default_storage_filter` で、これは絞り込みが始まる位置であって、利用者が組んだ条件の組ではない。組んだ条件は「既定に戻す」を押すか、アプリを閉じるかで失われる。 doc-7 §5.1 が 実行内保持 を明記しているのも 行折畳み・列折畳み・行非表示 の 3 値についてであって、絞り込みではない。着手する回は、絞り込みが画面の切替をまたいで残るかを先に木で確かめる。

## 決めること（実装より先に確定する）

本タスクは doc-7 §5.2 と decision-13 の両方へ行を足すので、契約を先に決める。

- 保存の単位と置き場。 アプリ設定ファイル（decision-13）へ持つか、別ファイルにするか。アプリ設定へ持つなら AGENTS のとおり `KNOWN_SCHEMA_VERSION` を上げ、`src/lib/settings.ts` の `mergeDraft` と `normalize` の両方へ通す。どちらも `pnpm run check` では落ちないので、抜けても黙って壊れる。
- 保存する値の範囲。 8 つ全部か、一部か。テキストと更新期間は他の 6 つと性質が違う。 更新期間は暦日の端を絶対値で持つので、保存した組を 1 か月後に呼び出すと、保存したときとは違う集合を指す。
- プロジェクトをまたぐか。 通常ラベル・assignee・priority の値集合はプロジェクトごとに違う。またぐなら、台帳に無い値を呼び出し時にどう扱うかが要る。 doc-7 §5.1 の 復元時の正規化 が 3 値について解いたのと同型の問題である。
- 呼び出し口の置き場。 フィルタ帯（トークン列と 2 つのアイコンのみの控え）へ足すか、別の入口にするか。「既定に戻す」が戻す先は「画面を開いたときの状態」と定義されているので、呼び出した組がその定義とどう並ぶかも決まる。
- 語。 保存した条件の組をなんと呼ぶかを m-4 の対応表へ 1 行足してから本文と画面文を書く。画面文は日本語と英語の 2 つを書く。
