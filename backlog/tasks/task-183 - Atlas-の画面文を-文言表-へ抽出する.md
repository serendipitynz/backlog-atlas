## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実施したこと

**取得子側の画面文 16 ファイル・480 行を 文言表 へ移した。** `src/**/*.svelte` に画面文の日本語は 0 行である（数え方は `screen-text.test.ts` の剥がし手順）。残る 22 ファイル・402 行は `msg()` 側の画面文 で、TASK-187 が持つ。

**分割はこの回に決めた。** 起票時の 883 行を数え直して同じ値を得たうえで、ユーザーが 2 分割を選んだ。**境界はファイルの拡張子と一致する** — 取得子は Svelte の context を要るので `.ts` からは読めず、`.svelte` が自ら綴る文はその画面のものだからで、線を引く判断ではない。

## 文言表 の群の切り方

`ja.ts` の頭註は「群は文が属する画面またはモジュールで切り、2 つの画面が使う文はその文が名指しするものの群へ入れて写さない」と定めている。**16 ファイルを当てたところ、`閉じる`・`title（必須）`・`なし` のように「名指しするものが画面ではない」文が残った**ので、名指しするものの種類で 4 群へ割った。

- **`shell`** — どの画面の内側にも属さず画面の外側に出る文（帯・通知・空状態）。**「`App.svelte` の文」ではない。**
- **`action`** — 2 つ以上の画面が同じ操作に使う名と、その操作の**進行中・失敗**を言う短文（`保存中…`・`保存できませんでした: <理由>`）。失敗の**理由**は入らない。
- **`field`** — 2 つ以上の画面が同じ入力欄に使う名と補助文。
- **`state`** — 2 つ以上の画面が読み取り結果の同じ状態に使う短文。失敗の理由は入らない（`failure` が持つ）。

画面ごとの群は `swimlane`・`filter`・`laneCreate`・`taskCard`（`state` へ吸収）・`projectRegister`・`gitHistory`・`taskDetail`・`projectDetail`・`modal`・`editor`・`shortcutHelp`、および既存の `settings` の拡張である。

**`settings.languageUnrecorded` は `settings.unrecorded` へ改めた。** 表示テーマ の未収録名が字面まで同じ文を出しており、この文が名指ししているのは保存されていた値であって項目ではない。

## 判断が要った 3 点

**1. マークアップを含む文は断片へ割った。** `<code>` を 3 つ挟む案内文などは 1 本の文字列にできない — 文言表 がマークアップを渡すことは decision-28 が許さない。**割る位置は文法の切れ目ではなくマークアップの境目**にしてあるので、各言語が同じ 3 つのパスの周りで自分の語順を保てる。該当は `projectRegister.backlogRootHint`・`slugHint` と `shell.noProjects` の 3 つである。

**2. 区切り文字は 文言表 の側が持つ。** `fields.join("・")` を画面が書いていた 2 か所（`taskDetail.postCheckMismatch`・`projectDetail.diverged`）は配列を受け取る形に変え、`・` と `, ` をそれぞれの 文言表 が綴る。画面に残すと英語表示で日本語の中黒が出る。

**3. `mark.ts` の `ManagedFileNoun` を種別の union へ変えた（この回で唯一の `.ts` の変更）。** `fileInconsistencyReasons(health, "文書")` の第 2 引数は日本語の文字列 union で、**画面が語そのものを渡していた** — `.svelte` から日本語を無くすにはここを動かすしかない。語は `MANAGED_FILE_NOUN` が持ち続けるので、**この変更は `mark.ts` の日本語を移したのではなく、画面が語を綴るのをやめさせたものである**（`mark.ts` 自体の抽出は TASK-187）。

## 実測 — 開いたままの画面がその場で描き直るか（AC #2）

**描き直る。** TASK-103 の回に観測できる場所が無かった件は、抽出が進んだことで解けた。

見たのは**タスク詳細パネル**である。スイムレーンだけを見ると「設定モーダルが閉じたついでに引き直された」場合と区別が付かないが、詳細パネルは言語を変えても閉じないので、**同じ要素が残ったまま字だけが変わる**ことまで見られる。`App.component.test.ts` の `表示言語 を変えると、開いたままの画面がその場で英語へ描き直る` が、パネルの DOM ノードが同一であること（`expect(after).toBe(before)`）と、`タスク詳細` → `Task detail`・`編集` → `Edit`・背後のスイムレーンの `1 / 1 件` → `1 / 1 tasks` を押さえる。

**変異で 2 通り確かめた。** ① `provideMessages` が `CATALOGS[language()]` を 1 度だけ束ねる形に戻すと落ちる。② `TaskDetail.svelte` の 1 か所を取得子から `msg()` へ替えると、**主張どおり `[aria-label="Task detail"]` が 0 件**で落ちる。②が要るのは、①は初期化時点の言語で落ちるので「描き直り」を測っていないためである。

**この時点の画面は 2 言語が混ざる。** 純関数が組む文は日本語のままで、混在は分割の帰結であって欠陥ではない。試験はその不在を主張せず、混在が解けたことを固定するのは抽出漏れの走査（TASK-184）の役目である。

## 試験の言語を固定した

**`fake-boundary.ts` の `language` を `"ja"` にした。** ここだけ 言語未選択 を採らない — `null` は OS が決める意味で、`jsdom` ではそれが `navigator.language` になる。コンポーネント試験の主張は日本語で書かれているので、**放置すると走らせた機械の locale で結果が変わる。**

**例外が 1 件ある。** `設定の読取が失敗しても既定値で起動を続ける` は、その `language` を運ぶはずの読み取りが失敗する回なので 言語未選択 になる。ここは帯の文を `msg()` と突き合わせる形にした — 文字列で書くと locale に釘付けになる。

## 英語の語彙を backlog.md と突き合わせた

**オーナーの求めで、上流（`Backlog.md` v1.50.1 の clone）の UI・CLI の語と照合した。** 最初に書いた英語は
上流を見ずに訳したものだったので、**この照合そのものが後追いである** — 語を足す回は上流を先に見る。

**一致していたもの**: `Acceptance Criteria`・`Description`・`References`・`Dependencies`・`Labels`・
`Priority`・`Milestone(s)`・`Decisions`・`Status`・`Type`。画面に出す CLI の綴り（`--notes`・
`--append-notes`・`--no-update-tasks`）と削除時の `clear`/`keep`/`reassign` も上流に実在する識別子だった。

**直したもの、3 種。**

1. **`Implementation Plan`・`Implementation Notes` は Title Case である。** 管理ファイル自身の節見出しが
   `## Implementation Notes`（この repo に 118 件）で、**英語には日本語のような別の画面語が無い** —
   大文字小文字を変えると「ファイルにある節とは別の何か」に読める。**これは判断ではなく誤りだった。**
2. **文書 の英語は `Documentation` である**（オーナーの判断）。上流の nav・見出しがその語で、
   **`Documents` は上流に 1 件も無い。** ただし**個々のファイルは document のまま**なので、件数と
   項目行はその名詞を保つ。
3. **追加の入力欄は上流の語を採る**（オーナーの判断）: `New criterion`・`New label`・`New assignee`・
   `New tag`、および `Create new document`・`Add milestone`。

**寄せる先が無いもの**: 保存区分・正準列・未分類・不整合・登録・継続検出・スイムレーンは Atlas の設計語で、
上流に対応概念が無い（あちらは `Board`）。**これらの英語はこちらで決めるしかないので、上流照合の対象外である。**

**TASK-187 への申し送りが 2 件ある。** どちらも `.ts` 側なので英語を書くのはあちらの回である。
**① 保存区分の値**を Atlas は素の `active`/`draft`/`completed`/`archive` で出しているが、上流の UI は
`Drafts`/`Completed`/`Archived` で、**`active` に当たる語を持たない**（あちらのディレクトリは `tasks/`）。
**② 状態遷移の 3 つ**は上流の CLI help では `move task back to drafts`・`archive a task`・
`cleanup … into completed` で、**完了整理 の英語は `cleanup` 系**になる。
