## 決定先行判定

**doc 改訂のみで decision は書かない** (TASK-66・67・112 に続く 4 例目。決 印は後付け)。押せる控えの中の
図形は doc-11 §2.4 の アイコンのみのボタン にそのまま収まり、`aria-label` 必須・`aria-hidden` の 2 条項が
そのまま効く。改訂したのは 3 か所。

- **doc-7 §2.2**: 列折畳みの控えを図形のみとし、＜ / ＞ が指すのは押した結果であることと、その理由
  (横方向に「開いている／畳んである」を指せる向きが無い) を書いた。
- **doc-7 §2.3**: 行折畳みの控えを図形のみとし、∨ / ∧ が指すのはいまの状態であることを書いた。**軸ごとに
  規則が分かれる**ので 2 か所へ書き分け、互いを参照させた。画面設計案から意図的に外れた点 (AC #3) も
  ここに置いた。§2.3 の図は ▼▲ → ∨∧ に直し、列に ＜ を足し、記号が図形の代用であることを図の下に書いた。
  図のフィルタ帯の行が TASK-112 の後も「検索」のままだったので、同じ図の中の誤りとして併せて直した。
- **doc-11 §2.4・§1・§8**: 「画面設計案 01・02 が折畳みに置いた記号（∧∨）」は事実として誤りで、原文は
  01 が ▼▲、06 が ▾▸ ＋ 可視文言「畳む」だった (doc-12 §2.5・§7.2)。∧∨ は TASK-69 の title の記号を
  写したものだった。TASK-112 の [P2] と同型 (誤りを生んだ規則を残すと後続で再生産される) なので、
  §1 の文字グリフの例からも ∧ を外した — doc-7 の図が ∧ を**図形の代用**として使うため、∧ を
  「アイコンではないもの」の例に残すと衝突する。
- **doc-12 §7.2**: 転記は改訂せず、実装が意図的に外れている事実と理由の在処 (doc-7 §2.3) だけを 1 文
  足した (TASK-112 が §4.3 でとった形と同じ)。

**ユーザーが 2 案から選択 (2026-08-03)**: Description の「行折畳みを ∧（展開は ∨）」は、図形が押した結果を
指す読みと、いまの状態を指す読みで正反対になる。**状態を指す**を選択。文言が消えると、その行がどちらの
状態にあるかを述べるものは図形だけになるため。結果、行の向きは現行の ▼ / ▲ と同じで、画面設計案 06 の
▾ (開いている行に置く) の流儀も保たれた。列は状態で読めないので動作読みとなり、軸ごとに規則が分かれた。

## 実測 (WebKit・Chromium、1280×800、`_sandbox/sticky-check/`)

`pnpm vite` を起こして本物の `Swimlane.svelte` を実エンジンに載せた (ハーネスは TASK-61 のものをそのまま
使えた)。同じ計測を変更前後で走らせた。

| 対象 | 変更前 (WebKit / Chromium) | 変更後 (両エンジン) |
|---|---|---|
| レーンヘッダ行の高さ | 31.59 / 31.98 | **31.59 / 31.98 (不変)** |
| 列ヘッダ行の高さ ＝ `--lane-top` | 71.97 / 75.16 | **71.97 / 75.16 (不変)** |
| 行折畳みの控え | 45.72×18 / 47.44×18.8 | 24.38×19.19 |
| 列折畳みの控え | 33.88×18 / 35.59×18.8 | 24.38×19.19 |
| 図形の箱 | — | 11.19×11.19 (1em × .7rem) |

- **レーンヘッダ行と列ヘッダ行の高さはどちらも変わっていない**ので、TASK-61 の 2 層スティッキーと着地の
  数値に影響しない。行の高さを決めているのはプロジェクト名 (.85rem) の行箱で、控えの 19.19px はその下。
- 文言 2 文字ぶん **21.34px (Chromium)** が行から返り、それはプロジェクト名が真っ先に失う幅である。
- 帯の控えを 1 つの高さに揃える形は `FilterBar.svelte` の `--bar-control` (doc-12 §4.3) と同じ理由で
  入れた。図形の箱は自分の 1em で、文字の行箱とは別の高さになるため、**エンジン差 (18 対 18.8) も
  この 1 値で消えた**。`box-sizing: border-box` も同じ理由で要る (全体リセットが無い)。
- 列ヘッダの控えは `align-self: flex-start`。`center` だと、未対応列の 2 文の折り返しで全列のヘッダが
  72px になるため、図形が列名から 20px 下に浮いた (実測 top 25.89 → 6.39 で列名と同じ高さに揃えた)。
  ベースラインに乗らないのは、図形しか持たない箱がベースラインを持たないため (`App.svelte` の ☰ と同型)。
- 畳んだ列では控えを帯幅 (72px) に伸ばし、図形を中央に置いた。
- `aria-hidden="true"`・可視文言なし・`aria-label`／`title` あり・`aria-expanded` あり を 4 状態で確認。

**4 倍解像度の画像で図形の潰れを見た** (TASK-112 で確立した確認)。atlas-light・atlas-dark の両方で、
11.19px の chevron 4 種が読めることを確かめた。

## 目視 1 回目のあとの修正 (2026-08-03、ユーザー指摘 5 件)

1. **畳んだ列ヘッダを 1 行にした。** 列名・件数・控えを縦に積んでいたのをやめた。列ヘッダ行はどの列も
   最も高い列に揃うので、1 列を畳むだけで全列のヘッダが 3 行になり、グリッド全体が押し下がっていた
   (実測 71.97 → **32.97px**、両エンジンで同値)。
2. **控えをヘッダの左端へ**。列名の長さが変わっても控えの x が動かない (実測 left 8px、畳んだ帯では 4px
   ＝ それぞれの padding)。
3. **列名は 1 行のまま省略記号で切る**。5rem の帯では `In Progress` が `In Pro…` になる (CSS の
   `text-overflow: ellipsis` なので、切る位置は幅が決める。全文は `title`)。
4. **列ヘッダの件数を撤去**。`swimlane.ts` の `columnTotal` はこの表示のためだけにあったので関数ごと落とし、
   TASK-50 の AC #2 のうち合計を見ていた 1 節も落とした (行ごとの内訳を見る節は残る — そちらが下の四角と
   件数の裏付けになる)。
5. **畳んだレーンセルはカード 1 枚を四角 1 つに置き換えて並べ、その下に件数**。四角は 5.59px、色を持たず
   (`--line-strong`)、`aria-hidden`。件数は従来どおり `aria-label` に列名を添える。
6. **全列を同時に畳めないようにした**。展開中が 1 列になったらその控えを `aria-disabled` + `aria-describedby`
   にし、理由を列ヘッダ行の下に 1 行で常時出す (doc-11 §5 の 2 形式のうち、`title` だけに置かない方)。
   規則は `swimlane.ts` の `columnFoldable` として持ち、単体試験を足した。**押しても畳まれないことを
   playwright の force click で確認**した (playwright 自身も `aria-disabled` を「enabled でない」と見て
   通常の click を拒否した)。

### 追加の doc 改訂

- **doc-7 §2.2**: 上の 1・2・3・4・5・6 をすべて規範として書いた (件数の置き場、1 行の保持、控えの位置、
  四角と件数、全列折畳みの禁止)。畳んだ列の見え方の図も足した。
- **doc-11 §3**: 「畳んだ列のレーンセルに並ぶ四角はチップの 4 系統に入らない」を、絞り込みトークンと
  同じ形で足した。**色を与えないことがこの区別の担保**である (族の色を借りると縮退・読取不能の札と
  同じ見た目になる)。
- **doc-12 §7.2 列ヘッダ**: 転記は変えず、実装が帯の幅とヘッダ・セルの中身で意図的に外れている事実と
  理由の在処 (doc-7 §2.2) を 1 文足した。

### 残っている 3 行（未対応列があるとき）

**未対応列が出ている間は、列ヘッダ行が 71.97 / 75.16px のまま**である。原因は折畳みではなく、未対応列の
ヘッダが持つ 2 文 (「正準列ではないため列折畳みなし」「候補集合を定義できないため新規入力なし」) で、
doc-7 §2.2・§4.1 が「置かない操作の理由をその場所に書く」と定めているものである。1 行に収めるには
その 2 文を今回足した全列幅の 1 行へ移すことになり、doc-7 の 2 つの条項の改訂になるので、この PR では
触っていない。

## 未対応列も折畳みの対象にした (2026-08-03、ユーザー指摘)

除外の根拠は doc-7 §2.2 の「正準ステータス列ではないため」だけで、**畳めるかどうかとは関係が無かった** —
カードを持つ列であり、畳んだときの見え方も正準列と同じである。契約を次のように書き換えた。

- **doc-7 §1**: 列折畳み の定義を「1 つの正準ステータス列を…」から「1 つの列を…対象は正準ステータス列 4 つと、
  出ている間の未対応区画」へ広げた。既存の定義語の指示対象の拡張なので、対応表を第 3 版へ上げてから書いた。
- **doc-7 §2.2**: 除外の一文を落とし、**未対応列は「展開中の最後の 1 列」に数えない**ことを書いた。未対応
  status のタスクが 1 件も無くなった時点で未対応列は自分から消えるので、それを最後の 1 列と認めると、
  4 列すべてが帯のまま戻せない画面になりうる。未対応列そのものは、畳んでも正準列を 1 つも奪わないので
  常に畳める (`columnFoldable` の実装はこの 1 点だけを特別扱いしている)。
- **doc-7 §4.1**: 未対応列に新規タスク入力を置かない理由を、**画面に出さないことにした** (ユーザーが 2 案から
  選択)。理由は 3 つ — 押せない控えを置いていないので doc-11 §5 が理由を要求する対象 (無効化) ではない、
  正準 4 列に入口があって未対応列だけに無いという並びが画面に出ている、常設の 1 文は列ヘッダ行の 1 行保持で
  得た高さをそのまま食う。**候補 0 件の列の理由文は残す** — そちらは同じ列がプロジェクトによって入口を
  持つので、無いことが並びから読み取れない。

### 実装

- `swimlane.ts` に `GridColumn = StatusColumn | "unmapped"` を置き、`collapsedColumns` と `columnFoldable`
  をそれで受けるようにした。`UNMAPPED_FOLD_ABSENT_REASON` と `UNMAPPED_ABSENT_REASON` (lane-create.ts) は
  画面から消えたので、関数・定数・試験ごと落とした。
- 列ヘッダは正準列と未対応列で **1 つの snippet** を共有する。控えの 4 つの aria 属性を 2 か所に書くと
  片方だけが後から変わりうる。読み上げ名だけを引数で分けた (「To Do 列の」対「未対応区画の」)。

## 目視の結果 (2026-08-03)

**問題なし。** 未実測として挙げた 2 点のうち、**11.19px の図形は押す対象として十分な大きさ**であることが
実機で確認された (控えの箱は 24.38×19.19px)。**後続で押せる図形を置くときも同じ寸法から始めてよい** —
1em × その控えの font-size (.7rem)、箱は 24×19px 程度。TASK-112 の funnel (11.52px・押せない目印) と
合わせて、押せる／押せないのどちらでも 11px 台の図形が読めることが確認できたことになる。
