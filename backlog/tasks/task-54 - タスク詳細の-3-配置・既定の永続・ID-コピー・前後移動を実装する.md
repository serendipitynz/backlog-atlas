## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-8 §2 は、これまで併置サイドバー固定だったタスク詳細画面に、中央モーダルと全面シングルビューを加え、選んだ配置をアプリ設定へ永続すると定めた。読む内容が同じでも必要な広さは作業によって違う（カードを選び替えながら読む／本文を編集する／Git 履歴を全件たどる）ためである。配置ごとに常設・折畳み・粒度が変わる割当は doc-8 §3 の表に従う。縮退表示だけは 3 配置とも常設する（折畳みへ落とすと問題のあるタスクが正常に見える）。

配置の切替と前後移動も、閉じる・別タスクを開くのと同じ破棄前確認（doc-8 §6.3）を通す。Atlas には URL が無いため、横断タスクID のコピーがタスクを他所で指し示す唯一の手段になる。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装（この版）

- **詳細配置の保持はシェル（App.svelte）**。配置とはパネルをどこへ置くかであり（グリッドの脇／上／代わり）、置けるのはシェルだけである。`placement` はアプリ設定の既定から起動時に採り、切替のたびに `settings_save` で書き戻す（doc-8 §2.2）。
- **doc-8 §3 の割当表を `src/lib/placement.ts` にデータとして持つ**。区画ごとの `{#if placement === …}` にすると配置が部分適用されうるため、1 配置＝全区画の割当という形にした。試験は doc-8 から書き起こした 2 つめの表と突き合わせる。
- **常設／折畳みは同じ `<details>`**（`DetailSection.svelte`）。doc-8 §3 は両者を「既定で開いた／閉じた」と定義しており、利用者が開閉できること自体は禁じていない。縮退表示だけは折り畳めない素の区画にした（前のタスクで閉じた状態が引き継がれると、問題のあるタスクが正常に見えるため）。
- **破棄前確認は 5 経路で 1 本の帯**（doc-8 §6.3 の「文言は 5 経路で同じ」・doc-7 §5.3 の上部帯 ①）。シェルが継続（closure）を預かる形にし、キャンセルだけはパネル側が `onconfirmDiscard` で同じ帯を借りる。中央モーダルの層はグリッド領域だけを覆うので、帯は常に読めて答えられる。
- **前後移動は選択変更そのもの**として `onselect` へ流し、別タスクを開くのと同じ関門を通す。隣接は `laneNeighbours`（`swimlane.ts`）が描画済みの行から求めるため、絞り込み・行非表示・並びは画面と一致する。未対応区画はレーンセルではないが、カードが並ぶ 1 かたまりなので位置表示を分けて扱う。
- **1280×800 の 2 列**は寸法定数（`placement.ts`）を CSS カスタムプロパティで流し込み、同じ数値を試験が確かめる形にした。縦積みへ落とす分岐は持たない。

## 設計文書へ反映した判断

- doc-8 §3: 表に (主列)/(脇列) の無い区画の列を明記（見出し・編集・縮退は 2 列にまたがる／実装ノート・Git 履歴欄は主列／状態遷移・外部エディタは脇列）。
- doc-8 §5: 併置サイドバーの「関連 PR m 件」は、関連解決の参照手段が未実装の間（doc-6 §6）件数ではなく関連解決の状態を 1 行で出す。件数だと常に 0 件になり「関連が無い」と読めるため。
