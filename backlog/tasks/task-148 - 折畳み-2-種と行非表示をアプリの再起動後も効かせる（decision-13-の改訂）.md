## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-11 のユーザーの要求である。**列折畳み・行折畳み・行非表示 を、アプリを終了して起動し直した後も効いたままにする。再起動をまたぐ保持 とは、アプリの終了と起動をまたいで値が効いたままであることを指す。**

**decision-13 の改訂を要する（決定先行）。** 同 ADR の「アプリ設定を持たない値」がこの 3 値を名指しで除外しており、doc-7 §5.1・§5.4 の 2 か所がそれを引いている。

**除外の根拠 1 文は、そのままでは 3 値のうち 1 値にしか掛かっていない。** decision-13 が書いているのは「次回起動時に前回どけたものが消えたままだと、**行非表示の「件数も読めない」性質と相まって**、登録したはずのプロジェクトが失われたように読める」であり、**根拠が名指ししている性質を持つのは 行非表示 だけである** — 行折畳み はレーンヘッダ行と列別件数を残し（doc-7 §2.3）、列折畳み は列名と行ごとの件数を残す（doc-7 §2.2）。doc-7 §5.4 が並び順を保存する根拠に使った判定（次回起動時に効いていても「登録したはずのものが消えた」とは読めないか）を同じく当てると、折畳み 2 種はその判定を通る。

**行非表示 についても、根拠が前提にしていた状態は 2026-08-09 に変わった。** TASK-131 が表示・非表示をメニューのプロジェクト一覧へ一元化し、**一覧は登録済みプロジェクトを常に全件並べ、非表示の行も印の無い行として並ぶ**（doc-7 §2.1）。decision-13 が書かれた時点では、一覧は非表示の行だけを並べていた。起動直後に「登録したはずのプロジェクトが失われた」と読める経路が今も残っているかは、**着手時に確かめる** — 残っているなら 3 値のうち 行非表示 だけを除外に留める道がある。

**着手時に確かめること**: 保存する値の形（列折畳み は正準ステータス列 4 つ＋未分類区画、行折畳み・行非表示 は slug の集合で、台帳から消えた slug が保存値に残ったときの扱いが要る）、`KNOWN_SCHEMA_VERSION` の引き上げ（decision-13 の Consequences。現在 3）、`src/lib/settings.ts` の `mergeDraft` と `normalize` の両方へ通すこと、設定モーダルの「ここに無い項目」区画（`Settings.svelte:16`）が 3 値を挙げている記述。
