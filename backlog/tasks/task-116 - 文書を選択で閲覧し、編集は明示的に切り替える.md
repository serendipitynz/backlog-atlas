## Implementation Notes

## 契約の改訂（着手時の判定で必要と分かった。決 印は後付け、14 件目）

- **doc-10 §5**: 「カードを押すことが選択で、選択が更新フォームを開く」を
  **「選択は閲覧を開き、編集セッションを開かない」** へ改訂。**閲覧**・**閲覧ヘッダ**・
  **編集への切替**を定義した。右の列は **編集ペイン → 文書ペイン** へ改称（3 状態のうち
  編集は 1 つになり、§6 が置いた「列の名はその列が開くもので決める」規則の下で
  編集ペインと呼べなくなったため）。
- **decision-24 を原地改訂**: 理由行の置き場を「編集ペイン／操作ペインの見出し下」という
  場所の名指しから、**「選択が開く場所の見出し下」という規則**へ改めた。文書側の実例は
  閲覧ヘッダ、マイルストーン側の実例は操作ペインで、規則は 1 つ。場所を引き写す形の
  規則は、選択が開くものが変わった時点で doc-11 §2.4 の保証を切る（今回それが起きた）。
- **doc-11 §2.4 を原地改訂**: 「文書・マイルストーンでは編集ペイン／操作ペインの理由行」を
  実例 2 つと規則の形へ直した。
- **選択の解除は置かない**（2026-08-07 にユーザーが確定）。§6 との意図的な非対称で、
  TASK-117 が作成フォームをペインから出すまでの過渡期にしか要らない導線だから。
  **帰結として、TASK-117 が入るまでは一度カードを選ぶとその画面のまま作成フォームへ戻れない。**
  承知のうえで置かないと決めたので欠落ではない、と doc-10 §5 に書いた。

## 実装（`ProjectDetail.svelte`）

- **選択を `docSelection`（文書 id）として `docSession` と別に持つ。** 選択中の強調は
  `docSelection`、編集中チップと未保存チップは `docSession` から出る。
- `selectedDocument` は**現在の読み取り**から導く derived。理由行・表示パスの両方が
  これ 1 つを引くので、同じ 1 件についてカードの ⚠️ と別の読み取りが描くことはない
  （decision-22「導出は 1 回」。PR #71 の 1R [P2] と同じ形を避けた）。
- **選択が解決しなくなったら落とす `$effect`** を置いた（TASK-64 の 1R [P2] が
  「同型の列を足す区画は最初から織り込む」と定めたもの）。**編集セッションが開いている間は
  除外する** — baseline は未保存入力を作った読み取りで、意図的に再読込を生き延びる
  （doc-8 §6.4 と同じ規則）ので、編集フォームとその入力は画面に出たままである。
  閉じた時点でここへ落ちて選択が消える。
- **理由行は閲覧ヘッダのみ**。更新フォームには繰り返さない。
- **表示パスは 2 か所**（閲覧ヘッダと path 欄の直上）で、導出は `selectedDocPath` 1 つ。
  path 欄は移動要求で現在値を持たないため、「空欄なら変更しません」は現在の所在と
  並べて初めて読める。
- **本文は読み取った文字列そのまま**（`white-space: pre-wrap`）。Markdown を整形する手段が
  この版に無く、整形した見た目は画面が守れない主張になる。**行長上限 48rem を掛けた** —
  `placement.ts` の `PROSE_MAX_WIDTH_REM` を借り、2 つ目の 48 を置かない。
- カード保持の文言を「完了するまで文書の編集は開けません」→「別の文書は開けません」へ
  直した（押して開くのが編集でなくなったため）。`編集` ボタンにも `issuing` の保持を掛けた。
- SCSS の `.body` は既にこのコンポーネントの外枠が着ている名前なので、閲覧の本文は
  `.doc-body` にした。

**実エンジン実測**（借り物 playwright / Chromium、`_sandbox/project-detail-check/` の
`?docs=6&unmapped=1`。1280×800 相当の箱）:

- カードを選ぶと閲覧が開く（`pre.doc-body` が 1 件、`編集を閉じる` は 0 件）。
  閲覧ヘッダは title と `編集` が同じ 1 行（どちらも y=61）、その下に id・type・tags（y=90）・
  表示パス（y=108）・理由行（y=131）・本文（y=155）。
- 閲覧では編集中チップ 0・選択中カード 1。`編集` を押すと編集中チップ 1。
- 更新フォームに理由行は出ない。path 欄の直上に「現在の所在: backlog/docs/doc-1 - screen.md」。
- `編集を閉じる` で閲覧へ戻り、作成フォームは出ない。
- 破棄前確認は 2 経路のまま。閲覧のまま別カードを選んでも確認は立たず、編集に入力を入れて
  から別カードを選ぶと「文書の編集に未保存入力があります。doc-3 を開くと破棄されます。」が立つ。
  「入力に戻る」で編集が残り、「破棄して続行」で進む。
- 横スクロールは一覧列・文書ペイン・本文のいずれにも出ない
  （scrollWidth = clientWidth: 274/274・800/800・758/758）。
- 行長上限: 箱 1280px では本文 content box 47.50rem で上限は当たらない。箱 1900px では
  content box が 768px = **48.00rem ちょうど**で止まる（`max-width` は content box に効く。
  TASK-115 の規約どおり）。
