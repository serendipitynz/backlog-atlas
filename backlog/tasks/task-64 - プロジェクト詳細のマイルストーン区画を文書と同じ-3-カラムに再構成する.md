## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
doc-10 §6 をマイルストーン一覧（16rem の一覧列）と操作ペインの 3 カラムへ改訂し、実装した。§5 が TASK-63 で確定させた形をそのまま引く。

## 契約として書いたもの（doc-10）

- **§1 に一覧列を新設**。選ぶ対象のカードを縦に並べ選択を保持する幅 16rem の列で、文書一覧（§5）とマイルストーン一覧（§6）がその 2 実例。2 区画が同じ列を持つことを doc が言っている以上、幅の定数も 1 つにした（`DOC_LIST_WIDTH_REM` → `LIST_COLUMN_WIDTH_REM`、custom property は `--doc-list-width` → `--list-column-width`）。16 を持つ定数を 2 つ置くと、doc が同じ列と呼んでいる間に値が離れうる。
- **§6 の逸脱は 2 件**（本画面では §5 の 2 件と合わせて 4 件目まで）。①3 カラム化そのもの — 07 は一覧とフォームを縦に積む。②説明を一覧に出さず操作ペインに出す — 一覧列は 16rem で説明が読める幅ではない（§5 が表示パスに下したのと同じ判断）。
- **右の列は編集ペインではなく操作ペイン**。位置も切替規則も §5 と同じだが、選択が開くのは doc-8 §1 の編集セッションではなく改称・削除・アーカイブなので、別の名を与えた。同じ理由でカードは「編集中」チップを持たない（選択中は強調だけが述べる）。未保存チップは持つ。
- **破棄前確認は §6 自身の契約**。別のマイルストーンを選ぶ／選択を解除する の 2 経路。doc-8 §6.3 の文言契約は借りない（§5 と同じ理由）。守る対象は改称の新名称と削除の参照タスクの扱い（付け替え先は扱いが `reassign` のときしか出せないので、扱いの検査に含まれる）。
- **作成後の説明編集を提供しない理由を、提供しない操作区画に加えて操作ペインの説明の隣にも書く**。3 カラムでは提供しない操作区画が非選択時にしか画面に出ず、説明を読んでいる利用者がそこへ辿り着けなくなるため。

## 実装

`milestoneOp` を「どのマイルストーンの・どの操作か」の対から「選択中のマイルストーン」（`milestoneSelection`）と「開いている操作」（`milestoneOp`）へ分けた。選択は id で持ち、ペインが読むのは `selectedMilestone`（現在の読み取りから引く derived）— 外部変更で消えたマイルストーンに操作を向けたままにしないため。削除・アーカイブの成功後は再読込後の一覧に id が残っているかで選択を落とす（改称は id を変えないので選択は立ったまま。doc-9 §4.2.1）。

SCSS は 2 区画で同一の構造になったのでクラスを 1 語彙へ揃えた（`doc-grid`/`doc-list`/`doc-cards`/`doc-card`/`doc-pane` → `split-section`/`list-column`/`cards`/`card`/`pane`）。`.panel.split` はマイルストーン区画でも効かせる。使われなくなった `.records` を削除。

## 実測（借り物 playwright / WebKit・Chromium、1280×800 と 1280×420）

ハーネスは `_sandbox/project-detail-check/` に `?milestones=<n>` を追加。件数のつまみは「無指定なら fixture のまま、指定したらその数ちょうど」へ直した（0 を「複製しない」の合図にすると空一覧を出せない。`?docs` も同じ扱いへ揃えた）。

- **3 カラムの実幅（20 件・1280px 幅）**: 区画ナビ 205.78px（12rem=192 + padding 12.8 + 枠 1）／マイルストーン一覧 274.59px（16rem=256 + padding 17.6 + 枠 1）／操作ペイン 799.63px。合計 1280.00。**同じ数が文書区画でも出る**ので、TASK-63 の記録を再現できている（TASK-115 の確認手順）。
- **独立スクロール**: 一覧を 400 までスクロールしてから 2 回続けてカードを選んでも一覧は 400 のまま。選択は m-2 → m-3 と動く。playwright の `click()` は要素を可視域へ寄せるので、この検査だけは `element.click()` をページ内で呼んで測った。
- **ペインだけ先頭へ戻る**: 420px 高の箱で削除フォームを reassign まで開くとペインが溢れる（WebKit 496/369、Chromium 511/368）。末尾までスクロールしてから別カードを選ぶと、ペインは 127→0（WebKit）・143→0（Chromium）、一覧は動かない。
- **破棄前確認**: 改称に入力してから別カードを押すと、文は「マイルストーンの操作に未保存入力があります。m-3 を開くと破棄されます。」、位置は 2 列の外（`.columns` の外・y=51.38）、選択は動かないまま。「入力に戻る」で入力が残り、「破棄して続行」で選択が移り操作は閉じ、ペインは先頭。
- **カード**: 通常 48.19px、長い名称の行は 84.19px（3 行に折り返す）。未保存チップは `atlas-light`・`atlas-dark` の両方で出る（4 倍解像度で潰れなし）。
- **非選択時のペイン**: 作成フォーム 1・提供しない操作区画 1・強調されたカード 0。**0 件のとき**は一覧に「マイルストーンはありません。」、ペインは作成フォーム。
- **文書区画の回帰**: クラス改名後も一覧 274.59／ペイン 799.63 で変わらず、カード 12 件。
