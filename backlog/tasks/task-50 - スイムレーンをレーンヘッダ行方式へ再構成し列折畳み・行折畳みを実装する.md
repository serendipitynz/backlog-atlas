## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
doc-7 §2 は、左端の固定プロジェクトカラムをレーンヘッダ行へ置き換え、列折畳み・行折畳みを加えた。現行 `Swimlane.svelte` は `grid-template-columns: minmax(11rem, 14rem) repeat(4, …)` で左端に固定幅の行見出しカラムを持つ。この方式は「名前が読める幅を取ると 4 列に配れる横幅がその分減る」という両立しない要求を抱える。レーンヘッダ行が横幅を丸ごと使えば、名前・slug・件数・行単位の操作を折り返しなしに収められる。

畳む（件数は読める）と隠す（件数も読めない）は別の操作・別の語として扱う。同じ語で呼ぶと「畳んだつもりで件数まで失った」「隠したつもりが件数だけ見えている」という取り違えが起きる。既存の「隠す」（行非表示）は語も挙動も変えない。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装

- `Swimlane.svelte`: 左端の固定プロジェクトカラムを廃止し、グリッドの列を正準 4 列（＋未対応列）だけにした。行の識別（プロジェクト名・slug・表示件数／全件数）と行単位の操作は、全幅のレーンヘッダ行 `.lane-head`（`grid-column: 1 / -1`）へ移した。ヘッダ行は `flex-wrap: nowrap` で 1 行に固定し、幅が足りないときに縮むのはプロジェクト名（`title` に全文）と行折畳み時の件数列だけにした（AC #1）。
- 列折畳みは列見出しの「畳む／展開」1 箇所だけが持つ。幅はグリッド全体の `--columns`（`columnTemplate`）を 1 度書き換える形なので、「行ごとに畳む」は構造として存在しない。畳んだ列は 5rem の帯になり、列名・全行合計（`columnTotal`）・各行の件数（`LaneCell` の `collapsed`）を残す。0 件の行も `0` を出す（AC #2）。
- 行折畳みはレーンヘッダ行の「▼畳む／▲展開」。畳むとレーンセル群を描かず、`laneCounts()` の列別件数をレーンヘッダ行に並べる。未対応の件数は、未対応列が出ている間だけ並べる（AC #3）。
- 語と操作の分離: 行折畳み＝「畳む／展開」（レーンセルを畳み件数を残す）、行非表示＝「隠す」（件数も読めなくなる）。説明文も件数が読めるか否かで書き分けた（AC #4）。
- 読取不能行には行折畳みを置かず、`ROW_FOLD_ABSENT_REASON` を行に常時表示する（ホバー依存にしない）。↑↓・隠す・再読み込みは従来どおり残る（AC #5）。
- 未対応列は該当がある間だけ現れ、列折畳みの操作を置かない。置かない理由を見出しに短く出す（`UNMAPPED_FOLD_ABSENT_REASON`）。doc-7 §4.1 が列内新規タスク入力に与えたのと同じ「置かない＋理由」の扱いで、doc-11 §5 の無効化ではない（AC #6）。
- 列折畳み・行折畳みの状態は `Swimlane.svelte` の `$state` に閉じ、アプリ設定にも台帳にも出さない（doc-7 §5.1・decision-13）。行非表示と違い上部帯が読む必要がないため、シェルへ上げていない。
- 併せて `.slug`・`.count` の `opacity` を `--muted` に置き換えた（doc-11 §2.1 の 副次。TASK-48 が Git 履歴欄で行ったのと同じ理由）。

## レビュー（PR #26）で直したもの

- 畳んだ列の 0 件セルが空セルの `—` へ落ちていた。畳んだ列ではセルの内容が件数そのもので、ダッシュと数字が混ざる帯は列として読み下せないため、`0` を出す。開いた列の空セルは従来どおり `—`（doc-11 §6）。
- 畳んだ行が再読込・再試行で読取不能へ変わると、`foldedRows` に slug が残るため 4 列 0 件が描かれ、展開操作も消えていた（読取不能行には折畳みを置かないため）。`folded` を `rowFoldable(row)` でも制限し、読取不能行が畳まれた姿で描かれないようにした。折畳み状態自体は保持するので、読み直しに成功すれば利用者が畳んだままの姿に戻る。

## AC #5 の範囲

プロジェクト詳細画面（doc-10）はまだ存在せず、レーンヘッダ行からその画面を開く入口は TASK-55 AC #1 が自分の範囲として明記している。よって本タスクの AC #5 は「読取不能行を折畳みの対象にせず、行非表示と既存の行単位の入口を保つ」までとし、入口の追加は TASK-55 で行う（同タスクにコメントで記録）。doc-7 §2.3 の要件そのものは変えていない。
