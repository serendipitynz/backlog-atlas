## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-09 のユーザーフィードバック。現在は 3 か所が同じ 1 つの状態 (どのプロジェクトの行を出しているか) を扱っている — レーンヘッダの「隠す」ボタン、上部帯 ⑥ 非表示の行、メニューの「◯◯ を戻す」の一覧。ユーザーはこれをメニュー 1 か所へ寄せることを求めた。

求められている形 (原文):

```
+-------------------------+
|プロジェクトを登録    ⌘N|
|設定                  ⌘,|
|キーボード操作一覧       |
|-------------------------|
|すべてのプロジェクト表示 |
|☑Backlog Atlas          |
|□mallow                 |
|☑geomyth                |
+-------------------------+
```

表示中にチェック、非表示にチェックなし。macOS のメニューで一般的な形 (`proj2.png` が Chrome の View メニュー)。

**決定先行**: 触る契約が 3 つある。(a) doc-7 §5.1 の 行非表示 は帯から戻す操作として定義されている。(b) doc-11 §4 の上部帯は 6 種の閉じた集合で、⑥ を落とすと 5 種になる (`band.ts` の `BandKind` は網羅性で守られている)。(c) 画面設計案 06 は行ヘッダの「畳む」と「隠す」を別の語・別の操作として持っており (doc-12 §7.2)、「隠す」の撤去は原文からの意図的な逸脱になる。撤去して残るのは「畳む」だけである。

メニューの一覧は現在「非表示の行だけを 1 行ずつ」並べているので、全プロジェクトを常に並べる形へ変わる。`headerMenu()` の `showRow` 群がその置き場である。

## 実装

- `header.ts`: `headerMenu()` の入力を「非表示の slug 列」から `MenuProject[]`（slug・name・shown）へ替えた。`showRow` → `toggleProject`（`shown` を持つ）、`SHOW_ALL_ROWS_LABEL` → `SHOW_ALL_PROJECTS_LABEL`（「すべてのプロジェクトを表示」）、`showAllRowsHeld` → `showAllProjectsHeld`（理由文は「（すべて表示中）」）。行の語は `projectMenuLabel` が `name || slug` で決める — 空文字も slug へ落とすのは、語の無い行が行を名指さないためで、レーンヘッダ行が同じ値を同じ規則で読んでいる。
- `band.ts`: `BandKind` から `hiddenRows` を、`BandInputs` から `hiddenRowCount` を、`hiddenRowsBand()` を撤去。`topBands` の `Record<BandKind, …>` が網羅性を持つので、種を落とすと文も一緒に落ちる。
- `HeaderMenu.svelte`: 表示切替行に `aria-pressed` と lucide `check`（`.mark` は印の有無によらず 1em を確保）。印は doc-11 §2.4 の 可視の文言を持つ控えの中のアイコン なので `aria-label` を持たない。
- `Swimlane.svelte`: 「隠す」ボタンと `onhide` prop、`HIDE_HINT` を撤去。
- `App.svelte`: `menuProjects`（台帳順・load から名前）を新設、`hide`/`show` を `toggleProject` へ、帯 ⑥ の markup と CSS を撤去。
- `lucide.ts`: `check` を追加（lucide-react v1.17.0 `check.mjs` の `__iconNode` を写した `M20 6 9 17l-5-5`。ローカルの同版パッケージと突き合わせて確認）。
- doc 改訂は doc-7 §1・§2.1・§2.3・§5.1・§5.3・§6、doc-11 §4・§7・§10、doc-12 §4.2・§7.2・§9。**decision は書いていない。**

## 実測（借り物 playwright・WebKit / Chromium・`_sandbox/app-check` port 5186）

ハーネスに `PROJECT_NAMES` と `?longname=1` を足した（`fixtures.CONFIG` は 1 つの名前しか持たないので、3 行が同じ語になり幅も並びも測れない）。窓は 1280×860、狭い窓の条件だけ 420×860。

| 変更前・非表示 1 件 | 153.92 / 161.72 | 162.19 / 162.19 | 0 |
| 変更後・3 プロジェクト | 170.42 / 180.70 | 235.38 / 235.50 | 0 |

- **幅を決めている行が替わった。** 行ごとの固有幅を測ると、いちばん広いのは「すべてのプロジェクトを表示」で 157.23 / 167.52。次が「プロジェクトを登録」＋和音の 140.73 / 148.53（変更前はこれが幅を決めていた）。**プロジェクト名は幅の原因ではない** —「Backlog Atlas」は 111.38 で 4 番目である。パネルが 16.5 / 19.0px 広がったのは、一覧が伸びたからではなく、すべての行の語が 3 字長くなったためである。
- **上限に当たった側も測った。** 60 字の名前で両エンジンとも 397.19px（doc-7 §2.1 の 24rem。TASK-130 の実測値と同値）で止まり、ラベルは 2 行に折り返し（labelH 18 → 36）、パネル内の横あふれ・文書の横あふれとも 0px。窓 420px では 391.17 / 391.19（90vw 側）で止まり、パネル右辺と窓の間は 12px、文書の横あふれ 0px。
- **区切り線は 1 本で、位置は変わらない。** 1280px 窓では y=133.59（変更前後とも「すべて」の行の上）、420px 窓ではヘッダが 2 行になるぶん y=144.09。
- **印の幅と語の左端。** `.mark` は 12px（1em）、チェックの `<svg>` も 12px。3 行とも labelX が同値（WebKit 1132.36 / Chromium 1122.08）で、印の無い行でも語が動かない。被せ層の 3 行の labelX はその 21.6px 左（印 12 ＋ gap 9.6）。
- **帯とレーンヘッダ。** 通常状態で `.band` は 0 本（変更前は非表示 1 件で `hiddenRows` が 1 本立っていた）。レーンヘッダの控えは `↑ ↓ ›` の 3 つで、「隠す」は無い。
- **「すべてのプロジェクトを表示」は全表示中に `aria-disabled=true`** で、理由文「（すべて表示中）」が行の下に出る。
