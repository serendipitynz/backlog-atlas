被せ層（§1・§7）と一覧見出し行と一覧編集。**列や「本文系・参照系」で括り直さなかった** — 括ると
doc-8 §3.1 の並びの 2 つ目の写しがコンポーネント境界として生まれる。

行数（markup と SCSS を含む、AC #1）は `TaskDetail.svelte` が 2,956 から **1,080** へ、

## 分けなかったもの

**状態は親のまま動かしていない。** 区画切替でも折畳みでも未保存入力が残るのは、それが 1 か所に
あるからで（m-1 TASK-55）、子が `$state` を持てばその瞬間に壊れる。プロジェクト詳細の `dirty` は
5 区画ぶんをこの 1 か所で足しており、そこも動かしていない。子が受け取るのは値と、書き戻しの口
（`edit`・`setSession`・`set…`）だけである。**`$bindable` は使っていない** — この木に 0 件で、
「入力の受け渡しに限る」を prop の形として読めるのがコールバックの側の値である。

**親の script は出していない。** AC #1 が課すのは 1 ファイル 2,000 行未満で、マークアップと SCSS を
出せば満たす。TASK-92 の形で controller へ出すことはできるが、`src/lib` 直下の 91 ファイルが
TASK-197 の起票理由であり、あのタスクは本タスクを依存に持つ。**「script が長いままなので分割が
不十分」ではない** — 長いままである理由は AC #2 である。

## SCSS をどう分けたか

Svelte のスコープはコンポーネント境界を越えないので、マークアップが子へ移ると親に残した規則は
その要素へ届かない。複数の区画が要る規則は宣言だけを持つ mixin として画面ごとの `_shared.scss` に
置き、呼び出し側が選択子を書く。**全部入りの 1 mixin を全区画へ配らなかった** — Svelte が使われない
選択子に「Unused CSS selector」を出すので、そうすると配置の検算が丸ごと失われる。1 つの区画しか
使わない規則はその区画へ置いてあり、いま `_shared.scss` に単独利用の mixin は 0 件である。

**警告 0 は配置の検算であって挙動不変の証明ではない。** 親に置き忘れた規則は親で未使用になり、
子へ写しすぎた規則は子で未使用になる — どちらも警告に出る。**出ないのは「同じ規則を親と子の両方が
要る」場合**で、本タスクは実際にそこで 2 件落とした（下記）。

## 走査を 2 本広げた

- **`text-scale.test.ts`** は `.svelte` の素の文面だけを読んでいたので、mixin へ移した `font-size` が
  走査の外へ出ていた。`?raw` では partial を読めない（`app.scss` と同じく vite の CSS 経路を通り、
  キーは在るのに 0 バイト。実測）ので、**各コンポーネントの `<style>` を sass に通した結果** を走査対象へ
  継いだ。`@use` の先も mixin の展開も出るので、これは前より広い走査である。mixin に `0.5rem` を
  植えると 6 ファイルで落ちることを確認した。
- **`hidden-reason.test.ts`** の glob が 1 階層だけだったので `**` にした。区画コンポーネントが
  それぞれ自分の `unseen` を持つため、広げないとこの検査が届かない。

## 実測（AC #3、変更前と変更後）

借り物 playwright（WebKit）に本物のコンポーネントを載せ、**タスク詳細 16 状態・プロジェクト詳細
18 状態** について、DOM の形・属性・文字列・矩形・**算出スタイル全プロパティ** を分割前後で突き合わせた。
差は **意図した 2 件だけ** である。

- `aside.detail` と `.panel` に `issue-row` class が付いた。分割前は `:has(> .issue)` /
  `:has(> section > .issue)` で発行の行の有無を読んでいたが、その要素は子のスコープクラスを持つので
  構造の選択子では届かない。**算出 `padding-bottom` は前後で同じ** である。
- それ以外の全プロパティ・全矩形が一致した。

**画像も撮った。** 同じ 14 状態のフルページ画像が **分割前後でバイト同一** である（変更前は
`git stash` して撮影）。数と画像は別のものを見ているので両方を見た。

**AC #2 は実測した。** プロジェクト詳細で 概要 → 新規タスク → 文書 → 概要 → 新規タスク と 4 回
区画を切り替えても、打った値が両方残る。タスク詳細では編集セッション中に折畳み区画を閉じて開いても、
題と未追加の下書きが残る。**この走査が空でないことも確かめた** — 子に `$state` を持たせる変異を
入れると、切替後の値が空になる。

## 実測で見つけた 2 件（どちらも「親と子の両方が要る規則」）

- **`.line` と `.title-line` の並びが効いていた。** 限定度が同じ（どちらも 0,1,0）なので後ろが勝ち、
  `.line` の `align-items: baseline` と `gap: 0.35rem` が `.title-line` の 2 宣言を上書きしている。
  並べ直した最初の版では title の行が 26.5px → 24.5px に縮み、その 2px が見出しからパネルの高さまで
  伝わった。**分割前と同じ並びに戻し、効いていることを註に書いた。**
- **発行の行の理由文が濃くなった。** 分割前は `.issue .hint` の隣に `.hint` の地が居て、opacity 0.65 は
  そこから来ていた。`.issue .hint` は margin と揃えだけを持つので、`.hint` を落とすと理由の行が本文と
  同じ濃さで立つ（実測 0.65 → 1）。
- **プロジェクト詳細では `button` の地を親に残し忘れた。** ヘッダの ← と 区画ナビ の控えが UA 既定
  （`border: outset`、角丸なし）に落ちた。決定事項区画にも同じ落としがあり、カードが同じ姿になった。
