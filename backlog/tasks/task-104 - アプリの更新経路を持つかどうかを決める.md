## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
v0.1.0 の後の版を利用者へ届ける経路を決める。Tauri updater を使うなら更新署名鍵の管理と更新エンドポイントが必要で、公開リポジトリでの鍵の扱いを決めることになる。使わないなら、新しい版が出たことを利用者が知る手段（README・リリース通知）で足りるかを判断する。決定を decision として残す。

m-2 に置く理由: updater は署名鍵とバンドル設定がビルド時に必要なので、TASK-101 が v0.1.0 のバンドル構成を固めた後では選択肢が失われ、公開済みの v0.1.0 の利用者は自動更新の対象外に固定される。当初は m-3 へ置いたが、それでは本文が残していた「TASK-101 より前に判断する選択肢」を台帳の側で実行できず自己矛盾していた（2026-08-01 のレビュー指摘、2 名が独立に指摘）。判断だけを m-2 で行い、TASK-101 の依存にする。

このタスクが決めるのは経路と時期であって実装ではない。「updater を持つ」と決めた場合、v0.1.0 のバンドルへ受け皿を入れる作業は TASK-101 に含め、更新の配信を実際に回す実装は m-3 へ別タスクとして起票する。「持たない」と決めた場合は、v0.1.0 が意図的に手動更新のみであることを decision と README に明記する。
<!-- SECTION:DESCRIPTION:END -->
