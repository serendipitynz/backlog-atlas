## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-31 の実装。固定ヘッダ（doc-7 §2.1）の行を無くし、その 3 つを行き先ごとに分ける — 画面名は廃止、総件数はタイトルバー、メニュー（☰）はその画面の最上段の帯の右端（スイムレーンはフィルタ帯、プロジェクト詳細は doc-10 §3 のヘッダ行）。

タイトルバーへ出す手段は OS で分ける。macOS は重ね型（titleBarStyle: Overlay ＋ hiddenTitle、decorations は true のまま。信号機帯の幅を帯の左に空ける）、Windows・Linux は窓の題そのものを書き替える。分岐は cfg ではなく値で持つ（m-1 TASK-44 の規則）。自前装飾（decorations: false）は 3 OS どこでも採らない — 失う窓操作が出るうえ、固定ヘッダが OS の窓操作を持つ形になって doc-7 §2.1 と衝突する。

あわせてプロジェクト詳細の 戻る を arrow-left のアイコンのみのボタンにする。これは doc-11 §2.4 の 語の中の記号（← スイムレーン。原文は doc-12 §8）からの意図的な逸脱で、逸脱として記録する。

実測済みの値（decision-31 の実測の項）: 取り戻す高さ 32.0 pt、信号機帯の右端 69 pt・窓上端から 9〜23 pt、固定ヘッダ 46.83 px。帯の左を 78 px 空けても 1200 px 幅では溢れない。

## 実装

- **固定ヘッダの行を撤去した。** 画面名は廃止、総件数はタイトルバー、☰ はその画面の最上段の帯の右端（スイムレーン=フィルタ帯、プロジェクト詳細=doc-10 §3 のヘッダ行）。☰ は `App.svelte` の snippet 1 つで、両方の帯へ `{@render}` する — メニューの項目・開閉・モーダルからのフォーカス戻りはシェルのものなので、2 か所に写すと食い違いうる。
- **OS 分岐は値で持つ**（m-1 TASK-44）。`src/lib/platform.ts` の `OVERLAY_TITLE_BAR`（`MAC_KEYBOARD` と同じ user agent から、別の意味として名付けた）。true なら `TitleBar.svelte` が帯を描き、false なら `App.svelte` の effect が窓の題を書き替える。`cfg` 相当の分岐はコードに無い。
- **題の文言は `src/lib/title.ts` の `windowTitle` 1 か所**。macOS の帯と Windows・Linux の題が同じ 1 文を出す。`APP_NAME` は 3 つ目の綴りなので、`title.test.ts` が `tauri.conf.json` の窓 title と `index.html` の `<title>` に対して突き合わせる（読めない側を読める側から導けないため、規約でなく検査で保つ）。
- **プロジェクト詳細の 戻る** は `arrow-left` のアイコンのみのボタン。図形は lucide-react v1.17.0 の `arrow-left.mjs` の `__iconNode` をそのまま写した。
- **登録が外れた状態（`detailEntry === null`）にも ☰ を残した。** この状態はプロジェクト詳細画面が立たないのでヘッダ行が無く、置かないと 設定・登録・キーボード操作一覧 に可視の入口が無い画面が 1 つできる（doc-7 §2.1 の「ショートカットだけが入口の操作を作らない」）。**AC が求めた範囲の外にある追加なので、判断として明記する。**
- **`windowTitleSet` は `async`。** `getCurrentWindow()` は promise ができる前に Tauri の注入メタデータを読むので、Tauri の窓の外では *同期的に* throw する — `.catch()` を持つ呼び出し側の手前で落ちる。`_sandbox/app-check` で実測して分かった（画面が丸ごと立たなくなっていた）。

## 実測（借り物 playwright / WebKit・Chromium、1200x800、地 110%）

**変更前の値は decision-31 の実測の項のものを使い、測り直していない**（固定ヘッダ 46.83px・フィルタ帯 36.16px・グリッド開始 y=82.98px）。

- **実機 Tauri（macOS 26.5.2、backingScaleFactor 1.0）**: 変更前は `window.innerHeight` = **768**（窓 800 − タイトルバー 32）。`titleBarStyle: "Overlay"` を入れた後は **800**。同じ窓で `header.top` は y=0・高さ 46.828125px だった。**つまり重ね型で内容が窓の全高を得ることを実測で確かめてある。**
- **変更後（app-check ハーネスに本物の `App.svelte`、WebKit）**: タイトルバー **y=0・高さ 32px**（罫線込み。`box-sizing: border-box`）、フィルタ帯 **y=32・高さ 36.15625px**（**変更前と同じ**）、グリッド開始 **y=68.15625px**、グリッドの高さ 731.84375px。
- **内容へ返る高さ**: 変更前 768 − 82.98 = 685.02px、変更後 800 − 68.16 = 731.84px。**差は 46.82px** で、decision-31 の「固定ヘッダの 46.83px はどの OS でも内容へ返る」と一致する（0.01px は 46.828125 の丸め）。
- **☰ の寸法**: 24.625 × 24.625px（= `--bar-control` 1.4rem）。同じ帯の 直前の 1 つを戻す と同寸で、帯の高さは変わっていない（AC #3）。
- **溢れ**: 1200px 幅で `document.scrollWidth` = `clientWidth` = 1200、フィルタ帯も `scrollWidth` = `clientWidth` = 1200。プロジェクト詳細のヘッダ行も 1200 = 1200。
- **プロジェクト詳細（WebKit）**: タイトルバーの文字は `Backlog Atlas` のみ（総件数なし。AC #6）、ヘッダ行 y=32・高さ 45.22px、戻る 24.625px 角・`aria-label` は「スイムレーンへ戻る」、☰ の右端 1186.81px（行の右端 1200 − 余白 13.2px）。
- **Windows・Linux 側の枝（Chromium ＋ Windows UA）**: 帯は描かれず、フィルタ帯が y=0、グリッドは 763.84px。`pageerror` 0 件（`windowTitleSet` が拒否されても画面は立つ）。**窓の題そのものは実機でしか見られない（AC #12）。**

## Linux の帯（decision-31 の改訂。オーナーが 2026-08-15 に 3 案から選択）

**Linux も帯を描く。** 部品は macOS と同じ `TitleBar.svelte` 1 つで、置き場だけが違う — macOS は装飾の帯に
重ねる（重ね型）、Linux は装飾の下、内容領域の最上段に置く（**内容上の帯**）。**信号機ぶんの左空け 78px は
macOS だけが取る。** Linux は窓の題も従来どおり書く（無害で、窓一覧が読む環境では効く。画面に総件数を
届ける役目は帯が負う）。

**「帯を描くか」と「重ねるか」を別の値にした**（`DRAWN_TITLE_BAR` と `OVERLAY_TITLE_BAR`）。改訂前は同じ
1 つの事実だった（macOS か否か）。1 値のままだと、Linux が信号機ぶんの空白を持つか、Windows が帯を持つかの
どちらかが必ず誤る。

**代償は内容の高さ 32px である。** Linux で内容へ返る高さは 46.83 px ではなく **14.83 px** になる。退けたのは、
総件数をフィルタ帯へ出す案（数を刷る場所が環境で変わる）と、何もしない案（次に出す版で Linux の利用者が
総件数を受け取れない）。

**書き込みの適用確認は落とした。** 読み戻して届いていなければ述べる機構は、**この不具合を検出できない** —
GTK は題を受け取っているので「適用済み」と答える。守る対象も無くなった（Linux は帯が出し、Windows は題が
出ることを実測済み）。**拒否の通知は残す**: Windows で題が書けなければ総件数はどこにも出ない。
