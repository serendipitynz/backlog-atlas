## Description

オーナーの画面目視（2026-08-17、TASK-188 のマージ待ち中）で出た 8 件の指摘に応じ、**画面の注記から「利用者が行動に使えないもの」を落とす。** 対象は 文言表 の日英 2 ファイルと、それを要求している doc の該当項である。**doc の改訂を伴うので決定先行だが、争点はオーナーが同日に 3 つとも答えている**（下の「確定した判断」）。TASK-188 とは別タスクなのは、あちらの範囲が doc-11 §8 の 設計文の写し 1 種に限られており、本タスクは §8 の 残す 3 種 の側を狭める改訂だからである。

## 確定した判断（2026-08-17、オーナー）

1. **全置換の注記は落とし、doc-11 §8 を狭める。** §8 は 結果の予告 の例として「保存が既存を含む全置換になること」を名指しているが、**§8 自身の軸は「元に戻せない形で何を変えるか」** である。assignee・References・依存 の 3 欄は GUI が集合そのものを見せて編集させるので、保存で失われるものがない。**例を「欄が全集合を見せていない場合」に限る改訂を入れる。**
2. **不可の理由に添えた根拠と代替経路は落とす。** オーナーの理由がそのまま規則になる — **「`Atlas からは` と明示すれば、外部からは可能だと分かる」**、そして **「外部エディタ経路は 依存 に限らず全てに言えることなので、敢えて言う必要もない」。** 後者は 5 か所に掛かる（下の実測）。
3. **置き場は m-3 の新タスク。** TASK-188 は APPROVED のままマージする。

## 事実の誤りを 2 件含んでいたので、文言はオーナー案どおりではない

**どちらも実装・doc と突き合わせて確かめた。** オーナー案の趣旨は採り、偽になる部分だけ差し替える。

- **Type の注記。** 案は `Type は kind ラベル由来の値であり、Atlas では編集できません。` だが、**decision-20 は Type に 2 つの導出元（kind ラベル / frontmatter `type`）を与えており**、さらに **doc-8 §4 は「Type 値の由来は画面に出さない」**（どちらから来た値か区別せず 1 つの並びで出す）と決めている。画面は「この値は kind ラベル由来です」と言えない。**採る文言: `Type は Atlas では編集できません。`** — 指摘の核心（`この画面では` が別経路の存在を含意する）はこれで直る。doc-8 §4 は「この画面からも 6 章の編集操作からも変更できない」と書いており、Atlas に経路が無いことは doc 側の事実である。
- **通常ラベルの注記。** 案は `カンマを含むラベルはカンマ区切りで複数ラベルとして登録されます。` だが、**実装は逆で、発行を拒否する** — doc-10 §7 が「入力検査で拒否し、理由を示す」と決めており、`src/lib/comma.ts` がその検査である（`task create -l` に適用済み）。**採る文言: `カンマを含むラベルは登録できません。`**

- **全置換系は 文言表 に 4 件。** 落とすのは **`field.replacesWholeSet`**（呼び出し元 3 か所 = `TaskDetail.svelte:1324`・`:1698`・`:1769`）と **`taskDetail.pullRequestNote` の「既存参照を含む非空全集合で置き換えます」**。**残すのは 2 件** — `taskDetail.replaceAllNote`（AC 全体差し替えは、画面に無い旧項目を消す）と `projectDetail.bodyReplaceNote`（本文全文の置換）。**改訂後の §8 の軸で判定した結果である。**

- **doc-11 §8 の 代替経路の案内** … **外部エディタ経路は一般の逃げ道なので、各欄の 不可の理由 で名指ししない**を入れる。§8 が挙げる 3 例のうち **assignee の解除が外部エディタ経路であること（doc-8 §6）はこれで落ちる**が、doc-10 §7 の 注記モーダル と doc-10 §4.1 の slug は**具体的な別の場所**を指すので残る。**「残さない選択肢は無い」の一文はこの区別を持つ形へ書き直す。**
