2026-08-19 の TASK-161 の回に実測して分かった差。TASK-161 の AC は「markdown-it で全文描画し code span を除いて 0 件」＝**描画条件** で書かれており、それは満たした（426 個の区切りを 44 ファイルで直し 0 件）。**本タスクが扱うのは、規約の字義がその描画条件より広いことである。**

**実測（2026-08-19、markdown-it で全文描画し `</strong>` の直後が非空白・非タグの箇所を数えた）— 3,454 箇所。** 内訳は tasks 1,574・docs 1,325・decisions 555・散文 4 ファイル 64（`AGENTS.md` 29・`AGENTS.ja.md` 32・`README.md` 2・`README.ja.md` 1）。多い順に doc-11（332）・doc-10（268）・doc-7（215）・doc-8（210）。**TASK-161 が直した 426 個とは別の集合である** — あちらは描画が崩れていた分で、こちらは崩れていない分である。

**押さえているものは無い。** TASK-161 が置いた `src/lib/emphasis-closing.test.ts` は描画条件だけを持ち、字義との差はヘッダ註と AGENTS 和英に実測値として書いてあるだけである。**「`pnpm test` が通ることは字義充足の根拠にならない」を両 AGENTS が明記している。**

- **案 A: 字義どおり 3,454 箇所を書き換える。** 検査を字義へ広げれば恒久化できる。**費用は 3,454 箇所で、そのうち tasks の 1,574 は Done タスクの本文が大半を占める** — decision-36 §4 が `backlog/tasks/` を `_sandbox/` パスの走査から外した理由（終わったセッションの記録を書き換えることになる）が、ここにも同じ形で掛かるかを先に判じる必要がある。**また `**〜である**（実測:` のように直後が括弧の箇所へ半角スペースを入れると、日本語の組版として読みにくくなる** ので、字義を機械適用してよいかは実物を見て決める。
- **案 B: 規約を描画条件へ狭める改訂。** 「直前が句読点の閉じる `**` の後に文が続くなら半角スペース」へ改める。**3,454 箇所は違反でなくなり、検査と字義が一致する。** 規約の改訂なので decision を要するか判じる。
- **案 C: 現状維持。** 字義は理想として残し、検査は描画条件のまま。**新しく書く文は字義どおりに書く** という現在の AGENTS の指示を続ける。

句読点であるとき」に限り、字義超過箇所を違反でなくした。**数えた 3,872 箇所は 1 件も書き換えていない** —
動いたのは規約を述べる 3 か所（AGENTS 和英とテスト頭註）と decision-46 だけである。

**判断の根拠になったのは、着手時に測り直して初めて出た内訳である。** 閉じ側の直前と直後を組にして
数えると、字義超過箇所は 3 つにしか割れない — 語 → 約物 2,655、語 → 語 1,049、約物 → 約物 168 で、
**約物 → 語 は 0 である。** そしてその 0 は実測値ではなく CommonMark からの帰結で、直前が約物・直後が
語だと閉じ側が right-flanking を満たさず `<strong>` が生まれないためである。**規約が理由として挙げて
いる例文 `**〜です。**Atlas` はその形そのもの** なので、**規約の理由は字義が指す 3,872 箇所に 1 件も
現れない。**

**半角スペースを入れて読みやすくなる並びも 3,872 のどれでもない。** **何が壊れるかを決めるのは直後の
文字である** — 直後が語の 1,049 件では語と助詞・述語の間が割れ、直後が約物の 2,823 件では約物の前が
空く。**案 A は機械適用できないと分かったので退けた。** 実体は 3,872 件それぞれについて文を書き換えて
