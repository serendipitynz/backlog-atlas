## Description

<!-- SECTION:DESCRIPTION:BEGIN -->

## 先行して積んだ差分 (画面設計案 02、TASK-73 の目視より。2026-08-04)

TASK-73 の目視でユーザーが見つけた差分のうち、TASK-113 (区画の並び・全面の列構成) に束ねなかった 2 件。
どちらも触る契約が TASK-113 とは別なので、ここで分類する。

- **ACCEPTANCE CRITERIA の達成割合バー** — 原文は常設区画の罫線の位置に達成数 (`2 / 3`) と達成割合の
  バーを入れる (doc-12 §3)。実装は達成数だけを持ちバーが無い。doc-8 §3 の割当表は AC の内容を
  「`#N` 項目と checked 状態、達成数」とし、バーに触れていない。
- **通常ラベルを TYPE 区画の中の小見出しとして描くこと** — 原文は通常ラベルに罫線付きの区画見出しを
  与えず、TYPE 区画の中の小見出しにしている (doc-12 §3)。doc-8 §4 は Type と通常ラベルを別区画として
  出すことを AC の要請から定めているので、実装は別区画のままにしてある。意図的に外れる側の候補。

## 先行して積んだ差分 (TASK-117 の目視より。2026-08-07)

PR #73 の目視でユーザーが見つけた 2 件。どちらも**画面設計案との差分ではなく実装どうしの不統一**なので、
07 との突き合わせとは別枠だが、拾う先が他に無いのでここで分類する (TASK-121 へ回した 2 件とは別)。

- **`<select>` の高さが `<input type="text">` と揃っていない** — 文書作成モーダルの title・type・path が
  1 行に並んだとき、type だけが低い。**ユーザーの指摘は「ここに限らず」で、画面全体に効く規則の欠落として
  出ている。** doc-11 §2.2 (寸法) はフォーム部品の高さを持っておらず、各コンポーネントが素の
  `<input>`・`<select>` を出しているだけなので、揃うかどうかはエンジンの既定に委ねられている
  (WebKit と Chromium で `<select>` の既定 padding は違う)。**追随する側の候補**だが、直す先は
  画面ではなく doc-11 §2.2 と `app.scss` である — 1 画面で揃えると同じ不統一が次の画面で再発する。
- **作成モーダルの欄の並びが 2 区画で揃っていない** — 文書は title・type・path を横 1 行に、
  マイルストーンは名称・説明を縦に積む。**doc-10 §1 は作成モーダルを「2 区画とも同じ型を使う」と
  定めた (TASK-117) が、揃えたのは入口と層であって欄の配置ではない。** 欄数が 3 と 2 で違うので
  同じ配置が最適とは限らず、「同じ型」がどこまでを含むのかを決める必要がある。**追随する側の候補**で、
  直す先は doc-10 §1 (作成モーダルの定義に欄の配置を含めるか) である。

## 先行して積んだ差分 (TASK-79 の目視より。2026-08-08)

TASK-79 の一掃と目視で出た 3 件。**文言ではないので TASK-79 の AC 4 件のどれにも当たらず**、
契約変更を要するものは別タスクへ起票した (TASK-122〜126)。ここに積むのは残り 3 件。

- **Git 履歴欄の全面への導線と、doc-12 §3 の転記が食い違う** — 転記は
  「残り 1 件と関連 PR は全面表示で →」という**件数形**だが、実装のボタンは展開するものが無いときも
  出るのでその形を取れない (`GitHistory.svelte`)。TASK-79 はラベルを操作の名へ書き直したうえで、
  **画面設計案 02 への帰属をしていない**。追随するか意図的に外れるかはここで決める。
  **TASK-79 の Description が「原文は『全面表示で開く →』」と書いていたのは誤り**で、
  転記を当たって判明した。
- **上部帯 ⑤ 通知の変化が分かりづらい** (TASK-74 の目視、2026-08-05)。TASK-74 の記録は
  「帯全体を見る TASK-79・80 で扱う」としているが、**これは文言ではなく帯の描き分け**で、
  doc-11 §4 が 6 種すべてに共通で決めている。⑤ だけを強めると描き分けが崩れるので、帯全体を見る
  こちらで扱う。
- **作成モーダルの欄の並び (再掲)** — 2026-08-08 の目視でユーザーが同じ点を挙げ、
  **方向を明示した**: 文書側のレイアウトをマイルストーン側に合わせる。上の TASK-117 由来の項と
  同じ対象で、直す先も同じ doc-10 §1 である。
