## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
タスク詳細の編集セッションでラベルを追加すると、カンマを含む値が保存時に 2 件のラベルへ分かれる。v1.48.0 の task edit --add-label は 1 個のカンマ区切り値として読むため（実測。--add-label "a,b" で labels が a・b の 2 件になった）で、Atlas 側にこの入力を拒む検査が無い（src/lib/edit.ts の buildSave の labels 節）。同じ規則は既に別経路で守られている: 新規タスク作成モーダルのラベルと文書のタグは commaReason で拒む（src/lib/comma.ts。TASK-151 が manage.ts から移した）。したがって同じ入力が作成では拒まれ編集では通るという非対称であり、しかも編集側は divergence（edit.ts）がラベルを突き合わせないので事後通知にも載らない。dependencies も --depends-on がカンマ区切り全置換なので同型だが、値が TASK-ID なので現実の入力にカンマが入りにくい。References は --ref を参照ごとに繰り返すので分割は起きない。TASK-151 のセッションで、assignee の同型を直しているときに見つけた。公開阻害には当たらないとこちらは判断した（保存後の画面に 2 件のチップが出るので結果は見えており、データは失われない）。
