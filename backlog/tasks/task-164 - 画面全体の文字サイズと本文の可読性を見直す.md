## 決めたこと

**置き場は `app.scss` の `:root` である**（doc-11 §9 の 2 つ目に追記）。これは doc-11 §9 の既存の但し書き「複数コンポーネントが参照するものだけを変数として置く」の適用結果ではなく、**その但し書きの外に出した** — 1 コンポーネントでしか使わない大きさであっても段を取る。「ここでしか使わないから」を許した結果が 186 件だったためで、decision-12 が色値に与えているのと同じ形にした。

**文字寸法段階は 6 段・幅一定 0.06rem**（`.62 / .68 / .74 / .80 / .86 / .92rem`）。既存 18 値の割り当ては **最寄りの段へ寄せる**規則で機械的に決め、**同点は大きい側へ寄せた**（このタスクは字が小さいことを直すものなので、同点で小さい側を選ぶと目的と逆を向く）。**動いた幅の最大は 0.08rem** で、`1rem` だった 2 件（`h1` と ☰）だけがそれに当たる。残りは 0.04rem 以下。

**幅を一定にしたのは、狭い段が段として働かないためである。** 置き換えた 18 値には `.74/.75`（0.01 差）と `.92/.95`（0.03 差）があり、隣り合う 2 つを別の大きさとして読める画面は無かった。検査は「ある幅以上」ではなく**一定であること**を見る — 下限だけでは一部だけ詰まった梯子が通る。

**画面設計案 06 のタイポ 2 行から意図的に外れた**（doc-12 §7.1、逸脱表に行を足した）。原文の 6 値を含む一定幅の梯子が無いためで、外れたのは タスク title（`.95` → `.92`）と カード title（`.78` → `.86`）だけ。残る 4 行は原文の値か原文の範囲の中にある。

## PR #118 のレビューを受けた改め（1R、Codex、2026-08-14）

**4 件すべてを受け入れた。取り下げた指摘は無い。**

- **[P2] 検査が `var(--…)` を名前で通していた。** 画面が `--caption-size: 0.5rem; font-size: var(--caption-size)` と書けば通っていた — 別名を見る case が名前に `text` を含むものだけを対象にしていたためである。**`var()` を定義まで辿って段に届くかで判定する形へ改めた**（`resolvesToAStep`）。名前で選ぶ形が穴そのものだったので、**名前で選ぶ専用の case は落とした** — 残すとそちらが番をしているように読める。**別名が 2 か所で定義され片方だけが段を指す形も通さない**（すべての定義が段に届くことを要求する）。循環は段に届かないものとして扱い、検査が止まらないようにした。

- **[P2] doc-11 §2.2 で閉じる `**` の後の半角スペースが 1 か所欠けていた**（`。**利用者` → `。** 利用者`）。**指摘より広い範囲が壊れていた** — 描画すると `<strong>` が入れ子になり、強調の範囲が約 200 字ぶんずれて、意図した太字（「全体的にテキストサイズが小さい」に対する変更はこの 1 行だけである）と、太字でないはずの文が入れ替わっていた。**自分の検査が取り逃した理由は 2 つある**: (1) literal の `**` を数える形は「対がずれた `**`」を捕まえない（指示書が警告している型）、(2) 入れ子の検出に `/<strong>[^<]*<strong>/` を使っており、**間に `<code>` が入ると当たらなかった**。**深さを数える形に改めて文書全体を旧版と突き合わせ、この 1 行だけがこの PR 由来であることを確かめた**（doc-12・task-164・task-173 は 0 件）。

## 目視の反映（2026-08-14、受入条件 #4 の 1 巡目）

**ユーザーが backlog browser と並べて 3 つを述べた。**「前より大きくなって見やすくなった」「特にカンバンのカードは現在のバージョンがよい」「マークダウンのレンダリング部分はまだ小さい。余白も少なく窮屈で、段落間のマージンと上下左右のパディングを広げた方がよい」。**前 2 つは据え置きの指示、3 つ目が変更の指示である** — 混ぜるとカードまで動く。

**動かした範囲は 整形表示 だけである。** **カードが動いていないことは実測で確かめた**（card title 15.14px・横断タスクID 13.02px。変更前後で同値）。

| 整形表示（4 か所とも同値。WebKit・Chromium） | 1 巡目 | 2 巡目 |

| 行の高さ | 19.54px | 21.12px |
| ブロックの padding（上下 / 左右） | 6.16 / 7.92px | **10.56 / 13.20px** |

**余白はすべて §2.2 の 余白段階 の値へ揃えた。** これは併せて逸脱の修正でもある — `.body-block` の padding は `0.35rem` で、**段階に無い値だった。**

**本文の行が 2 本になった代償を doc-11 §2.2 に書いた**: 整形表示の本文 の段を取るのは `Body.svelte` だけで、他の画面は 本文・リスト の段を取る。**画面の本文・リストは動かしていない** — 同じ目視が「前より大きくなって見やすくなった」と述べており、動かす理由が報告のどこにも無い。
