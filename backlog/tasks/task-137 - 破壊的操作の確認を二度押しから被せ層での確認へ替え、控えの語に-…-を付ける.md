## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-09 のユーザーフィードバック (`task-edit1.png`・`task-edit2.png`・`task-edit3.png`)。タスク詳細の状態遷移区画にある draft へ差し戻す・アーカイブ・完了整理は、1 度目の押下で同じ控えのラベルが「〜：実行してよいですか？（もう一度押す）」へ変わり、2 度目の押下で発行する。ユーザーの指摘は「ボタン連打でほぼ確認なく実行できてしまうので危険」。

求められている形は 2 つ。
① 確認をポップアップなりモーダルなりではっきり出す。
② すぐに実行されない操作なので、控えの語を `draft へ差し戻す…`・`アーカイブ…`・`完了整理…` のように `…` 付きにする。

**決定先行**: 画面設計案 06 が「二度押し確定の破壊的操作はラベルを差し替える（「実行してよいですか？」）」と定めている (doc-12 §7.2) ので、これは原文からの意図的な逸脱になる。加えて doc-11 §7 は被せ層を同時に 1 枚だけと定めており (doc-7 §2.1)、状態遷移区画は中央モーダル配置ではモーダルの中にある — その中で確認を出す形が doc-8 §6.3 の破棄前確認 (モーダルの中に出す) と同じでよいかを決める。破棄前確認が問うのは未保存入力の行方で、こちらが問うのは発行そのものの可否なので、同じ層の使い方でも問いは別である。

同型の二度押しが他にあるかを数える (登録解除は slug の入力を求める形なので別、doc-12 §8.2)。

## 決定（2026-08-11）

**争点 3 件をユーザーが確定した。** ①確認の場所は**被せ層を 1 枚上げる**（上部帯 ①・区画内の確認行の 2 案は採らなかった）、②範囲は**状態遷移 5 件すべて**（active の 3 件に加え draft の `タスクへ昇格`・`アーカイブ`）、③**外部エディタ起動の二度押しも同じ形へ替える**。

**語は `実行前確認` とした。** 対応表の第 1 版は `発行前確認` だったが、③の回答で外部エディタ起動（CLI 更新ではなく起動）も同じ問いを通ることになり、doc-5 の `発行` では指示対象を覆えなくなった。原文（画面設計案 06）の語も「実行してよいですか？」である。対応表は `_sandbox/handoff/referent-table/referent-table-task-137.md` 第 2 版。

**doc 改訂だけで足り、decision は書いていない。** doc-11 §12 新設・§5 末項の撤去（§12 へ移した）・§10 に記録、doc-8 §6.5・§7 に通る控えを名指し、doc-12 §7.2 に画面設計案 06 からの意図的な逸脱を記録（逸脱表に 1 行）。

## 着手して分かったこと

**1. 二度押しは 5 か所ではなく 7 か所に掛かっていた。** ユーザーが名指したのは active の 3 件だが、`confirming` は kind を問わず掛かるので draft の 2 件も同じ形で、さらに外部エディタ起動 2 件（未保存入力があるときだけ）が同型のラベル差し替えを持っていた。後者は doc にどこにも書かれておらず、実装の註と `needsConfirmation` にしかなかった。

**2. 現行の二度押しには連打とは別の抜けがあった（実測で確認）。** `confirming` は `task.sourcePath` を鍵に持たず（同じ画面の `openState`・`confirmingOpen` は持っていた）、`<TaskDetail>` は key を持たないので別のカードを選んでも作り直されない。**1 打してから別のタスクを選ぶと、差し替わったラベルがそのまま残り、次のタスクを 1 打でアーカイブした** — コンポーネントテストで再現させ（`update_apply` が 1 件、引数に次のタスクの id）、その記録を doc-11 §12 の逸脱理由の 2 つ目にした。

**3. 中央モーダル詳細配置は被せ層ではない。** `.modal-layer` はグリッド領域だけを覆い、フォーカスも Escape も持たず上部帯を覆わない（doc-11 §7 も「§7 のモーダルに含まない」と明記）。したがって詳細がその配置のときに確認の層を上げても「同時に 1 枚」に触らない — 争点 1 で (a) を選べる根拠がこれである。

**4. 「破壊的操作」は doc-11 が定義していない語だった。** doc-8 §6.5 は「逆操作の無い」と限定していたが、`backlog task --help`・`backlog draft --help` を実測すると**押す前の状態へ戻せる遷移は 1 件も無い**（アーカイブ・完了整理を戻すサブコマンドが無く、`task demote` と `draft promote` は互いの行き先へ戻せるが id を採番し直す）。範囲を語で書かず、通る控えを各画面の doc が名指しで持つ形にした。

**5. 問いの文は控えの隣の 結果の予告 の言い直しにできない。** `effect` は押す前に「この控えは何をするか」を述べるもので、完了整理のそれは前提（`status が Done のときのみ`）を含む — 問いが立てる時点では既に満たされている条件である。5 件それぞれに問いの文を持たせた。**片道の 3 件の語は目視で替わった** — 初版は「アーカイブから戻す操作は v1.48.0 の CLI にありません」と実測を述べていたが、ユーザーが「この操作は戻せません。」を指定した。版番号が答えているのは、この押下について問われていることではない（実測そのものは doc-8 §6.5 が持ち続ける）。

## 同型の二度押しの数え上げ（AC #4）

**替えた（同型・7 控え）**: タスク詳細の状態遷移 5 件（`draft へ差し戻す` / `アーカイブ` / `完了整理` / `タスクへ昇格` / draft の `アーカイブ`）と、外部エディタ起動 2 件（`…で開く` / `OS の関連付けで開く`。未保存入力があるときだけ問う）。**同型は 0 件になった**（`もう一度` の全文検索で残るのは、下の 起動の差し控え と、競合を提示したあとの「内容を確かめてからもう一度保存してください」という案内文だけである）。

**同型ではない（替えていない・3 形）**: どれも 2 打目が別の要素なので、同じ座標の連打が動作に届かない。
- **起動の差し控え**（doc-8 §7 の `WATCH_STOPPED_BEFORE_LAUNCH`）… 1 打目は問いを立てず、押下が継続検出の停止を見つけて報せている。
- **slug 入力一致**（doc-10 §4.3 の登録解除）… 本節より強い条件。
- **副パネル ＋ 発行の控え**（doc-10 §6 のマイルストーン 改称・削除・アーカイブ）… 押下で副パネルが開き、必須入力を受けてから別の控えが発行する。

## 実測（2026-08-11）

**シェル**: `_sandbox/app-check/`（本物の `App.svelte` ＋ 本物の `commands.ts` ＋ 偽 IPC）を WebKit・Chromium の両方で、1280×800（明・暗）と 560×420（明）の 6 条件。

| 測ったもの | WebKit / Chromium 1280×800 | 560×420 |
|---|---|---|
| 確認の層の箱 | 706×107px（両エンジン同値。暗いテーマでも同値） | 528×107px（Chromium の外部エディタ側だけ 528×161） |
| 見出しの文字の右端 対 × の左端 | 940 対 960（20px 空き） | 491 対 511（20px 空き） |
| × の中心の最前面 | × のアイコン（見出しではない） | 同じ |
| 横あふれ | 0px | 0px |
| **押した控えの中心の最前面** | **層の地（`DIV.backdrop`）** | 同じ |
| 押した座標から 2 答までの距離 | 740 / 692px（Chromium 738 / 688） | 308 / 247px |
| やめる で層が下りる | 下りる | 下りる |

**連打で素通りできないこと（AC #2）の根拠はこの 2 行である** — 押した座標は層の地で覆われ、答えは 242〜740px 離れた別の層にある。

**語尾の `…` は切り落とされていない**（`text-overflow: clip`・`white-space: normal` で `scrollWidth === clientWidth`。WebKit 105 / 75 / 65px、Chromium 109 / 79 / 68px）。CSS が作った省略記号ではなく、こちらが足した記号が描かれている。

**外部エディタ側**: 未保存入力があるときだけ控えが `…` を持ち（`アプリ設定の外部エディタ指定 で開く（code）…`・`OS の関連付けで開く…`）、押すと層の名前がその動作名になる。長い動作名でも見出しは × の下へ入らない（上表）。1280×800 では最大スクロール位置で控えの中心の最前面が控え自身だが、**560×420 で編集セッションを開いた状態では固定見出しが控えを覆う** — これは doc-11 §11 の固定行と最下部の区画の幾何で、本タスクが動かしたのはラベル 1 文字ぶんなので、この覆いは本変更に帰属しない（TASK-136 が測ったのと同じ型）。

**偽 IPC 側の直しを 2 件入れた**（`_sandbox/` はローカル無視）: `settings_read` が `default_card_order` を返しておらず `CARD_ORDERS[order]` が undefined でスイムレーンが描画で投げていた（TASK-132 が足した項目）。`editor_probe` が `{ state, command }` という wire に無い形を返しており、外部エディタ区画が 未設定 の理由を描いていた。

## 目視（2026-08-11）

**ユーザーが実アプリで層を確認し、問いの文の指摘 2 件を出した。** `アーカイブから戻す操作は v1.48.0 の CLI にありません。`・`completed から戻す操作は v1.48.0 の CLI にありません。` の 2 つを **`この操作は戻せません。`** へ替えた。**draft のアーカイブも同じ語にした** — 指摘は画面に出ていた active の 2 件についてだが、述べている事実が同じものなので、1 つだけ別の語を残すと同じことを 2 通りに述べることになる。片道でない 2 件（差し戻す・昇格）は「戻せません」を持たない（id を採番し直すことを述べる）。

**測っていない（目視の範囲）**: 実アプリ（Tauri WebView）で層が実際に上がること、5 件それぞれの問いの文が読めること、進む側の答えで実際に CLI が走ること、暗いテーマ以外のテーマでの見え方、キーボードだけでの往復（Tab の巡回とフォーカスの戻り先）。
