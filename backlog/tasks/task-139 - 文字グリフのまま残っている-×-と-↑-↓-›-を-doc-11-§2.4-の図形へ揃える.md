## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-80 の洗い出しで確定した追随項目。doc-11 §2.4 は画面の記号を lucide の図形 (viewBox 24・線幅 2・1em) へ揃えると定めているが、文字グリフのまま残っている箇所が 2 群ある。

① `×` が 3 か所 — 上部帯の通知の閉じる・絞り込みトークンの解除・status 別名表の行削除。doc-11 §7 が「本節はモーダル以外の × を覆わない…TASK-80 が実装と画面設計案の差分としてまとめて扱う」と本タスクへ預けている。図形 `x` は `src/lib/icons/lucide.ts` に既にある。
② `↑`・`↓`・`›` — doc-7 §5.2 が「文字グリフのままで、置き換えの対象に入っていない (doc-11 §2.4 が挙げる 5 タスクのどれもこの 3 つを扱わない。差の当否は TASK-80 が判断する)」と本タスクへ預けている。`arrow-up`・`arrow-down` は既にあり、`›` に当たる図形は追加が要る。

揃える理由は doc-11 §2.4 が既に持っている — 文字グリフは字面と大きさがフォントによって変わり、画面共通の寸法規則に乗らない。**同じ行に並ぶ控えの高さが揃う条件でもある** (TASK-74 の実測: 図形の箱は自分の 1em で、文字の行箱から高さをもらわない)。

## 着手時判定 — 決定先行だった（決 印は後付け）

対応順の表に 決 印は無かったが、AC #4 が doc-11 §7 と doc-7 の預けを閉じることを求めており、
`›` に当たる図形が `lucide.ts` に無く、その選択が製品判断だった。ユーザーへ出した争点は 3 点で、
**3 点とも推奨案で確定**。**doc 改訂だけで足り decision は書いていない。**

- **争点 1（図形の族）**: `›` に lucide `arrow-right` を新設し、`↑↓` は 前後移動 と同じ
  `arrow-up`/`arrow-down` を共用する。実装は TASK-67 以来「chevron＝折畳み／arrow＝移動」で
  書かれていたが、規則としてはどこにも無く `arrow-up` の註が理由を 1 度述べていただけだった。
  `chevron-right` を行末の入口へ回すと、同じスイムレーン画面で 1 つの図形が「列を開く」と

- **争点 2（AC #3 の範囲）**: 名指しの 6 か所に加え、残る `✓`・`☑☐`・`→`・`＋` も同じ PR で揃える。

  図形にすることは追随ではなく逸脱である。図形を採り、doc-10 §4.2 に逸脱として記録した。

## 着手して分かったこと

- **AC #4 の「doc-7 §5.2」は節番号が違っていた。** 預けの記述は §2.3（レーンヘッダ行の図の下）に
  あり、§5.2 が持っていたのは「保存区分の既定をトークンの × で外し」という 1 文だけだった。
  §2.3 の預けを閉じ、§5.2 のその 1 文も控えの名（解除）へ直した。
- **TASK-80 の判定は原文と突き合わされていなかった。** doc-11 §7 末項の預けは `×` の字形についての
  もので、status 別名表の原文が文言だったこと（doc-12 §8.2）は入っていない。争点 3 はこれで出た。
  同じ行の「＋ 別名を追加」も原文の `＋` が落ちており、こちらも未記録の逸脱だった（doc-10 §4.2 に
  2 件目として記録。発行しない控えに 作成の入口 の印を置かないのが理由）。
- **`☑`/`☐` を図形にすると閲覧側の名前が消える。** 文字グリフだったころは中身そのものが名前で、
  `<span aria-label>` はそれを上書きしていただけだった。図形は `aria-hidden` なので、包む要素は
  中身の無い `<span>` になり、`role` の無い要素の `aria-label` は読み上げに現れない。
  doc-11 §2.4 に 族を持たない状態の印 を新設し、`role="img"` を条件に書いた。
- **保存で送る属性 の `→` は、図形にすると doc-11 §2.4 の 操作に属さないアイコン の条件に触れる。**
  その型は「図形が示すことを同じ区画の語も述べていること」を求めるが、変更前と変更後を
  分けていたのは `aria-hidden` の `→` だけで、読み上げは「project_root 旧パス 新パス」だった。
  視覚的にのみ隠す語（変更前・変更後）を足した。**替える前から同じ欠陥だったが、
  図形にして初めて規則が当たる。**別名表の側は区画の hint 文が既に述べていた。
- **図形の族の規則を doc に書いただけでは何も守らない。** 図形の選択がマークアップに散っていると、
  規則を突き合わせる相手が無い。スイムレーンの 4 控えぶんを `swimlane.ts` の `LANE_FIGURE` に出し、
  `swimlane.test.ts` が `placement.ts` の `DISCLOSURE_ICON`・`STEP_ICON` と併せて「折畳みは chevron・
  移動は arrow・両方に出る図形は無い」を検査する。**表に出し切らないと穴が残る** — 前後移動 だけは
  1R の [P3] まで `TaskDetail.svelte` にインラインで残っており、検査が読んでいなかった。
