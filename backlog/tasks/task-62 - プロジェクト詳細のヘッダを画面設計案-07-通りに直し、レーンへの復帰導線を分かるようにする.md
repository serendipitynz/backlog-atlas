## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
画面設計案 07 はヘッダ左上に「← スイムレーン」を置き、その右にプロジェクト名・slug・件数を並べる。現在の実装は ProjectDetail.svelte の件数表示より後ろに戻るボタンを置いており、復帰導線が見つけにくい。あわせて「このプロジェクトのレーンへ」が機能していないように見える問題を直す。原因は着地が scrollIntoView({block:'nearest'}) だけで、対象行が既に視界内にあると何も動かず、行が視界外でもレーンヘッダ行が非スティッキーなため着地位置が分からないこと。

## 決めたこと（doc-7 §2.3 へ 1 項。decision は書いていない）

TASK-62 は決 印なしだが、着手時の判定で AC #3 の「一時的な強調」が doc-7 §2.3 の着地の記述に無い
新しい振る舞いだと分かり、doc-7 §2.3 の改訂を先に行った（doc 改訂だけで足りる 12 例目）。対応表は
`_sandbox/handoff/referent-table-task-62.md`（第 1 版・先行確定）。

- **着地には一時的な強調が伴う**（doc-7 §2.3 に追記）。一時的な強調とは、着地した行のレーンヘッダ行に
  付き、ひとりでに消える背景の色づきを指す。対象行が既に視界内にあると着地は何も動かさないので、
  これが無いと復帰は「何も起きなかった」ように見える — 強調はスクロールの有無によらず着地のたびに付く。
- **付く先はレーンヘッダ行 1 本**（行の可視の身元はこの行で、行折畳み中はセルが無くこの行だけが行を代表する）。
- **doc-11 §2.3 の表には足さない** — §2.3 の 4 行は持続する状態の描き分けで、消えた後に何も残らない事象は
  対象でない。選択の outline（--sel）も借りない（借りると持続する選択と見分けが付かない）。
- **AC #1 のヘッダ再配置は契約を動かさない** — doc-10 §3 は中身（名前・slug・件数・往復 2 操作）を定め、
  並びを定めていない。並びの写し元は doc-12 §8 のパンくず転記。doc-10 の改訂は不要。

## 実装

- `ProjectDetail.svelte` のヘッダ: `.identity`＋末尾 `.exits` を、パンくず（`← スイムレーン` ボタン /
  区切り `/` / プロジェクト名）＋ slug ＋件数＋右端の「このプロジェクトのレーンへ」へ再配置（AC #1）。
  文言は 2 つとも不変なので既存のコンポーネントテストのセレクタは動いていない。
- `Swimlane.svelte`: 着地の $effect の末尾で `landedSlug` を立て、`.lane-head` に `.landed` を付ける。
  消すのは `animationend`（`event.target === event.currentTarget` で子のアニメーション終了を弾く）。
  色は `color-mix(in srgb, var(--info) 30%, var(--inset))` から `--inset` へ 1.6s ease-out —
  `--info` は「通知・確認」の変数で、不透明のまま退色する（レーンヘッダ行の下をカードが流れるため）。
  常設 transition ではなく一時 class の一発 animation（TASK-72 の教訓: 常設するとテーマ切替を巻き込む）。
- AC #2（行非表示の解除）は `App.svelte` `leaveProject` の `show(slug)` が既に持つ現行挙動で、変更なし。
- コンポーネントテスト 1 本追加（画面横断契約: 詳細画面の出口 → シェル → グリッドの着地の強調）。
  jsdom はアニメーションを走らせないので class の付与だけを検査し、退色と終了は実測で確認した。
