## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-11 のユーザーの目視で報告された。**スイムレーン画面で列や行を畳んでからプロジェクト詳細画面へ移り、スイムレーン画面へ戻ると、畳んでいた列・行が畳まれていない。**

**原因は値の置き場である。** `Swimlane.svelte:273-274` の `collapsedColumns`（列折畳み）と `foldedRows`（行折畳み）はその部品だけが持っており、`App.svelte:2217` の `<Swimlane>` は `{#if screen === "project"} … {:else}` の下にあるので、詳細画面へ移ると部品ごと降りて 2 値が失われる。**同じ原因の経路がもう 1 つある** — `App.svelte:2216` の `{#if placement !== "full" || selectedRef === null}` により、既定の詳細配置 が 全面シングルビュー のときはタスクを選ぶだけで同じことが起きる。

**行非表示 では同じことが起きない。** `App.svelte:253` の `hidden` は `App` が持つので、画面を移っても残る。**doc-7 §5.1 は 行折畳み・列折畳み・行非表示 を 1 つの規則にまとめている**（「いずれも画面の一時状態で、アプリ設定にも台帳にも保存しない」）が、**その規則は 1 回の実行の中でどこまで残るかを述べておらず**、実装は 3 値に 2 通りの寿命を与えている。契約からの逸脱ではなく契約の欠落である（TASK-113・TASK-115 と同型）。

**本タスクの範囲は 実行内保持 だけである。実行内保持 とは、1 回のアプリ実行の中で画面を移って戻っても値が効いたままであることを指す。**保存先を要さず、値を持つ場所を、画面を降ろす部品の外へ移せば足りる。アプリの終了と起動をまたぐ保持は decision-13 の改訂を要するので TASK-148 が扱う。
