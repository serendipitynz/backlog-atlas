## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
PR #73 (TASK-117) の目視フィードバック (2026-08-07) 由来の 2 件。どちらも doc-10 §5・§6 の契約を変えるので決定先行。

**① 文書・マイルストーンの「選択を解除」を撤去する。** TASK-116 がこれを置いた理由 (作成フォームの未保存入力が画面外で破棄前確認に数えられ続ける) は TASK-117 で消えており、TASK-117 は「どの対象も選んでいない状態へいつでも戻れること」へ理由を書き直して残した。目視でユーザーが不要と判断したので、その理由ごと反転する。撤去すると doc-10 §5 の非選択時の文書ペイン (提供しない操作区画＋1 行) と §6 の非選択時の操作ペイン (1 行のみ) は、選択が着地する前の初期状態としてしか現れなくなる — その状態を残すのか、それとも一覧の先頭を自動選択するのかまで含めて決める。§6 の破棄前確認は「選択を解除する」を 2 経路のうち 1 つに数えているので、経路数も動く。

**② マイルストーン区画にも閲覧と編集への切替を導入する。** 現在 §6 の操作ペインは選択で改称・削除・アーカイブと説明の編集入力を同時に開いており、doc-8 §1 の編集セッションはどこにも現れない。§5 が TASK-116 で「選択は閲覧を開き、編集は明示的に切り替える」に変わったので、同じ形の一覧列を持つ 2 区画で選択の意味が食い違っている。§6 に閲覧 (id・title・説明・所属タスク件数を読む状態) と編集への切替を入れ、説明の編集入力と 3 操作をその向こうへ移すかを決める。

用語は doc-10 §5 の確定語 (閲覧・閲覧ヘッダ・編集への切替・編集セッション) を使う。TASK-116 の対応表は「閲覧モード／編集モード」を、モードが文書ペインの状態とも画面全体の状態とも読めることを理由に退けている。

①②を 1 件にしてあるのは、どちらも同じ `ProjectDetail.svelte` の選択分岐と doc-10 §5・§6 を触り、①が撤去したあと何が非選択時に残るかは②が §6 に何を置くかで変わるため。別セッションに分けると同じ節を 2 度読み直すことになる。
