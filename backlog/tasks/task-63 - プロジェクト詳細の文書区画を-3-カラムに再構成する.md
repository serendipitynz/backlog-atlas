## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
画面設計案 07 の文書区画は、16rem の文書一覧と編集ペインの 2 カラムで、これが画面共通の区画ナビ（12rem・概要／文書／マイルストーン／新規タスクを切り替える。4 区画すべてが共有する）の右に並ぶため、画面全体では 3 カラムに見える。現在の実装は単一スクロールのアコーディオンで、一覧と編集が縦に積まれ、文書を選び直すたびに縦位置を失う。3 カラムへ再構成し、一覧の選択と編集ペインの内容を左右に並べる。

画面設計案 07 は 12rem ナビの外側を単一スクローラにしており、列ごとの overflow を持たない。しかし一覧の縦位置を保つ（ユーザーが求めた gmail 的な操作）には列ごとの独立スクロールが必要なので、そこは意図的に 07 から外れる。doc-10 に理由を記録する。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 構成 (TASK-64 が引く。2026-08-05 目視反映後)

- 3 カラム: 区画ナビ 12rem (`--section-nav-width`。旧 9rem を design 07 の値へ。4 区画共通) / 文書一覧 16rem (`--doc-list-width`) / 編集ペイン (残り幅)。幅定数は `lib/project-detail.ts` の `SECTION_NAV_WIDTH_REM`・`DOC_LIST_WIDTH_REM` から custom property で降ろす。**いずれも content box を名指す** (TASK-115。padding・1px 罫は外側)。
- **文書一覧はカード** — 行全体が選択の操作で編集ボタンを持たず、選択中カードは強調＋「編集中」チップ。列頭に「文書 N 件」(スクロール外)。パスは一覧に出さず、編集ペイン見出し下の表示パス (`displayPath` = source_path のプロジェクト相対、表示専用) に出す — **07 からの意図的逸脱 2 件目** (1 件目は独立スクロール。どちらも doc-10 §5 に記録)。
- **編集ペインは排他** — 編集セッションが開いている間は更新フォームだけを出し、閉じている間だけ作成フォームと提供しない操作区画を出す ({#if docSession}...{:else}...{/if})。縦積みの同時表示ではない。「閉じる」は「編集を閉じる」。ペイン先頭ブロックは margin-top 0 (上部余白の目視指摘)。
- `.panel` は文書区画のとき `&.split` でスクロールを止め、左右 padding を各列 (`.doc-list`/`.doc-cards`・`.doc-pane`) へ移す — スクロールポートの端に接したフォーカスリングが切れるため (TASK-74 実測)。一覧側のスクローラは `.doc-cards` で、見出しは外。
- **選択が成立したら編集ペインだけを先頭へ戻す** (`await tick()` 後に scrollTop=0。1R [P2])。一覧には触れない。
- 破棄前確認は `.columns` の外・上。**文書区画自身の契約** (doc-8 §6.3 を借りない。2R [P2]) — 経路は 別の文書を選ぶ / 編集を閉じる、答えは 破棄して続行 / 入力に戻る。
- ルート読取不能・読み込み中は列を作らず、文と提供しない操作区画だけを出す。

## 実測 (playwright WebKit、1280×800)

- 初版: 3 列横並び x = 0 / 205.8 / 484.4、content 幅 ナビ 192.2px ≒ 12rem・一覧 256.4px ≒ 16rem (Chromium も一致)。
- 目視反映後 (?docs=12): ペイン先頭ブロックが列上端と一致 (51.4=51.4)。編集中ペインは更新フォームのみ。表示パス `backlog/docs/doc-3 - screen.md`。一覧 scrollTop はカード選択で保持 (クリックしたカードが見切れていた場合のみ WebKit の焦点合わせで数 px 動く)。ペインは選択で 0 へ。
- ハーネス: `_sandbox/project-detail-check/` に `?docs=<n>` を追加 (fixture の 1 件を複製、title 長は 3 行ごとに長文)。
