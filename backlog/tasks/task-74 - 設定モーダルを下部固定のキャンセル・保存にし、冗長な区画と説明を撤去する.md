## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
設定を変えて閉じても何も起きないのが分からない。「閉じる」をなくし、モーダル下部に固定で「変更せずに閉じる」と「保存する」を置いて常に見えるようにする。「保存する」は変更があるときだけ活性化し、押下で保存して閉じる。結果として「変更を取り消す」ボタンと「保存できません：変更ありません」的な説明は不要になるので落とす。「ここに無い項目」の見出しと中身は完全に冗長なので削除する。
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->

- [x] #2 「保存する」は変更があるときだけ活性化し、押下で保存してモーダルが閉じる
- [x] #3 「ここに無い項目」区画・「変更を取り消す」ボタン・変更なしの説明文が消えている
- [x] #4 保存後、設定が効いた結果（テーマ・カード情報量など）が画面に現れるか、保存した旨の通知が出る

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 下部操作行 (AC #1・#2)

**モーダルの最下部に、本文のスクロール領域の外側で「変更せずに閉じる」「保存する」の 2 つだけを持つ
1 行を置いた。** 本稿ではこれを **下部操作行** と呼ぶ — 設定モーダルの本文スクロール領域の外側・最下部に
置かれ、モーダルを出る 2 つの押下だけを持つ 1 行を指す。ヘッダの「閉じる」は無くした。

固定は sticky ではなく**箱の高さを区切って作った**。`.settings` を縦の flex にして高さの上限を与え、
本文だけを `overflow-y: auto` の `.body` に入れ、下部操作行をその外に置いている。上限は
「窓の高さ − `Modal.svelte` がこの箱と窓端の間に置くもの」で、その 2 つ（backdrop の上下 padding と
dialog の枠）は `Modal.svelte` 側で custom property (`--modal-backdrop-inset`・`--modal-dialog-border`)
として宣言し、`.settings` がそれを読む。`4rem` を写すと、片方を変えたときにもう片方が黙ってずれる。

枠の 1px を `rem` で書いていないのは TASK-115 と同じ理由で、px の枠はルートフォントに比例しないため
`rem` では正しく表せない。`.settings` に `box-sizing: border-box` を与えているのは、この箱が `rem` で
高さを述べつつ padding を持つためである（全体リセットが無いので、無いと padding が上限の外へ足される）。

**「保存する」は変更があるときだけ活性で、押すと保存して閉じる。**保存が失敗したときは閉じず、失敗文を
下部操作行の中（押した場所の隣）に出す。失敗文をパネル上端に出していた従来の形は、スクロールしたフォーム
では押した瞬間に画面外にある。

**保存の発行中は、どちらの出口もモーダルを閉じない**（レビュー round 1 の [P2]）。閉じてしまうと、
発行済みの書込みは走り続けるので、「変更せずに閉じる」という名前の控えを押したのに下書きが保存される。
失敗した場合は、下書きを保持して失敗文を出すはずのパネルが既に無い。発行中かどうかはシェル側
（`App.svelte` の `settingsSaving`）が持つ — `Modal.svelte` の Escape はフォームではなくシェルへ届くので、
フォームだけが持つと 2 つの出口が別々の事実を見ることになる。フォームは同じ旗を prop で受け取って
自分の 2 つの控えを withhold する。**1 つの事実に 1 つの旗**である。

## 変更なしの理由をどう到達可能にしたか (AC #3)

AC #3 は「変更なしの説明文」を落とすが、doc-11 §5 は理由の無い無効化を禁じている。同節が挙げる 2 つ目の
形を採った — **「保存する」を `disabled` ではなく `aria-disabled` にしてフォーカスを受けたままにし、
理由の要素を `aria-describedby` で結び、その要素を視覚的にのみ隠す**。要素は常に DOM に置く（`display:
none` や取り外しはアクセシビリティツリーからも外れ、結ばれた先が無くなる）。

理由は**下部操作行に 1 本だけ**置き、両方の控えがそれを指す。保存の発行中は 2 つの控えが同じ 1 つの事情で
押せないので、同じ状況を 2 つの語で呼ばないためである（TASK-115 の教訓）。

**隠すのは「変更はありません」だけ**である。上書きを断る（`readOnly`）などの、利用者自身の操作では
解消しない理由は従来どおり可視の補助文として出す。実測でも `readOnly` では理由が 680×34px で描かれ、
下部操作行はその分高くなったまま固定位置を保っている。

## 保存した旨 (AC #4)

保存に成功したら上部帯 ⑤ 通知（doc-11 §4「済んだ操作の結果」）に「設定を保存しました。」を出す。
表示テーマのように閉じた瞬間に見える項目だけではなく、既定の保存区分・既定の詳細配置・外部エディタ指定の
ように次回起動や次の押下まで結果が出ない項目があるためである。モーダルは上部帯を覆う（`Modal.svelte`）
ので、この帯は閉じた後に読まれる — 「保存する」が閉じる形だから成り立っている。

## 実エンジンでの実測 (WebKit・Chromium、`_sandbox/settings-check/`)

本物の `Modal.svelte` ＋ `Settings.svelte` に記録済み wire fixture (`loaded_settings.json`) を載せて
測った。シェル (`App.svelte`) では測れない — Tauri IPC が無いと `settings_read` が失敗し、
`loaded` が null のまま「設定を読み込んでいます…」しか出ないためである。

| 窓 | dialog | .settings | 本文 (scroll/client) | backdrop (scroll/client) | 下部操作行 top→bottom |
|---|---|---|---|---|---|
| 1280×800 | 736px | 734px | 924 / 628 | 800 / 800 | 719.63 → 751 |
| 1024×600 | 536px | 534px | 924 / 428 | 600 / 600 | 519.63 → 551 |

- dialog は「窓 − 上下 32px」、`.settings` はそこから枠 2px を引いた値で、**計算式と実レイアウトは
  誤差 0**。両エンジン・両サイズで同値（Chromium の本文 scrollHeight だけ 932 で、これは本文の折返し差）。
- **本文を末尾までスクロールしても下部操作行の座標は 1px も動かない**（表の値は前後で同一）。backdrop は
  scrollHeight == clientHeight で、モーダル全体のスクロールはもう起きない。
- 2 つの控えは高さ 23.19px・上端も同じで、両エンジンで同値。「変更せずに閉じる」を `.mini`（0.7rem）に
  していた最初の形は 21.19px（WebKit）／21.98px（Chromium）で、隣と 2px 違い、しかもエンジンで違った。
  同じ行に並ぶ peer なので `.mini` を外した。
- `aria-disabled` は 変更なし で `true`、カード情報量を 1 つ変えると `false` になる。理由の要素は
  1×1px（視覚的に隠れている）で、テキストは入ったままである。
- **保存の発行中**（`?saving=1`）は 2 つの控えとも `aria-disabled="true"` で、両方が同じ 1 本の理由
  （「いま押せません: 保存中です」680×17px、可視）を `aria-describedby` で指す。両エンジンで同値。
- **フォーカスリングの余地**は、パネル左右 padding を子へ移した後で 12px（`select` の左端 300 と
  スクロールポートの左端 288 の差）。移す前は 0 だった。両エンジン・両テーマで同値。

**目視で 1 件出た（フォーカスリングの見切れ）。** 表示テーマの `select` のフォーカスリングの左端が
実機 WKWebView で切れていた。スクロール容器は描画を padding box で切り、フォーカスリングは控えの外側に
描かれるので、`.settings` がスクロールしていた間はその左右 padding（12px）がリングの余地だったのが、
padding を持たない `.body` へスクロールを移したことでクリップ端が控えの始まる位置へ来ていた。
左右 padding を `header`・`.body`・`footer` の 3 つの子へ移し（パネル側の宣言 1 つを 3 つが引く）、
**リングの太さを見積もるのではなく余地を元あった場所へ戻した**。画面は動かない（select の x は 300 のまま、
箱・本文・下部操作行の実測値も同じ）。**この切れは playwright の WebKit では再現しない** — padding を
全て外してもそちらではリングがスクロールポートの外へ描かれる。修正は 2 つのレイアウトの差から導き、
12px が戻ったことを実測で確かめたもので、再現からの確認ではない。

**目視は 2026-08-05 に完了し、リング修正も含めて指摘は無い**（3 点とも実機で確認: 下部操作行が
スクロールしても動かないこと、保存で閉じて上部帯に通知が出ること、場所を開く で Finder が
設定ファイルのフォルダを開くこと。フォーカスリングも全周出ている）。**残る未測定は 3 件** —
`atlas-light`・`atlas-dark` 以外の表示テーマ、非既定のルートフォントサイズ、1280×800 と 1024×600 以外の
窓の高さ。

**目視で 1 件だけ「気になる」が出て、別扱いにした**: 保存後の上部帯 ⑤ 通知の変化が分かりづらい。
帯の目立ち方は doc-11 §4 が 6 種すべてに共通で決めているので、⑤ だけを強めると描き分けが崩れる。
帯全体を見る TASK-79・80 で扱う（起票はしていない）、`atlas-dark` 以外の表示テーマ、非既定のルート
フォントサイズ、1280×800 と 1024×600 以外の窓の高さ。

## 画面横断契約として固定したもの

`App.component.test.ts` の「モーダルの 2 つの出口が同じ閉じる要求へ集まる」へ 1 件足した —
**保存の発行中は、「変更せずに閉じる」も Escape もモーダルを閉じない**。両経路が 1 つの旗に従うことは
シェルが配線しているので、呼び出し元を通してしか固定できない（AGENTS のテスト節が component test に
求める「画面横断契約」そのものである）。`fake-boundary.ts` に `settingsSaveHold` を足して書込みを
開いたまま保持する。シェルの `closeSettings` から `if (settingsSaving) return;` を外すと落ちることを
確認済み。

## doc・decision を改訂していない

**doc-11 に下部操作行の規則は書いていない。** いまこの形を持つのは設定モーダル 1 つで、3 つのモーダルに
共通する形になるのは「モーダルの閉じる操作を右上の × に統一する」TASK-76 である。× と下部の 2 つの関係を
決めるのはそちらの受入条件なので、そこが doc-11 に書く位置になる。doc-7 §2.1 の「設定」は設定モーダルが
**扱う項目**を列挙しており、控えの並べ方は述べていないので、こちらも改訂していない。
