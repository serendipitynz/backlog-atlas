## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
decision-12 は、色値一式を表示テーマ単位で一箇所に定義し、利用者がアプリ設定で 1 組を選べるようにすると決めた。現行 `src/app.scss` は族の色を `:root` に置き、地と文字は CSS システム色 `canvas`/`canvastext` を直接参照、罫線は `currentColor` の color-mix で導いており、色値の派生元が二箇所に分かれている。これを `[data-theme="…"]` のブロック群へ移し、システム色の直接参照を全コンポーネントから外す。

収録条件（4 族と --info の 5 つすべてで、印の文字と 12% 混色背景の比が 4.5:1 以上）は、設計案 05 が示した 10 組の色値のままでは満たせない。--bg に対して実計算すると 50 セル中 21 セルが 4.5:1 を下回り、最小は Solarized Light の照合不能で 3.28:1、既定の Atlas Light でも縮退が 3.91:1 である。族に割り当てた色相の役割（黄土・紫・灰青・赤・青）を保ったまま明度・彩度を調整して収録条件を満たす。満たせない組は収録しない。
<!-- SECTION:DESCRIPTION:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 実装範囲（AC #1–#5）

decision-12 の表示テーマ機構を実装し、10 組すべてを収録した。設計案 05 の色値のままでは収録条件（印の文字色と 12% 混色背景の比 4.5:1 以上）を満たさないため、族に割り当てた色相の役割（黄土・紫・灰青・赤・青）を保ったまま明度だけを動かして満たした。彩度は sRGB 色域から外れた分だけ縮んでいる。満たせず落とした組は無い。

## 主要ファイル

- `src/app.scss`（全面改稿）: `$themes` マップに 10 組の色値、`theme-vars` ミックスインが 1 組を custom property へ展開する。色値はこのファイルだけに在る（AC #1）。
  - 未選択（`theme = null`）は `:root` ＋ `@media (prefers-color-scheme: dark)` で Atlas Light / Atlas Dark に振り分ける。JS で解決せず CSS に任せたのは、セッション中の OS 明暗切替を購読なしで追えること、設定ファイル読み込み前の初回描画が既に正しい側になることの 2 点（AC #5）。
  - 明示選択は `:root[data-theme="…"]`。属性セレクタを `:root` 付きで書いているのは、上の 2 規則をソース順に依らず上回らせるため。収録していない名前はどのブロックにも当たらず、OS 追従の既定へ落ちる。
  - 各ブロックが `color-scheme: light|dark` を宣言する（AC #4）。
- `src/lib/theme.ts`（新規）: 収録テーマの名前・表示名・明暗と、`themeAttribute`（保存値 → `data-theme`。未選択と未収録は `null` = 属性を外す）。色値は持たない。
- `src/lib/theme.test.ts`（新規）: 収録条件の検算 15 件。`sass` で `app.scss` を実際にコンパイルし、`[data-theme]` ブロックから色値を取り出して 10 テーマ × 5 族 × 3 面（`--panel`・`--inset`・`--bg`）の 150 セルを計算する。値の写しではなくスタイルシート自身を読むので、テーマを足すとその場で検算対象になる（decision-12 の「検算を怠ると画面上は気付けない」への手当て）。TS 側の収録名と SCSS のブロック集合が一致することも突き合わせる。
- `src/App.svelte`: `settings.theme` を `<html data-theme>` へ反映する `$effect` を追加。`applySettings` ではなく effect に置いたのは、`<html>` がこのコンポーネントの markup の外にあり、かつテーマが変わる経路が 3 つ（起動時の読み取り・設定画面の保存・既定値への縮退）あるため。
- `src/components/Settings.svelte`・`src/lib/settings.ts`: 空だった `RECORDED_THEMES` を `theme.ts` の 10 組へ差し替え、「収録テーマがまだない」注記と「反映する画面はまだ」注記を外した。未収録の保存値は一覧に残し、その旨を添えて出す（黙って書き換えない）。
- 全コンポーネント（12 ファイル）: `canvas`・`canvastext`・`currentColor`・`highlight` 由来の色参照を撤去（AC #2）。罫線は 22% 以下を `--line`、25% 以上を `--line-strong`、面は `--bg`／`--panel`／`--inset`、選択アウトラインは `--sel`、チップの塗りは `color-mix(… var(--fg) N% …)` へ移した。

## 判断の記録

- **印チップ配色規則と priority の無彩 3 段をここで実装した**。当初は TASK-48（doc-11 への描き方統一）の範囲だが、AC #1 が「コンポーネントは変数名と color-mix のみを参照する」を求めており、印の白文字ベタ塗り（`color: #fff`）と priority の `#c0392b`／`#b8860b` を残すと色値がコンポーネントに残ってしまう。加えて AC #3 の検算対象は 12% 混色背景であり、印を塗り替えないと検算が画面と対応しない。TASK-48 に残るのは Type チップと通常ラベルの差の強化、無効化提示の統一（同タスク記述の (3)(4)）。
- **レーンヘッダ行の読取不能表示を面の淡色から左端 3px の縁へ変えた**（`Swimlane.svelte`、doc-11 §2.3 の問題の縁）。読取不能のルートは継続検出も止まっているため、読取不能の淡色面の上に継続検出停止の印が載る。この入れ子では印の 12% 混色背景が `--inset` 上のそれと別の色になり、ライト系 4 組で 4.0〜4.1 まで落ちていた（検算値は 4.6）。縁は同じことを伝え、印の下に回り込まない。
- **`--sel` は doc-12 §6.3 の関係を保った**。原文で `--info` と一致していた 7 組は調整後の `--info` に追従させ、意図的に違えていた 3 組（One Light・Solarized Light・Rosé Pine Dawn）はそのまま別の値にしてある。`--sel` は選択アウトラインで、印の収録条件の対象ではない。
