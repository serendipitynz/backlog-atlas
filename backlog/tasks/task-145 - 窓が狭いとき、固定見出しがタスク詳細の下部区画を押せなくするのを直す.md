## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-137 の実測（2026-08-11、借り物 playwright・WebKit）で見つけた。編集セッションを開いた状態でタスク詳細パネルを最下部までスクロールすると、**外部エディタで開く 区画の控えの中心で `elementFromPoint` が見出しの `dl` を返し、控えが押せない**。窓 560×420 で再現し、**700×420・900×520・1280×480・1280×600・1280×800 では 5 条件とも控え自身を返す（押せる）**ので、効いているのは高さではなく**幅**である。既定の窓は 1200×800（`tauri.conf.json`）で最小寸法の指定は無いため、この幅は到達しうる。

**TASK-137 が作った欠陥ではない** — 固定見出しは TASK-72、固定した発行の行は TASK-135 が入れたもので、TASK-137 が動かしたのは控えの語 1 文字ぶんである。狭い窓では併置のパネル幅が `min(30rem, 45vw)` で 252px まで縮み、**見出しが折り返して高さを食い尽くす**のが原因と見ているが、これは推測なので着手時に測って確かめる。

**公開阻害としてこちらが判断した** — 提供している控えが操作不能になる。用語節の定義により、発生条件の限定（狭い窓に限る）はこの判定に入れない。

**着手時に確かめること**: 覆っているのが見出しか発行の行か（両方とも固定されている）、押せなくなる幅の境目、同じことが他の最下部の区画（Git 履歴欄）でも起きるか、doc-8 §2.2 の見出しの固定と doc-11 §11 の発行の行の固定のどちらに上限を与えるべきか。

## 起票の記述と実測が 3 点違った

**測ったもの**: `_sandbox/app-check/`（本物の `App.svelte` ＋ 本物の `commands.ts` ＋ 偽 IPC）を WebKit・Chromium の両方で、窓 25 条件 × 閲覧／編集セッション。手順は `_sandbox/task-145/measure-band.mjs`・`measure-reach.mjs`・`measure-siblings.mjs`、値は同ディレクトリの `*.json`。

**1. 編集セッションは要らなかった。** 560×420 の閲覧でも同じ覆いが出る。**閲覧のほうが見出しは高い**（198.22px 対 166.67px、Chromium）— 閲覧の status 欄は札が折り返し、編集中は `<select>` が 1 行に収まるためである。

**2. 「操作不能」は 560×420 では起きていなかった。** 起票が観測したのは**最大スクロール位置で控えが覆われること**で、これは固定表示の帰結そのものであり **1280×800 でも起きている**（`全面表示で開く →` が見出しの下に入る）。**公開阻害に当たるのは到達不能** — 面をどのスクロール位置へ送っても控えの中心が最前面にならない状態 — のほうで、それが現に起きていたのは **560×300（帯 −7.29px／控え 26 件）と 360×420・320×420 の閲覧（帯 −20.91・−37.72px／控え 12 件）** である。2 つは別々に立つので対応表（`_sandbox/handoff/referent-table/referent-table-task-145.md` 第 1 版）で語を分けた。

**3. 「効いているのは高さではなく幅」も誤り。** 幅 560 のまま高さだけ 420 → 300 に下げると到達不能になる。効いているのは**見出しの高さ ÷ パネルの clientHeight** で、帯は 1280×800 の 82.28% から単調に落ちる（560×420 で 37.5%、560×300 で −3.7%）。起票の 6 標本は高さが 420〜800 の広い幅ばかりで、比が動く方向を 1 つしか見ていなかった。

## AC #2 覆っていた要素と境目

**覆っていたのは見出しで、発行の行ではない。** 100 条件のどれでも `.issue` は覆う側に出なかった（下端 38.4px のまま育たない）。`elementFromPoint` が返したのは `header.heading`・`dl.facts`・`dt`・`dd` で、いずれも見出しの中である。

**見出しの内訳**（WebKit・閲覧、1280 / 560 / 320px 窓）: 1 行目 22.72 / 50.38 / 77.56px、2 行目 23.19 / 23.19 / 40px、**属性表 55.78 / 94.58 / 162.58px**。**育つのは属性表と 1 行目で、2 行目はほぼ動かない。**

**境目は幅の 1 点では書けない。**帯が 0 を割るのは (a) 幅 560 のまま高さ 300（clientHeight 197px・閲覧で帯 −1.22px）と (b) 高さ 420 のまま幅 360（clientHeight 269px・閲覧で帯 −27.67px）。**閲覧のほうが先に割れる**（編集は `<select>` で属性表が縮むため）。**帯が正でも控えの高さ 22.45px に満たなければ到達不能は起きる** — WebKit 560×300 の閲覧は帯 2.28px で 5 件が到達不能だった。

## AC #3 上限は doc-11 が持つ

**doc-11 §13「固定行の高さの上限」を新設した。**争点として提示し、ユーザーが確定した（3 点とも推奨案）。doc-8 §2.2 でも doc-11 §11 でもなく doc-11 に新しい節を立てたのは、**覆う側が「見出し」と「発行の行」の 2 種に分かれていて、置き場を定める節が doc-8 §3 と doc-11 §11 に離れている**一方、覆う側としては 1 つの型だからである。**doc-11 §11 に置いても今回の欠陥には掛からない**（発行の行は 1 条件も覆っていない）。

**規則は「覆われない帯は、その面に立つ控えの高さ（doc-11 §2.2 の段階の最大値 1.75rem）を下回らない」。****割合で書かなかったのは、割合では守れない窓があるためである** — 560×300 の編集セッションで帯は面の 32.2% になるが、そこでも到達不能は 0 件である。「面の半分」のような規則にすると、規則の側が実装より先に破れる。

## 直したもの

**① 属性表を固定帯の外へ出した**（doc-8 §3 を 3 行の固定から 2 行の固定へ改訂）。**doc-8 §3 が固定の理由に挙げる 3 つ（ID コピー・前後移動・閉じる）はいずれも 1 行目の控えで、属性表にはその理由が及んでいない。**画面設計案 02 は 3 行を固定で描いているので意図的な逸脱にあたり、doc-12 §3 と逸脱表に記録した。

**② 見出し 1 行目の折り返しを、ID の下限（4rem）付きの折り返しへ改めた**（doc-8 §2.2 の「1 行に収める」を条件付きへ）。**着手して分かったのは、この行には floor があって「1 行に収める」が成り立たない幅があること** — 控えの群が 253.73px（WebKit）/ 257.14px（Chromium）を占めて縮まず、併置サイドバーは `min(30rem, 45vw)` なので窓 590px あたりで内容幅がその数を切る。`nowrap` で押し通すと **560px 窓で 12 / 16px の横あふれ**になるか、**600 / 620px 窓で横断タスクID の描画幅が 0** になる（どちらも実測）。後者は doc-8 §2.2 が ID に与えた役目を画面から消すので、下限を与えて折り返しを許す形をユーザーが選んだ。**1 行に収めることは目的ではなく帯を守る手段だった**ので、①で帯が守られた以上この行を押し通す理由は無い。

**③ 属性表の `select` に `min-width: 0` を与えた**（横あふれ）。**本タスクの変更前から在る欠陥で、私の変更が作ったものではない** — 変更前実測で編集セッション中に 700px 窓で 35px、560px で 66px、480px で 84px あふれていた。`minmax(0, 1fr)` はトラックを 0 まで許すが、その中の `select` が自分の `min-width: auto` を保っていた。移した当の要素なので同じ PR で閉じた。**あわせて、その場の註が書いていた「The whole table drops to one pair per line under a narrow box」が誤りであることも記録した**（4 トラックに折り返しの規則は無い）。

**④ doc-8 の参照ずれを 2 か所直した。** §2 の割当と §3 の区画見出しの項が、どちらも見出しの固定を「§2.2」に帰していたが、**§2.2 が定めるのは切替と既定で、固定を述べているのは §3 である**。

**⑤ `.title-line` の註の事実を直した。**「The row is one line in both states (目視 2026-08-04)」と書かれていたが、320px 窓では 40px（2 行）である。目視が広い窓で行われていた。
