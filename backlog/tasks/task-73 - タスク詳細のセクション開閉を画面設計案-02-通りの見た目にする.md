## 実装

- **常設と折畳みは別の要素になった** (`DetailSection.svelte`)。常設は `<section>` ＋ `<h3>` ＋ 区画境界、折畳みは `<details>`/`<summary>` ＋ 開閉印。同じ区画が配置によって両方になる (実装計画・実装ノート・References・状態遷移) ので、体裁は区画ではなく**その配置での割当**から決まる。
- **開閉印の割当を `placement.ts` の `DISCLOSURE_ICON` に置いた** (`open: chevron-down` / `closed: chevron-right`)。`PLACEMENT_ICON` と同じ置き方で、区画見出しと縮退表示の中の未知セクションが別々の chevron へ分かれるのを防ぐ。**指すのはいまの状態**で、原文の `▼`＝展開中の実装計画がそれを述べている (doc-7 §2.3 の行折畳みと同じ流儀、§2.2 の列折畳みとは逆)。
- **UA 既定マーカーは 2 通りに消す** — WebKit は `::-webkit-details-marker`、Chromium は `list-style: none` に答える。片方だけだと一方の webview で記号が 2 つ出る。
- **未知セクション (縮退表示の中) も同じ開閉印に揃えた**。区画ではないが、同じ面の中で UA 既定マーカーと開閉印が並ぶと同じ操作が 2 通りの記号になる。**向きは `[open]` から CSS で選ぶ** — 開閉を持つのは要素自身で、写した変数を別に置くと、この一覧の鍵が index なのでタスクを移った先の別のセクションへ前の開閉が付く。
- **`assignee` が通常ラベルの割当を借りていたのを、自分の行に直した** (`placement.ts`)。doc-8 §3 は TASK-72 で assignee の行を得ていたが、`DetailSection` にその鍵が無かった。3 配置とも値は同じなので画面は変わらないが、doc がどちらか一方を動かした日に借り手が黙って付いていく。
- 区画見出しのタイポを doc-12 §7.1 の転記 (`.68rem` / 650 / `letter-spacing .05em` / `--muted`) へ揃えた。実装は `.8rem` で太さ・字間・色の指定が無かった。

## 実測 (WebKit・Chromium、1280×800、`_sandbox/detail-check/`。箱幅は配置ごとの実幅 480 / 1114 / 1280px)

- **常設区画は 4 条件とも 印なし・罫線あり、折畳み区画は 印あり・罫線なし**。併置は折畳み 5 (実装計画・実装ノート・References・状態遷移・外部エディタ)、モーダルは 2、全面は 0 (全区画が常設) で、割当表のとおり。

## レビュー round 1 で直したこと (PR #56)

- **[P2] 折畳み側で `<h3>` を落としていた**。常設と折畳みを別要素にしたとき、折畳みの区画名を `<summary>` 直下の素のテキストにしてしまい、**同じ区画が配置によって見出し要素になったりならなかったり**する状態になっていた (実装計画は全面では `<h3>`、併置では見出しなし)。`<summary>` の内容モデルは見出し要素 1 個を許すので、区画名を両方の枝で `<h3>` にする snippet へまとめた。
- **その修正が新しい欠陥を作り、実測が拾った** — `<h3>` を戻したことで開閉印が `.section-title` の外へ出て、1em が `<summary>` の既定 (1rem = 16px) に解決され、区画名 10.88px の隣に **16px** の図形が並んでいた。doc-11 §2.4 の「大きさはアイコンを置く箱の font-size が決める」がそのまま効いた形で、箱が変わったのに寸法を見直していなかった。`<summary>` に `.68rem` を与えて直し、4 条件とも 10.88px に戻したことを実測で確認した。
- **[P3] doc-8 §3 の語が実装より広かった**。未知セクションについて「体裁は折畳みの区画に揃える」と書いたが、揃えたのは開閉印だけで字面は縮退表示側の `.72rem` のまま (自分の実測が 11.52px と 10.88px を別々に記録していた)。「開閉の記号だけを揃える」へ絞った。

## 目視 (2026-08-04、ユーザーが実機で 3 枚) — 1 件修正・2 件は仕様の確認

- **空の編集卓の枠を消した**。見出しと TYPE の間に、中身ゼロの `.console` が枠だけ描かれていた (実測: 要素の子 0 個・テキスト空・高さ 14.78px・`1px solid var(--line)`)。**TASK-72 が押しボタンを見出しへ移してから、この区画は文だけを持つようになり、何も述べない状態が通常になっていた** — 以前は必ず「編集」ボタンが入っていたので空にならなかった。`&:not(:has(*))` で要素の子が無いときだけ消す形にした (上の `{#if}` 群の条件を書き写すと二重に持つことになり、片方だけが動く)。WebKit・Chromium とも `display: none`・高さ 0 を実測。親は grid なので `gap` も消費しない。
- **全面シングルビューで折畳みが無いのは仕様** (doc-8 §2.1「全区画を常設で出す」・§3 の割当表の全面列)。TASK-73 は常設と折畳みの見た目を変えただけで、どの配置で何が折り畳まれるかは変えていない。
- **全面シングルビューが 1 列で幅いっぱいに伸びる件は、契約が覆っていない**。doc-8 §2.1 は全面を「スイムレーンを退け、全区画を常設で出す」としか書いておらず、列構成にも 1 行の長さにも触れていない。2 列は中央モーダルだけに定められている。**別タスクの対象** (TASK-80 か新規起票)。

- **編集中に Ace の内部レイヤが固定見出しの上へ抜けていたのを直した** (TASK-72 の欠陥。ユーザーが実機で発見)。Ace 自身の CSS は `.ace-host` を `position: relative` にするが z-index を与えないので**スタッキングコンテキストが立たず**、`.ace_gutter` (z-index 4) と `.ace_scrollbar` (同 6) が外の文脈へ抜けて `.heading` の z-index 1 を上回っていた。`.ace-host.promoted` に `isolation: isolate` を与えて内部を閉じ込めた。**見出しの数字を上げる形は採っていない** — Ace が内部で使う値に依存し、変わるたびに追いかけることになる。
