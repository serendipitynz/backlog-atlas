## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
2026-08-09 のユーザーフィードバック 3 件。どれも固定ヘッダのメニュー (`HeaderMenu.svelte`・`header.ts`) の中で閉じる。

① メニューの幅が `min(24rem, 90vw)` 固定で、行の文字数に対して右側が大きく空く (`menu1.png`)。24rem は TASK-67 が表を持っていた頃の幅で、表を `ShortcutHelp.svelte` へ移した後も残っている。
② 「行非表示をすべて戻す」は非表示の行が無いとき無効化され、doc-11 §5 の破線枠が出る。戻す行があるときは枠が消えるので、利用者にはメニューの区切り線が現れたり消えたりして見える (`menu2.png`)。ユーザーの指摘は「一貫性を保て」。無効化提示そのものは doc-11 §5 の契約なので、変えるのは枠の見え方ではなく、行の群を分ける印を無効化と無関係に持たせるかどうかである。
③ 「キーボード操作表示…」を「キーボード操作一覧」にする。`header.ts` の `SHORTCUT_HELP_LABEL` が `…` を付けた理由 (行が一覧そのものではなく一覧へ導くこと) をユーザーの語で上書きする。

## 着手して分かったこと

- **ユーザーが「消えた」と述べた区切り線は、実装に 1 本も無かった。** menu1.png で見えていたのは
  次行の無効化提示の破線枠の上辺で、実測でも保留時だけ `border-top: dashed`、非保留時は
  `transparent` である。**直す対象は枠ではなく、群を分ける印が無いことだった。**
- **AC #2 は現状のままで空虚に成立する。**「群を分ける印が現れたり消えたりしない」は、印が
  1 つも無い状態で無条件に真になる。**代わりに確かめた肯定形**は「区切り線が index 3 に
  現に 1 本あり、すべて戻す が保留のときも非保留のときも同じ index にある」で、
  `header.test.ts` の `区切り線 (doc-7 §2.1)` がそれを主張する。
- **区切り線の位置をデータにした。**`MenuGroup`（`layer` / `rows`）を各項目が持ち、
  `startsGroup()` が群だけを読む。CSS で「保留の行の上に線を引く」形にすると、無効化と
  独立であることが表現にならない（doc-11 §5 が新設した 保留判定と保留理由を別の欄に持つ と
  同型の理由）。群の軸は位置ではなく押した結果 — 被せ層を上げるか、グリッドが描く行を変えるか
  — なので、TASK-131 が `rows` 群を組み替えても境目の意味は動かない。
- **24rem はメニューの中身が減った後も残っていた値だった。** TASK-67 が割り当て一覧の表を
  モーダルへ出した時点で、幅を要求していたものが無くなっている。

## PR #85 1R で足したこと（レビュー: Claude Code CLI・押し返し 0 件）

指摘は [P1] 0 件・[P2] 1 件・[P3] 2 件で、**3 件とも doc-7 §2.1 の沈黙だった** — 実装の欠陥は
1 件も出ていない。反証を試みたがどれも成立したので全件直した。

- **[P2] 上限 24rem が doc に無かった。**§2.1 へ書いた「幅は内容から決める」は無条件で、しかも
  「固定値は要求元が消えても残る」と述べて 24rem を名指しで否定していた。その 24rem が
  `max-width` として生き残っており、書かれているのはこの Notes だけだった。**Notes は設計契約の
  置き場ではない**ので、次の差分洗い出しが「実装にあって doc に無い値」として拾ったとき、消すか
  残すかを書かれたものから決められない。§2.1 に上限・その値・その理由を書いた。
- **[P3] 幅が非表示行の状態で動くことに §2.1 が触れていなかった。**`right: 0` なので動くのは左辺で、
  長い行を隠すと次に開いたときラベルの左端がずれる。§2.1 は同じ引き金について**縦軸では**
  明示的に論じている（固定の項目を可変群の後ろに置かない）のに横軸に何も書いていなかった。
  承知のうえで採る旨を書いた。
- **[P3] 区切り線が支援技術に何も残していなかった。** 指摘は実装変更を求めず「§2.1 が決めろ」で、
  独断で `role="separator"` を足すのは「根拠なき独自例外」に当たるという判断も添えられていた。
  **目に対してだけ引く**と決め、根拠は doc-11 §2.4 が操作に属さないアイコンへ課している判定
  （図形が示すことは同じ区画の中の語も述べていなければならない）が満たされていること —
  群の別を述べているのは線ではなく各行の語である。**群を名前のある単位として持つかどうかは
  別の問い**で、そちらは開いたままにして §2.1 に置き場を書いた。

**1R で学んだこと**: 実測した値を Implementation Notes に書いたことで、**測ったのに契約にしていない**
状態を作っていた。「測っていないもの」は Notes でよいが、**測った結果として実装に残した値は契約側へ
書く**。数を Notes に置くと、次の読み手には「実装の事情」と「設計の決定」の区別が付かない。
