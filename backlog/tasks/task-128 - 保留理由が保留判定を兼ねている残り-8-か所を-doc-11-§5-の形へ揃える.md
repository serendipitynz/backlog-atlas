## 2026-08-19（AC #2 の判断）

**揃える。「試験で足りる」は採らない。** doc-11 §5 は条件を付けずに「理由文が非 null であることを保留判定そのものにしない」と定めており、試験で足りるとするのは、根拠を書かずに設計文書へ例外を足すことになる（AGENTS「更新」節と同じ姿勢）。**試験が押さえているのは「いまその関数が非 null を返すこと」であって、「保留判定をその値から導かないこと」ではない** — 実際、押さえていた 4 件のうち `overviewBlocked` は 3 つの呼び出し側すべてが `!== null` で分岐しており、理由文を `null` にすればその 3 つとも黙って押せるようになる。試験は変更後の値を見ているだけで、この形自体には掛かっていなかった。

## 2026-08-19（AC #3 の判断）

**`Modal.svelte` の `closeBlocked` prop は `closeAvailability: Availability` にする。** 起票時の「呼び出し側が渡す値の上流は tagged な `IssuePlan` なので別に判断する」は、実際の呼び出し 3 か所を読むと当たらなかった — `App.svelte` の 2 か所は `registerSubmitting ? registeringReason() : null`、`ProjectDetail.svelte` の 1 か所は `createOpen === null ? null : issuingReason` で、**どれも `IssuePlan` を経由していない。** prop が `string | null` である限り、× の無効化は渡された文字列の非 null がそのまま決めている。

## 2026-08-19（入れた形）

**`src/lib/availability.ts` の `Availability`** = `{ state: "ready" } | { state: "withheld"; reason: string }` の 1 つにまとめた。17 か所それぞれに同じ 2 変種を書き直すのは同じ宣言を 17 回書くことになる。**label や第 3 の状態を持つ既存の型はそのまま**（`IssuePlan`・`IssueAvailability`・`RedetectControl`・`OverviewSave`・`EditAvailability`）— それらが運ぶのは 2 欄だけではない。

**画面の出力は変えていない。** 描かれる文・`title`・`aria-describedby` の指す先・無効化の掛かる条件は、17 か所すべてで変更前と同じ組み合わせになるよう置き換えた。

## 2026-08-19（再発を止める機構）

**`src/lib/availability.test.ts`** が `src/components/*.svelte`・`src/App.svelte`・`src/lib/*.ts` を走査する。押さえるのは 2 つの字面だけである。

- `disabled=` / `aria-disabled=` / `draggable=` の束縛が、`…Blocked`・`…Held`・`…Hold`・`…Reason`・`…Withheld` という名前の値を `null` と比べて決めていないこと。
- オブジェクトの `enabled:` を理由の非 null から導いていないこと。

**名前を読むのは、正規表現が値の型を訊けないためである** — `disabled={crossId === null}` はコピーする id を比べており、`null` 比較を一律に弾くと許可一覧で答えることになる。**したがって規則そのものは押さえていない**（頭註に書いた）。**別の名前に隠れた保留理由は捕まらない**ので、走査が緑であることは doc-11 §5 が守られている証拠ではない。

**落ちることは確認済み** — `GitHistory.svelte` を `disabled={reloadBlocked !== null}` に、`external-editor.ts` を `enabled: blocked === null` に戻すと、それぞれ別の検査が 1 件ずつ落ちた（2 件失敗）。戻すと 63 件とも通る。
