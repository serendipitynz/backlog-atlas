## Description

画面設計案 02 の原文と実装で、タスク詳細の区画の並びが違う。原文は DESCRIPTION → ACCEPTANCE CRITERIA → 実装計画 → 実装ノート → 縮退 → TYPE → 通常ラベル → DEPENDENCIES → PULL REQUEST の順で、実装は TYPE・通常ラベル・assignee を先頭に置き、縮退表示を編集卓の直後（見出しの近く）に出している。あわせて全面シングルビューは 1 列で窓幅いっぱいに伸びるため、1280px 幅では Description の 1 行が 1189px を走る。

2026-08-04 に TASK-73 の目視でユーザーが両方を指摘した。決定先行タスクとして doc-8 §3 と §2.1 に書く。中央モーダルは 2 列なので、原文の 1 列の並びがそのままは効かず、主列・脇列それぞれの中の順を決めることになる。画面設計案 02 に全面の原文があれば doc-12 §3 へ転記して判断材料にする（TASK-72・73 と同じ手順）。
