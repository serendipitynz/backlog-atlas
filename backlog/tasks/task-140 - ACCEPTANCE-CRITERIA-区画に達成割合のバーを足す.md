## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-80 の洗い出しで確定した追随項目 (TASK-73 の目視が 2026-08-04 に見つけ、ここへ積んでいたもの)。画面設計案 02 は ACCEPTANCE CRITERIA 区画だけ、常設区画の罫線の位置に達成数 (`2 / 3`) と達成割合のバーを入れる (doc-12 §3、3 図とも)。実装は達成数だけを持ちバーが無い。

doc-8 §3 の割当表は AC の内容を「`#N` 項目と checked 状態、達成数」とし、バーに触れていないので、追随するには割当表の側も書き足す。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
**決定先行だった**（決 印は後付け）。追随そのものは TASK-80 が判定済みだが、**罫線の位置に入るということは、doc-8 §3 が常設区画へ与えている区画境界（細い罫線 1 本）に AC だけの例外が入る**ということで、そこは製品判断だった。**ユーザーへ出した争点は 4 点で、4 点とも推奨案で確定**した。

1. **バーが区画境界を兼ねる**（罫線を残して別の行に置く形は採らない）。太さが 1px から .25rem へ変わっても「区画名の右から幅いっぱいへ 1 本が伸びる」ことは変わらないので、doc-8 §3 の「印の有無と罫線の有無が同じ 1 つのことを 2 通りに述べる」はこの区画でも成り立つ。
2. **太さは .25rem**（doc-11 §2.2 の余白段階にある値。新しい値を足していない）。
3. **塗りは `--fg`**。同じ区画の完了印（`square-check`）が既に `currentColor` = `--fg` で描いており、完了を述べる色がこの区画で 1 つに保たれる。`--info` の用途は doc-11 §2.1 が「通知・確認・リンク風操作」と定めており達成割合はそのどれでもない（TASK-72 が `--info` を借りたのは「押した結果を一定時間だけ述べる表示」で、持続する状態ではない）。
4. **AC が 0 件のときはバーを出さず細い罫線に戻る**。全件数が 0 では達成割合が値を持たないためで、塗り 0 のバーを出すと `0 / 0` と `0 / 3` が同じ絵になる（doc-11 §6 が正常な不在について禁じている型）。**達成数 `0 / 0` と本文の「なし」は変えていない。**

**doc 改訂だけで足り decision は書いていない。** doc-8 §3（割当表の AC 行に「達成割合のバー」／区画見出しの体裁に 5 項）、doc-11 §2.1（`--fg` の用途）・§10、doc-12 §3（TASK-80 の判定行に追随済みを追記）。

**着手して分かったこと 2 件。**
- **達成数と達成割合は同じ `AcProgress` から出る別の値である。** 前者は 0 件でも値を持ち（`0 / 0`）、後者は持たない。AC #2 が問うているのは後者が無いときに何を描くかで、**この 2 つを分けないと 0 件と 0% が同じ帯になる**。純関数 `acRatio` が全件数 0 で `null` を返す形にして、その判断を 1 か所へ置いた。
- **達成数の文字列を `TaskDetail` が組んでいた**ので、バーを別 prop で渡すと刷る数と描く割合が食い違いうる状態になっていた。`count`（件数の文字列）とは別に `progress`（`AcProgress`）を取り、**達成数の文字列も `DetailSection` が同じ 1 つの値から組む**形にした。

**実測（`_sandbox/detail-check/` に `?ac=<checked>/<total>` のつまみを追加。WebKit・Chromium × atlas-light/atlas-dark × 3 配置 × 4 比率 = 48 条件）**

- **変更前**: AC 区画見出しの高さ 16.00px（Chromium 16.80px）、区画境界は 1px・`--line`、その実幅は併置 305.04 / モーダル 613.04 / 全面 781.04px。達成数 `2 / 3` は `.7rem`・`tabular-nums`・opacity .65 で幅 24.69px（4 比率とも同値）。
- **変更後**: **見出しの高さは 48 条件とも変わらず** 16.00px（Chromium 16.80px）。帯は **305.05 / 613.05 / 781.05px × 4px**（Chromium 304.98 / 612.98 / 780.98）で、**変更前の罫線と同じ幅・同じ位置**（帯の右端と見出しの右端の差は 0px）。角丸 0px。塗りは 2/3 → 203.36px（= 全長 × 2/3）、0/3 → 0px、3/3 → 全長と一致。
- **0 件（`0 / 0`）では 48 条件のうち該当 12 条件すべてで帯が消え、1px の罫線に戻る**（`ruled` が立ち `::after` の height が 1px）。
- **色**は 地 = `--line`（同じ画面の他の常設区画の罫線と同一値）、塗り = `--fg`。10 テーマ全部で計算したところ、`--fg` は面に対して 4.86〜12.65:1、地に対して 3.91〜9.79:1 で、非文字要素の下限 3:1 を掛けても全テーマが通る（`--muted` は 6 テーマ、`--line-strong` は 10 テーマとも割る）。**これは収録条件ではない** — `--fg` は族でも優先度色でもなく、塗りが面から分かれることはそのテーマで本文が読めることと同じ事実である。
- **読み上げ**: 区画見出しの `textContent` は 48 条件とも `Acceptance Criteria 2 / 3` の形で、帯は語を 1 つも足していない（`aria-hidden="true"`）。
- **4 倍解像度の画像**（両テーマ・両エンジン・4 比率）で、4px の帯が潰れず、`0 / 0` の 1px 罫線と `0 / 3` の空の帯が別物として読めることを確かめた。

**測っていないもの**: 実機 WKWebView、ハーネス以外の窓幅（`detail-check` は配置ごとの実幅 480 / 1114 / 1280px で測っている）、編集セッション中の見出し（帯は保存済みの値を描くので変わらない想定だが実測していない）、atlas 以外の 8 テーマでの見え方（色値は計算済み、画像は未取得）。

**Rust 側は触っていない**ので `cargo test` は回していない。`pnpm test` 808 件・`pnpm run check` 295 ファイル 0 エラー。
