## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
`src/lib/placement.ts` の `modalMainColumnRem()` は「脇列・列間・モーダルの左右パディングを引いた残り」として主列幅を返し、1280×800 で 47.75rem を出す。しかし実レイアウトの主列は 49.25rem（788px）で、差はちょうど `MODAL_PADDING_REM`（1.5rem）である。

原因は box-sizing。このリポジトリには box-sizing の全体リセットが無く（各コンポーネントが必要な箇所で個別に `border-box` を指定している）、`.detail[data-placement="modal"]` の `width: min(var(--modal-max-width), ...)` は content box の幅になる。つまりパディングは幅から引かれるのではなく外側へ足される。関数はそれを引いているので、主列を 1.5rem 過小に見積もっている。

いまのところ契約は破れていない。この関数が支えている主張は doc-8 §2.1 の「1280×800 でも 2 列を保つ（脇列 18rem は確保できる）」で、過小評価は安全側に外れるからである。ただし関数の doc コメントは「パディングを引いた残り」と事実でないことを述べており、TASK-113 が行長上限 48rem をこの関数から導いたことで、導出の根拠が 2 つの数字にまたがるようになった（doc-8 §2.1 にその旨を明記してある）。

直し方は 2 通りある。(1) 関数からパディングの減算を外して実レイアウトに合わせる。(2) `.detail` に `box-sizing: border-box` を与えて実レイアウトを関数に合わせる。(2) はモーダルの見た目を 24px 狭めるので、どちらを取るかは判断が要る。2026-08-04 に TASK-113 の実測で判明した。

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
## 寄せ先の判断 (AC #2)

**関数の側を実レイアウトへ寄せた**（Description の案 (1)）。`modalMainColumnRem()` から
`PANEL_PADDING_REM` の減算を外し、49.25rem＝788px を返すようにした。2026-08-05 にユーザーが
両案の実測を見て選択した。

案 (2)（`.detail[data-placement="modal"]` に `box-sizing: border-box` を与える）を採らなかった理由は
3 つで、いずれも実測に基づく。

1. **一致しきらない。** `border-box` には枠 1px×2 も入るので主列は 762px になり、`MODAL_PADDING_REM`
   だけを引く関数の 764px とは 2px 残る。合わせるには枠ぶんの定数が要るが、この関数は `rootFontPx` を
   引数に取る一方 CSS の 1px 枠は rem に比例しないので、rem では正しく書けない。案 (1) は 1280px でも
   1000px でも両エンジンで誤差 0 で、新しい定数を要しない。
2. **中央モーダルが 26px 狭まる。** 主列が 788 → 762px になり、上限 48rem（768px）が主列に届かなくなる
   ため、doc-8 §2.1 が「48rem は中央モーダルの主列に収まる幅」と述べる由来が成り立たなくなる。
   TASK-113 が実測した「中央モーダルでは 20px 削られる」も無効になる。
3. **画面のピクセルが動かない。** 案 (1) は表示を 1px も変えないので、TASK-113・114 の実測と目視が
   そのまま有効なままである。案 (2) は 3 配置の実測と目視をやり直す必要がある。

契約の側は案 (1) で破れない。doc-8 §2.1 が数で述べているのは「1280×800 でも 2 列を保つ（脇列 18rem は
確保できる）」だけで、モーダルの外形にも窓端との間隔にも触れていない。

## 併せて直したこと

**幾何の定数はすべて content box の寸法だと明記した。** 全体 `box-sizing` リセットが無いので、
コンポーネントが書く `width` は 2 列が分け合う箱そのもので、padding と枠はその外に置かれる。
`modalWidthRem` は `modalContentWidthRem` へ改名した（この名前で呼んでいた箇所は無い）。
`MODAL_INSET_REM`（4rem）も同様に「内容ボックスを決める前に窓幅から引く量」であって、目に見える
窓端との間隔ではない — 既定のルートフォントサイズでは 2.375rem（片側 19px。1000×800 で実測）。

**`MODAL_PADDING_REM` を `PANEL_PADDING_REM` へ改名し、同じ数の持ち直しを 3 箇所から 1 箇所にした。**
実測すると左右 padding は 3 配置とも 12px で、モーダル固有ではなく `.detail` のものだった。それを
`.detail` と `.heading` がリテラル `0.75rem` で持ち直し、さらに「モーダルだけ padding が違う」を理由に
した `.detail[data-placement="modal"] .heading` の上書きが同じ値を書き戻していた（空振り）。
上書きを削り、両者を `--panel-padding` から引くようにした。削除後の実測でも見出し band の左右の隙間は
3 配置とも 0〜1px＝枠の太さぶんで、パネル端まで届いている。

## 実測 (2026-08-05、WebKit・Chromium、`_sandbox/detail-check/?long=1`。両エンジン一致)

変更前後で数値は完全に同一。1 ピクセルも動いていない。

| 窓 | 配置 | 列 | 主列 / 脇列 | 内容ボックス / 外形 | 本文ブロック | 最長行 (WebKit / Chromium) |
|---|---|---|---|---|---|---|
| 1280×800 | 併置サイドバー | 1（契約どおり） | — | 480 / 505px | 480px | 466.1 / 463.1px |
| 1280×800 | 中央モーダル | **2** | **788 / 288px** | 1088 / 1114px | 768px | 746.6 / 749.9px |
| 1280×800 | 全面シングルビュー | **2** | **956 / 288px** | 1256 / 1280px | 768px | 746.6 / 749.9px |
| 1152×800 | 中央モーダル | **2** | 788 / 288px | 1088 / 1114px | 768px | 746.6 / 749.9px |
| 1000×800 | 中央モーダル | **2** | 636 / 288px | 936 / 962px | 636px | 606.7 / 616.7px |

`modalMainColumnRem()` の返り値と実レイアウトの主列（AC #1）:
1280px → 49.25rem = **788px**（実測 788）、1000px → 39.75rem = **636px**（実測 636）。
1152px は 68rem の上限が効くので 1280px と同じ 788px。**両エンジン・全幅で誤差 0。**

外形が内容ボックスより 26px 広いことも実測で確かめた（1088 → 1114px）。内訳は padding 24px と枠 2px で、
枠ぶんが定数に無いのが「内容ボックスを名前にする」理由である。
