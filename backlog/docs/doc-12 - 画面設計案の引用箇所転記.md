# 画面設計案の引用箇所転記

## 1. この文書の役割

**画面設計案** とは、Atlas の画面設計の入力としてリポジトリ外に作られた HTML プロトタイプ束を指す。Claude Design（claude.ai/design）のハンドオフ束として書き出されたもので、`01 スイムレーン全景`・`02 タスク詳細3配置`・`03 フィルタ帯`・`04 カードサイズ`・`05 配色と契約`・`06 デザインシステム`・`07 プロジェクト詳細` の 7 本と、テーマ変数を持つ `themes.css` からなる。**リポジトリの外にあるため、このリポジトリの読者は開けない。**

doc-7・doc-8・doc-10・doc-11 と decision-12・decision-13 は、この画面設計案を反映した結果であり、反映後の正本はそれらの文書である。本書はその手前を埋める。すなわち、**リポジトリ内の文書が画面設計案から引いている事実を、原文の値のまま写す**。読者が「設計案 05 が示した色値」「04 の割当表」を確かめたいとき、リポジトリの外へ出ずに本書で足りるようにするためである。番号だけの参照が本書のどの節に対応するかは §9 の表に載せる。

以下は 01 から 07 まで設計案の番号順に並べる。転記の粒度は「リポジトリ内の文書が引いている事実」であり、プロトタイプの HTML 実装そのものは写さない。

**2026-08-06 に §3（02 タスク詳細3配置）の「縮退表示」「印（縮退・版ずれ）」を「不整合区画」「印（不整合）」へ改称した**（TASK-77、decision-22）。ユーザーが同日「転記時の言い換えである」と回答したため、原文の語ではなく、§1 の「原文の値のまま写す」に反しない（TASK-70 の未分類列と同じ扱い）。

**改称は §3 に限る。** §5（04 カードサイズ）・§6（05 配色と契約）・§7（06 デザインシステム）に残る「縮退」「版ずれ」は改称していない — §6.3 の色値表は原文の変数名（`--mark-degraded`・`--mark-conflict`）を写しており、原文の語であることがそこから確かめられる。§5・§7 の語も同じ 3 本の設計案の側に属し、§3 の回答は及ばない。現行の語との対応は decision-22 が持つ（縮退・版ずれ → 不整合、`--mark-degraded` → `--mark-inconsistent`、`--mark-conflict` 相当は廃止）。

本書は転記であって決定ではない。値の是非や採否は、引用している側の文書（doc-7・doc-11・decision-12 など）が定める。両者が食い違う場合は引用している側が優先する。原文が「対応 CLI（v1.47.1）に無い」と述べる箇所の版番号も、原文のまま写している。各節には、原文で改訂対象として名指しされた契約も併記する。

### 2.3 プロジェクト登録モーダル（設定モーダルとは別）

見出しの補記は「台帳ファイルにエントリを 1 件足します。プロジェクトのファイルには触りません。」。

- **プロジェクトルート**（絶対パス・必須）。「参照…」ボタンを併置。
- **Backlog ルート**（省略時は下の既定）。既定は `<プロジェクトルート>/backlog` で、「`config.yml` と `tasks/` が読めることが条件です」。
- **slug**（省略時はディレクトリ名から導出し小文字化）。「英小文字・数字で始まり、以降は英小文字・数字・ハイフンのみ。登録後は変更できません。」
- 入力に問題があるときは読取不能族の色で検証エラー帯を出し、項目名と理由を並べる。CLI 縮退時は「台帳の書き込みは可能ですが、対応 CLI が無いためタスクの作成・更新はこの後も発行できません」の警告帯を出す。読み取り専用の台帳ファイル（`schema_version` がビルドより新しい）では登録自体を理由付きで拒否する。
- ボタンは「登録」「取消」。「登録するとスイムレーンの末尾にレーンが 1 本増えます。」

**見出しの補記の 2 文は、実装では別々の場所にあり、2 文目は 2026-08-10 に落ちた**（TASK-136）。1 文目（エントリを 1 件足すこと）はメニューの 登録 の行が持つ（doc-7 §2.1。「台帳へエントリを 1 件足します。グリッドの末尾に行が 1 本増えます。」）。2 文目（プロジェクトのファイルには触らないこと）は登録モーダルの冒頭に括弧書きで置かれていたが、doc-3 §2.1 の一文を指示対象のまま写したものだったので doc-11 §8 の 設計文の写し として落ちた。**したがって画面のどこにも 2 文目に当たる文は無い** — 意図的な逸脱であり、理由は doc-3 §2.1 が持つ。

### 2.4 固定ヘッダの総計と入口

固定ヘッダは、画面名「プロジェクト別スイムレーン」の横に `表示 {shown} / {total} 件 ・ {laneCount} レーン` を置く。**レーン側は表示中のレーン数という単一値で、全件との比を出していない。** 右端の入口は 3 つで、`＋ プロジェクトを登録`（文言つき・`⌘⇧N` を kbd で併記）・`⚙`（アイコンのみ・`⌘,`）・`☰`（アイコンのみ）。☰ の title は「メニュー — ヘッダのボタンはすべてここにもあります」。

算出（原文 509-515 行）では `shown` も `total` も**表示中レーンのみの合計**で、行非表示にしたレーンと読取不能レーンをどちらの数からも除外している。`laneCount` は読取不能レーンを数えない。

01 の帯（フィルタ帯）には総計を置かず、解除のキーボード説明を置く。03 との食い違いは §4.1 に併記し、裁定は doc-7 §5.2 が行う。

### 2.5 レーンと帯

継続検出が動いていない行には帯で「変更監視が動いていない行があります」と出し、レーンごとの「再読込」で読み直せるようにする。行・列の折畳みと読取不能行の扱いは §7 の 06 に部品として整理されている。**01 が折畳みの控えに刷っていた記号は本書に転記が無い** — 転記があるのは §7.2 の 06（`▾` / `▸` ＋ 可視の文言「畳む」）だけなので、01 の記号を引いている記述があればそれは転記に基づいていない（TASK-69 のレビューで判明。doc-7 §2.3・doc-11 §2.4 はこの不在を明記して 01 に帰属させていない）。

## 3. 02 タスク詳細3配置

- 詳細の配置は併置サイドバー・中央モーダル・全面シングルビューの 3 種。既定の配置ボタンに下線印を付け、選択はアプリ設定へ保存して再起動後も保つ。
- 前後移動は同一レーンセル内の ↑↓ で、3 配置共通で見出しに置く。未保存入力があれば破棄前確認を通す。
- 見出しは 3 行で、中身をスクロールしても画面から出ていかない（原文では本文が見出しの下に潜り込んでいる）。1 行目は左から 横断タスクID・ID コピー・印（不整合）、右端に 前後移動 ↑↓・位置「セル内 3 / 7」・3 配置の切替・閉じる ×。2 行目はタスクタイトル。3 行目は属性を 2 列に並べた表で、`status`（正準列を併記）と `priority`、`assignee` と `milestone`、`保存区分` と `日付`（created と updated を 1 セルに収める）の 3 段。**属性表にファイルパスは無い。** ID コピーの操作は原文では「ID をコピー」の文言ボタンである。
- 編集の入口は属性表の下の行にあり、「編集」ボタンと保存キーの注記（保存は保存ボタンか Cmd/Ctrl+Enter、素の Enter は改行）が並ぶ。この行も見出しと同じく固定されている。

## 7. 06 デザインシステム

原文の位置づけは「scoped SCSS へ写す際の変数と部品の一覧」。

### 7.1 デザイントークン

- **色** — テーマブロックが定義（§6）。`--bg` / `--panel` / `--inset` が地・カード面・くぼみ面、`--fg` / `--muted` / `--faint` が本文・副次・弱、`--line` / `--line-strong` が罫線 14% / 30%、4 族 + `--info` が一箇所定義（decision-6）、`--sel` が選択アウトライン。
- **タイポ** — `system-ui` のままで寸法のみ設計する。画面見出し .92rem / 650、タスク title（詳細）.95rem / 650 / lh 1.35、カード title .78rem / 400 / lh 1.35、本文・リスト .72–.74rem、副次（ID・件数・注記）.6–.68rem + `tabular-nums`、区画見出し .68rem / 650 / letter-spacing .05em / muted、コミット SHA 等は `ui-monospace`。
- **余白段階** — .16 / .25 / .3 / .45 / .6 / .75 / 1rem。
- **角丸** — チップ 3px / カード・ボタン 4px / 面 6px / ラベルピル 999px。
- **状態** — hover は枠線を `--line` → `--line-strong`、選択は `outline 2px --sel` + offset 1px、無効は破線枠 + opacity .45 + `cursor:help` + `title` で理由（契約 #9）。
- **問題の縁** — カード左 3px（縮退 / 版ずれ。両方なら版ずれ優先）、帯左 4px。

### 7.2 コンポーネント一覧

- **状態の印** — 5 族 + 中立 2 態（生 status、正常な不在の `—`）。文字 = `var(--mark-*)`、背景 12% と枠 45% は `color-mix` で導出し、コンポーネントは族名だけを選ぶ。
- **Type チップ / ラベルチップ / priority** — §5 の分離規則と同じ。
- **タスクカード** — 面 = `--panel`、hover で枠 `--line-strong`、選択 = `outline --sel`。問題の縁は左 3px。
- **列ヘッダ** — 折畳みは幅 2.2rem の縦帯。ヘッダは件数、各行のセルに縦書きの列名 + 行内件数。折畳みは全行同時（契約 #1）。**実装は帯の幅（5rem）とヘッダ・セルの中身の両方で意図的に外れている**（TASK-69。ヘッダは列名だけ、セルはカード 1 枚ぶんの四角と件数。理由は doc-7 §2.2）。
- **行ヘッダ** — 「畳む」（▾/▸、件数は読める）と「隠す」（帯へ退避、件数も読めない）を別の語・別の操作に分ける。読取不能行は理由（例 `root が存在しません（ENOENT）`）と「再読み込み」を出す。**実装は「畳む」の可視文言と文字グリフから意図的に外れている**（TASK-69。理由は doc-7 §2.3）。**「隠す」は行ヘッダに置いていない**（TASK-131。表示・非表示を固定ヘッダのメニュー 1 か所へ寄せた結果の意図的な逸脱で、理由は doc-7 §2.3。**2 つを別の語・別の操作に分ける**という原文の判断そのものは doc-7 §5.1 が持ち続けている）。
- **ボタン** — primary は fg/bg 反転の 1 種のみ（保存・編集）。無効は破線 + opacity .45 + `cursor:help` + `title` 必須（契約 #9）。二度押し確定の破壊的操作はラベルを差し替える（「実行してよいですか？」）。
- **帯** — 4 種を重要度の固定順で積む（§4.2）。
- **詳細の区画見出しとレーンセル空表示** — 折畳み可能な区画は `details`/`summary`。空セルの `—` には色も記号も与えず、読取不能とは決して同じ見た目にしない（契約 #2）。
- **フィルタ制御** — トークン / ドロップダウン / ポップオーバー。値一覧のポップオーバー（検索 + スクロール + 件数 + 選択数フッタ）は両案共通部品（§4）。

### 7.3 SCSS への写し方

`themes.css` の `[data-theme]` ブロックを `app.scss` へ移し、各コンポーネントの scoped SCSS は `var(--…)` と `color-mix` のみを参照する。ユーティリティクラスは導入しない。

## 8. 07 プロジェクト詳細

入口はスイムレーンのプロジェクト名クリック。見出しはパンくず「← スイムレーン / <プロジェクト名>」と slug、タスク・文書・マイルストーンの件数、「このプロジェクトのレーンへ」。

画面の左端は幅 12rem の区画ナビ（概要・文書・マイルストーン・新規タスクを切り替える。4 区画すべてが共有する）。区画ナビの外側は単一スクローラで、列ごとの overflow を持たない。

### 8.1 縮退帯 2 種

- **台帳は読み取り専用** — 台帳ファイルの `schema_version` がビルドの読める版より新しいため上書きを拒否した状態。Atlas を更新するまで台帳は編集できない（ルートの変更・別名表・登録解除が無効）。
- **CLI 縮退** — 対応 CLI を検出できないため、文書・マイルストーン・タスクの作成と更新を発行できない状態。台帳の操作は CLI を使わないため影響を受けない。

### 8.2 台帳エントリ区画

slug（変更できません、理由はホバー）、プロジェクトルート、Backlog ルート、Git リモート（「再検出する」と現在値）、status 別名表、更新操作、登録解除。

- プロジェクトルートを変更したときは Backlog ルートも一緒に送る。既定は `<新ルート>/backlog` だが、送るのは入力欄の値である。移動が成立するとそのプロジェクトの編集セッションは閉じられる。
- **status 別名表** — 「原文の status を正準 4 列のどれに置くか。空の表が既定です。」行ごとに原文 status → 正準列（未選択 / To Do / In Progress / In Review / Done）を選び、「行を外す」「＋ 別名を追加」を持つ。
- 操作は「台帳を更新」「読み込み直す」。
- **登録を解除する** — 台帳からエントリを削除しレーンを 1 本外す。プロジェクトのファイル（`backlog/` 以下のタスク・文書）は削除しない。台帳操作が書き込むのは台帳ファイルだけであり、再登録すれば同じ内容が戻る。確認のため slug の入力を求める。

### 8.3 文書区画

区画の中は 16rem の文書一覧と編集ペインの 2 カラムで、区画ナビの右に並ぶため画面全体では 3 カラムに見える。一覧は id・type・「未保存」・title・path。作成は title と type（既定に任せる / readme / guide / specification / other）。編集は title・type・tags・path・本文。

- 本文は保存すると全置換になる（部分更新の手段が CLI に無いため、欄の全文をそのまま送る）。
- `path` に値を入れるとファイルの移動要求になる。読み取り層が持つのは `source_path` で `-p` に渡す値ではないため、現在値は入れない。
- type を未設定に戻す操作はない（CLI に手段が無い）。
- **文書の削除は提供しない** — 対応 CLI の `doc` に delete/remove 相当のサブコマンドが無く、ファイルを Atlas が直接消すことは設計に含めていない（不要な文書は本文にその旨を書いて残す運用になる）。

### 8.4 マイルストーン区画

一覧は id・title・タスク数・説明。作成は名称（必須）と説明。**作成後の説明の編集は提供しない** — 対応 CLI の `milestone` に update/edit が無く、説明は `milestone add -d` で作成時にのみ設定できる（`rename` は名称だけを変え、説明は変えない）。CLI が提供するまで Atlas も提供しない。

### 8.5 提供しない操作区画

押せない操作を並べるのではなく、何が無いか・CLI のどの写像先に当たるか・理由を書く。

### 8.6 新規タスク作成

title（必須）、description、status（CLI の `default_status` に任せる / 正準 4 列）、priority、milestone、labels、受入条件。

- 列から作るとその列の値で status が確定する。スイムレーンの列下の「＋」は title と status だけの簡易版で、発行するのは同じ `task create` である。
- plan・notes・依存・参照は作成時に渡せない（`task create` に対応する引数が無く、作成後の編集操作になる）。
