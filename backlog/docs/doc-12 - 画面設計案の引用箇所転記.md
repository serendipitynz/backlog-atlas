# 画面設計案の引用箇所転記

## 1. この文書の役割

**画面設計案** とは、Atlas の画面設計の入力としてリポジトリ外に作られた HTML プロトタイプ束を指す。Claude Design（claude.ai/design）のハンドオフ束として書き出されたもので、`01 スイムレーン全景`・`02 タスク詳細3配置`・`03 フィルタ帯`・`04 カードサイズ`・`05 配色と契約`・`06 デザインシステム`・`07 プロジェクト詳細` の 7 本と、テーマ変数を持つ `themes.css` からなる。**リポジトリの外にあるため、このリポジトリの読者は開けない。**

doc-7・doc-8・doc-10・doc-11 と decision-12・decision-13 は、この画面設計案を反映した結果であり、反映後の正本はそれらの文書である。本書はその手前を埋める。すなわち、**リポジトリ内の文書が画面設計案から引いている事実を、原文の値のまま写す**。読者が「設計案 05 が示した色値」「04 の割当表」を確かめたいとき、リポジトリの外へ出ずに本書で足りるようにするためである。番号だけの参照が本書のどの節に対応するかは §9 の表に載せる。

以下は 01 から 07 まで設計案の番号順に並べる。転記の粒度は「リポジトリ内の文書が引いている事実」であり、プロトタイプの HTML 実装そのものは写さない。

本書は転記であって決定ではない。値の是非や採否は、引用している側の文書（doc-7・doc-11・decision-12 など）が定める。両者が食い違う場合は引用している側が優先する。原文が「対応 CLI（v1.47.1）に無い」と述べる箇所の版番号も、原文のまま写している。各節には、原文で改訂対象として名指しされた契約も併記する。

## 2. 01 スイムレーン全景

### 2.1 Tweaks の既定値

切り替え軸はテーマ・カードサイズ・最悪ケース帯。**カードサイズの既定値は L**（原文のラベルは「L（既定・ラベルと担当まで）」）。§5 の 04 割当表は M を既定としており、**画面設計案の内部で一致していない**。この不一致の裁定は doc-7 §3 が行う（doc-7 は M を採り、既定値の正本を doc-7 とする）。

### 2.2 設定モーダル

見出しの補記は「この画面ではなく、アプリ全体に効きます。」。区分と項目は次のとおり。

| 区分 | 項目 | 原文の値・注記 |
|---|---|---|
| 表示 | テーマ | 草案では Tweaks で切り替え |
| 表示 | カード情報量 | S・M は 04 で比較 |
| 表示 | 既定の保存区分 | `active + draft` |
| 読み取り | ファイル監視で外部変更を取り込む | チェックボックス、既定 on。「止まっているルートはレーンに『継続検出停止』が出ます」 |
| 読み取り | 起動時に全ルートを読み直す | チェックボックス、既定 off |
| 編集 | 外部エディタ | テキスト入力。原文の入力値は `code -w` |
| 台帳 | ファイル | 表示のみ（`~/.config/backlog-atlas/projects.toml`） |

ボタンは「閉じる」だけで、保存ボタンを持たない。末尾に「個々のプロジェクトのルート・status 別名表・削除は、プロジェクト詳細（プロジェクト名クリック）で扱います」と注記する。

### 2.3 プロジェクト登録モーダル（設定モーダルとは別）

見出しの補記は「台帳ファイルにエントリを 1 件足します。プロジェクトのファイルには触りません。」。

- **プロジェクトルート**（絶対パス・必須）。「参照…」ボタンを併置。
- **Backlog ルート**（省略時は下の既定）。既定は `<プロジェクトルート>/backlog` で、「`config.yml` と `tasks/` が読めることが条件です」。
- **slug**（省略時はディレクトリ名から導出し小文字化）。「英小文字・数字で始まり、以降は英小文字・数字・ハイフンのみ。登録後は変更できません。」
- 入力に問題があるときは読取不能族の色で検証エラー帯を出し、項目名と理由を並べる。CLI 縮退時は「台帳の書き込みは可能ですが、対応 CLI が無いためタスクの作成・更新はこの後も発行できません」の警告帯を出す。読み取り専用の台帳ファイル（`schema_version` がビルドより新しい）では登録自体を理由付きで拒否する。
- ボタンは「登録」「取消」。「登録するとスイムレーンの末尾にレーンが 1 本増えます。」

### 2.4 固定ヘッダの総計と入口

固定ヘッダは、画面名「プロジェクト別スイムレーン」の横に `表示 {shown} / {total} 件 ・ {laneCount} レーン` を置く。**レーン側は表示中のレーン数という単一値で、全件との比を出していない。** 右端の入口は 3 つで、`＋ プロジェクトを登録`（文言つき・`⌘⇧N` を kbd で併記）・`⚙`（アイコンのみ・`⌘,`）・`☰`（アイコンのみ）。☰ の title は「メニュー — ヘッダのボタンはすべてここにもあります」。

算出（原文 509-515 行）では `shown` も `total` も**表示中レーンのみの合計**で、行非表示にしたレーンと読取不能レーンをどちらの数からも除外している。`laneCount` は読取不能レーンを数えない。

01 の帯（フィルタ帯）には総計を置かず、解除のキーボード説明を置く。03 との食い違いは §4.1 に併記し、裁定は doc-7 §5.2 が行う。

### 2.5 レーンと帯

継続検出が動いていない行には帯で「変更監視が動いていない行があります」と出し、レーンごとの「再読込」で読み直せるようにする。行・列の折畳みと読取不能行の扱いは §7 の 06 に部品として整理されている。

## 3. 02 タスク詳細3配置

- 詳細の配置は併置サイドバー・中央モーダル・全面シングルビューの 3 種。既定の配置ボタンに下線印を付け、選択はアプリ設定へ保存して再起動後も保つ。
- 前後移動は同一レーンセル内の ↑↓ で、3 配置共通で見出しに置く。未保存入力があれば破棄前確認を通す。
- 外部エディタ区画の起動口は「$EDITOR で開く」と「OS の関連付けで開く」の 2 つ。References は最後の 1 件を削除できない旨を注記し、削除は外部エディタへ誘導する。
- 縮退表示は印がある時のみ 3 配置とも常設。状態遷移・外部エディタの区画は併置とモーダルで折畳み（既定閉）、全面で常設。
- 原文が改訂対象として挙げた契約: doc-8 §2 の「併置サイドバー」前提を「3 配置から選ぶ・既定を永続する」へ拡張する改訂。

## 4. 03 フィルタ帯

検討条件は「ラベル 20 種・assignee 6 名まで増えた最大時」。現行はファセット値を全展開するため約 5 行に伸び、グリッドの高さを直接奪う。

### 4.1 二案

- **案A トークン／チップ型（推奨）** — 高さは常に 1 行。選択中の条件だけがトークンとして見える。保存区分は既定（active）から始まる唯一の条件なので常設トークン。値の一覧は常時展開せず、ポップオーバーの中で検索して選ぶ。トークンが折り返しても実用上 2 行で頭打ち。キーボードは `F` 追加 / `⇧F` 直前の 1 つを解除 / `⌥⇧F` 全解除。
- **案B 固定属性ドロップダウン型** — 7 属性を固定の順で常設し、選択の有無に関わらず並びが変わらない。選択があるボタンは「ラベル 3」のように件数へ縮約する。

**判断は案A**。根拠は、選択中の条件が常に読めること（案B は選択がボタン内の縮約表示に隠れ、思い出すのに開く操作が要る）、トークンに順序があるため「1 つ戻す」が成立すること（ドロップダウン集合には解除順の概念がない）、ファセット値が増えても高さが折返し分で頭打ちになること。案B の利点は実装の小ささと並びの固定で、値一覧のポップオーバー（検索 + スクロール + 件数）は両案共通部品として使える。クエリ言語型は、1 人用ローカルアプリに学習コストが見合わないため不採用。

総計はどちらの案でも帯の右端に「表示 n / m 件」を常設し、行見出しの「n / m 件」は行の内訳として残す（両方出す）。**01 はこれと食い違い**、総計を画面名の横に置いて帯には解除のキーボード説明を置く（§2.4）。裁定は doc-7 §5.2 が行う（後発の全景案である 01 を採り、帯には総計を置かない）。

### 4.2 追加帯 4 種の最悪ケース

重要度の固定順で積む（出現順にしない）。

1. **確認**（利用者の回答待ち） — 閉じるボタンを持たない。左端 4px は `--info`。
2. **継続検出停止** — 閉じるボタンを持たない。左端 4px は `--mark-undetectable`。
3. **通知** — `×` で閉じられる。左端 4px は `--info`。
4. **非表示の行** — 中立（色を与えない。decision-6）。左端 4px は罫線色。

各帯 1 行固定。フィルタ帯 1 行 + 帯 4 本で、最悪でも約 8.5 行ぶんが上限になる（現行は上限なし）。①と②が閉じられないのは、無視できない情報であり回答・再読込で消えるべきものだからである。

原文が挙げた「触れる契約」は **なし**。

**キーの割り当ては原文と違う。** §4.1 の原文は `F` 追加 / `⇧F` 直前の 1 つを解除 / `⌥⇧F` 全解除 だが、実装は `F` 追加 / `Backspace` 直前の 1 つ で、**全解除にキーは無い**（割り当て一覧の正本は `shortcuts.ts`。doc-7 §2.1）。TASK-68 はこの差を持ち込んでも直してもおらず、レイアウトだけを扱った。差の当否は TASK-80（画面設計案と実装の差分の洗い出し）が判断する。全解除にキーが無いことは、帯に 全解除 のボタンが要る理由でもある。

原文は帯を「常に 1 行」と置くが、**その高さを保つには帯の中の控えが 1 つの高さに揃っている必要がある**。原文は寸法を控えごとに並べており、揃えるべきだとは書いていない。実装は帯が高さと行間を 1 つずつ（`--bar-control`・`--bar-gap`）持ち、トークン・テキスト入力・＋ 絞り込み・解除の 2 つがそれを取る形にした。折返し 2 行の頭打ちも同じ 2 値から計算する（枠を含む高さでないと、2 行ぶんが上限を 4px 超えて 2 行目が切れる）。**寸法に `rem` を書いた箱には `box-sizing: border-box` が要る** — このリポジトリに全体リセットは無いので、書いた値と描かれる幅・高さが枠と余白のぶんだけずれる（値一覧ポップオーバーの 15rem も、これが無いと 16.02rem で描かれる）。

## 5. 04 カードサイズ

YouTrack の S/M/L/XL/TV を 3 段階に絞った案。サイズはユーザー設定として永続（ボード単位ではなくアプリ単位。単一画面のため）。状態の印（縮退・版ずれ・保存区分・生 status）はどのサイズでも落とさない。

項目割当表（原文の見出しは「doc-7 §3 の改訂案」）。

| 項目 | S | M（既定） | L |
|---|---|---|---|
| 横断タスクID | ○ | ○ | ○ |
| priority | ○ | ○ | ○ |
| 状態の印（縮退・版ずれ・保存区分・生 status） | ○ | ○ | ○ |
| title | 1 行 | 2 行 | 3 行 |
| Type チップ | — | ○ | ○ |
| 通常ラベル | — | — | ○ |
| assignee | — | — | ○ |

- 現行の固定項目表は「M ≒ 現行 − ラベル・assignee」「L = 現行どおり」「S = 識別と印のみ」の 3 段へ置き換える。
- 通常ラベルを L 限定にする根拠は、数が可変で高さが読めない項目がカードの行数保証を壊すため。
- 状態の印を全サイズで保持する根拠は、落とすと「問題があるタスクが正常に見える」ため。生 status は未対応列でのみ付くため、S でも密度を崩さない。

Type チップと通常ラベルチップの視覚的分離は、角丸半径の差だけでは弱いとして、形・塗り・太さの 3 点を変える。Type は塗り + 太字 + 角丸 3px（未知 = 実線輪郭、未設定 = 破線・色なし）、通常ラベルは輪郭のみのピル（角丸 999px）+ 細字 + muted。priority は族の色を借りず、high = `--fg` 反転ベタ、medium = 実線輪郭、low = 細線輪郭 + muted。

## 6. 05 配色と契約

### 6.1 印チップの構造

現行は「族の色でベタ塗り + 白文字」で、`#b8860b` 上の白文字は約 2.8:1 しかない。設計案はこれをやめ、次の構造へ変える。

- 文字 = 族の色
- 背景 = 族の色 12% 混色（`color-mix(in srgb, <族の色> 12%, transparent)`）
- 枠 = 族の色 45% 混色

コントラストは「族の色 対 ページ背景（12% 混色後）」で決まる。ライト・ダークとも同じ規則で成立し、テーマは色値だけを差し替えればよい。

族の判別は色相と文言の二重化による。縮退 = 黄土 / 版ずれ = 紫 / 照合不能 = 灰青 / 読取不能 = 赤 / 通知 = 青。「正常な不在（—）」と「Type 未設定」には引き続き色を与えない（不透明度と破線枠のみ。decision-6 を維持）。

コントラスト比の計算規則は WCAG の相対輝度比で、12% 混色後の背景に対する実計算値。目標は 4.5:1 以上、下回るセルに `▲` を付ける。原文は表示時に計算しており固定値を持たないため、セルごとの比は本書には写さない。

### 6.4 テーマ切り替えの方式

- 現行の `:root { --mark-* }` 一箇所定義を、`[data-theme="…"] { --bg / --fg / --line / --mark-* / --info }` のテーマブロック群へ拡張する。コンポーネントは従来どおり変数名だけを参照し、色を選ばない（decision-6 の構造は不変）。
- 各テーマブロックが `color-scheme: light` / `dark` を宣言し、フォームコントロールとスクロールバーの明暗も追従させる。`canvas` / `canvastext` の直接参照は `--bg` / `--fg` 経由へ置き換える。
- 収録テーマは §6.2 の 10 組。切り替えは設定で永続し、既定は OS の明暗に追従して Atlas Light / Atlas Dark を選ぶ。
- priority の現行色（high = `#c0392b`・medium = `#b8860b`）は読取不能・縮退と同色で族を汚染するため、無彩の濃淡 3 段へ置き換える。

- doc-8 §2 — 「併置サイドバー」前提を「3 配置から選び、既定を永続する」へ改訂。
- 依頼書 §1 配色基盤 — `canvas` / `canvastext` 派生から「テーマ変数一式の一箇所定義」へ改訂。

## 7. 06 デザインシステム

原文の位置づけは「scoped SCSS へ写す際の変数と部品の一覧」。

### 7.1 デザイントークン

- **色** — テーマブロックが定義（§6）。`--bg` / `--panel` / `--inset` が地・カード面・くぼみ面、`--fg` / `--muted` / `--faint` が本文・副次・弱、`--line` / `--line-strong` が罫線 14% / 30%、4 族 + `--info` が一箇所定義（decision-6）、`--sel` が選択アウトライン。
- **タイポ** — `system-ui` のままで寸法のみ設計する。画面見出し .92rem / 650、タスク title（詳細）.95rem / 650 / lh 1.35、カード title .78rem / 400 / lh 1.35、本文・リスト .72–.74rem、副次（ID・件数・注記）.6–.68rem + `tabular-nums`、区画見出し .68rem / 650 / letter-spacing .05em / muted、コミット SHA 等は `ui-monospace`。
- **余白段階** — .16 / .25 / .3 / .45 / .6 / .75 / 1rem。
- **角丸** — チップ 3px / カード・ボタン 4px / 面 6px / ラベルピル 999px。
- **状態** — hover は枠線を `--line` → `--line-strong`、選択は `outline 2px --sel` + offset 1px、無効は破線枠 + opacity .45 + `cursor:help` + `title` で理由（契約 #9）。
- **問題の縁** — カード左 3px（縮退 / 版ずれ。両方なら版ずれ優先）、帯左 4px。

### 7.2 コンポーネント一覧

- **状態の印** — 5 族 + 中立 2 態（生 status、正常な不在の `—`）。文字 = `var(--mark-*)`、背景 12% と枠 45% は `color-mix` で導出し、コンポーネントは族名だけを選ぶ。
- **Type チップ / ラベルチップ / priority** — §5 の分離規則と同じ。
- **タスクカード** — 面 = `--panel`、hover で枠 `--line-strong`、選択 = `outline --sel`。問題の縁は左 3px。
- **列ヘッダ** — 折畳みは幅 2.2rem の縦帯。ヘッダは件数、各行のセルに縦書きの列名 + 行内件数。折畳みは全行同時（契約 #1）。
- **行ヘッダ** — 「畳む」（▾/▸、件数は読める）と「隠す」（帯へ退避、件数も読めない）を別の語・別の操作に分ける。読取不能行は理由（例 `root が存在しません（ENOENT）`）と「再読み込み」を出す。
- **ボタン** — primary は fg/bg 反転の 1 種のみ（保存・編集）。無効は破線 + opacity .45 + `cursor:help` + `title` 必須（契約 #9）。二度押し確定の破壊的操作はラベルを差し替える（「実行してよいですか？」）。
- **帯** — 4 種を重要度の固定順で積む（§4.2）。
- **詳細の区画見出しとレーンセル空表示** — 折畳み可能な区画は `details`/`summary`。空セルの `—` には色も記号も与えず、読取不能とは決して同じ見た目にしない（契約 #2）。
- **フィルタ制御** — トークン / ドロップダウン / ポップオーバー。値一覧のポップオーバー（検索 + スクロール + 件数 + 選択数フッタ）は両案共通部品（§4）。

### 7.3 SCSS への写し方

`themes.css` の `[data-theme]` ブロックを `app.scss` へ移し、各コンポーネントの scoped SCSS は `var(--…)` と `color-mix` のみを参照する。ユーティリティクラスは導入しない。

## 8. 07 プロジェクト詳細

入口はスイムレーンのプロジェクト名クリック。見出しはパンくず「← スイムレーン / <プロジェクト名>」と slug、タスク・文書・マイルストーンの件数、「このプロジェクトのレーンへ」。

### 8.1 縮退帯 2 種

- **台帳は読み取り専用** — 台帳ファイルの `schema_version` がビルドの読める版より新しいため上書きを拒否した状態。Atlas を更新するまで台帳は編集できない（ルートの変更・別名表・登録解除が無効）。
- **CLI 縮退** — 対応 CLI を検出できないため、文書・マイルストーン・タスクの作成と更新を発行できない状態。台帳の操作は CLI を使わないため影響を受けない。

### 8.2 台帳エントリ区画

slug（変更できません、理由はホバー）、プロジェクトルート、Backlog ルート、Git リモート（「再検出する」と現在値）、status 別名表、更新操作、登録解除。

- プロジェクトルートを変更したときは Backlog ルートも一緒に送る。既定は `<新ルート>/backlog` だが、送るのは入力欄の値である。移動が成立するとそのプロジェクトの編集セッションは閉じられる。
- **status 別名表** — 「原文の status を正準 4 列のどれに置くか。空の表が既定です。」行ごとに原文 status → 正準列（未選択 / To Do / In Progress / In Review / Done）を選び、「行を外す」「＋ 別名を追加」を持つ。
- 操作は「台帳を更新」「読み込み直す」。
- **登録を解除する** — 台帳からエントリを削除しレーンを 1 本外す。プロジェクトのファイル（`backlog/` 以下のタスク・文書）は削除しない。台帳操作が書き込むのは台帳ファイルだけであり、再登録すれば同じ内容が戻る。確認のため slug の入力を求める。

### 8.3 文書区画

一覧は id・type・「未保存」・title・path。作成は title と type（既定に任せる / readme / guide / specification / other）。編集は title・type・tags・path・本文。

- 本文は保存すると全置換になる（部分更新の手段が CLI に無いため、欄の全文をそのまま送る）。
- `path` に値を入れるとファイルの移動要求になる。読み取り層が持つのは `source_path` で `-p` に渡す値ではないため、現在値は入れない。
- type を未設定に戻す操作はない（CLI に手段が無い）。
- **文書の削除は提供しない** — 対応 CLI の `doc` に delete/remove 相当のサブコマンドが無く、ファイルを Atlas が直接消すことは設計に含めていない（不要な文書は本文にその旨を書いて残す運用になる）。

### 8.4 マイルストーン区画

一覧は id・title・タスク数・説明。作成は名称（必須）と説明。**作成後の説明の編集は提供しない** — 対応 CLI の `milestone` に update/edit が無く、説明は `milestone add -d` で作成時にのみ設定できる（`rename` は名称だけを変え、説明は変えない）。CLI が提供するまで Atlas も提供しない。

### 8.5 提供しない操作区画

押せない操作を並べるのではなく、何が無いか・CLI のどの写像先に当たるか・理由を書く。

### 8.6 新規タスク作成

title（必須）、description、status（CLI の `default_status` に任せる / 正準 4 列）、priority、milestone、labels、受入条件。

- 列から作るとその列の値で status が確定する。スイムレーンの列下の「＋」は title と status だけの簡易版で、発行するのは同じ `task create` である。
- plan・notes・依存・参照は作成時に渡せない（`task create` に対応する引数が無く、作成後の編集操作になる）。
