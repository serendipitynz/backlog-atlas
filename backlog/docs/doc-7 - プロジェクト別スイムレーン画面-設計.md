# プロジェクト別スイムレーン画面 設計

TASK-11 の設計。用語は [doc-1](doc-1)・[doc-2](doc-2) に従い、本書で導入する語は初出に定義を置く。
前提は doc-3（台帳・横断タスクID）・doc-4（読み取り層・ドメインモデル）・decision-4（status はプロジェクト個別許容、正準ステータス列へ列対応規則で対応、未対応 status は未対応区画）・decision-5（kind 接頭辞除去で Type 導出、複数併記・未設定・未知）。

## 1. 用語

- **プロジェクト別スイムレーン** … `project` を行、status を列に、複数プロジェクトのタスクを同時表示する画面（doc-1）。
- **プロジェクト行** … スイムレーンで 1 台帳エントリに対応する横 1 行。その行のタスクは全て同一プロジェクト。
- **レーンセル** … プロジェクト行と正準ステータス列の交点で、該当タスク群を収める区画。
- **タスクカード** … レーンセル内で 1 タスクを表し、横断タスクID・Type・通常ラベル・priority 等を載せる表示単位。
- **active タスク** … タスク保存区分（doc-4 の 3.4）が active（走査元 tasks/）のタスク。スイムレーンの既定表示対象。draft・completed・archive のタスクは既定では出さない。

## 2. 全体構成（行=プロジェクト、列=status、セル=タスクカード）

- **既定表示は active タスクに限定**: プロジェクト行・レーンセルに既定で並べるのは、タスク保存区分（doc-4 の 3.4）が active のタスクだけとする。draft・completed・archive のタスクは走査され読み取り層のドメインモデルには在るが、既定のスイムレーンには出さない。完了整理済み・アーカイブ・下書きが通常の進捗カードへ混入するのを防ぐためである。これらを見たいときはフィルタで明示的に加える（5 章）。
- **列（正準ステータス列）**: 画面上部に To Do / In Progress / In Review / Done の 4 列を固定配置する（decision-4）。列はプロジェクト横断で共通・固定で、プロジェクト行が変わっても列位置は動かない。これによりプロジェクトをまたいだ同一 status の縦読み（優先順位判断、doc-1）が成立する。
- **行（プロジェクト行）**: 台帳エントリ（doc-3）ごとに横 1 行を置く。行の並び順は台帳の並び（doc-3 の表示既定順）を既定とし、画面で変更できる（5 章）。
- **セル（レーンセル）**: プロジェクト行 × 正準ステータス列の交点に、当該プロジェクトで当該列へ対応づいたタスクのタスクカードを縦に並べる。空セルは空のまま示す（該当タスク無しと、読取不能の区別は 6 章）。
- **未対応区画**: 列対応規則でどの正準ステータス列にも対応づかなかったタスク（未対応 status、decision-4）は、正準 4 列へ紛れ込ませず、当該プロジェクト行内に設けた未対応区画へ集める。区画には元の status 文字列をそのまま示す。

```
                To Do        In Progress    In Review     Done      | (未対応)
 geomyth      [card][card]   [card]         —            [card]     |  [card: status=Blocked]
 backlog-atlas[card]         [card][card]   [card]       [card]     |  —
```

## 3. タスクカードに表示する項目

タスクカードは、一覧上で識別・優先順位判断に要る最小限を載せる。ドメインモデル（doc-4）のタスクから写す。

| 項目 | 由来 | 表示 |
|---|---|---|
| 横断タスクID | slug（台帳）＋ TASK-ID（frontmatter id） | `<slug>:<TASK-ID>`。横断画面のため常に slug 前置（doc-3 の 5.3）。 |
| title | frontmatter title | カードの主見出し。 |
| Type | kind ラベル由来（decision-5） | 0 個以上の Type 値を併記。未設定は「Type 未設定」を明示、未知 Type は中立表示に印。通常ラベルと混ぜない。 |
| 通常ラベル | labels の非 kind 要素（doc-4） | Type と分けて示す。kind ラベルを混ぜない。 |
| priority | frontmatter priority | high/medium/low を視覚差で示す。並び順の鍵（5 章）。 |
| assignee | frontmatter assignee | 任意。空なら省略。 |
| health（縮退印） | doc-4 の health | 縮退（解析不能・想定外スキーマ・参照欠損）を検知したタスクはカードに縮退印を付け、判別できた項目だけを載せる（doc-4）。 |
| 保存区分印 | doc-4 の storageState | 既定表示は active のみで印は付けない。フィルタで draft / completed / archive を加えたときだけ、active と区別する保存区分印を付ける（5 章）。 |

- 依存・AC 進捗などの詳細はカードに載せず、タスク詳細画面（doc-8）へ委ねる。カードは一覧の密度を保つ。
- カードを選ぶとタスク詳細画面（doc-8）を開く。

## 4. プロジェクト／status のマッピング方針

- **status → 列**: 各タスクの status を、そのプロジェクトの列対応規則（decision-4）で正準ステータス列へ対応づけ、対応先セルへ置く。どの列にも対応づかない status は未対応区画へ置く。config.yml 未定義の想定外 status（doc-4 の想定外スキーマ）は未対応区画に置きつつ強い縮退印を付ける（decision-4）。
- **タスク → プロジェクト行**: タスクの所属プロジェクトは、読み込んだ Backlog ルートに対応する台帳エントリで決まる（doc-3 の決定規則）。タスクへ `project:` ラベルを付けない。
- **列対応規則の別名**: 別名表（decision-4、台帳エントリの任意属性）が設定されていれば適用する。既定は名称一致（大文字小文字・前後空白を無視）。

## 5. フィルタと並び順

- **プロジェクト行の並び**: 既定は台帳の並び順。画面で行の表示順を変更でき、行の表示/非表示（特定プロジェクトを一時的に隠す）も持つ。並びの変更は台帳の表示順（doc-3 の更新で許す並び順）へ反映してよい。
- **セル内タスクの並び**: 既定は priority 降順、同 priority 内は ordinal（frontmatter）昇順、次いで updated_date の新しい順。安定した並びで、更新のたびにカード位置が飛ばないようにする。
- **フィルタ**: 次を単独・組合せで適用する。フィルタはカードの取捨のみを行い、行・列の骨格（プロジェクト行と正準ステータス列）は保つ。
  - Type（decision-5 の Type 値。複数 Type のタスクはいずれか一致で残す。未設定・未知も選べる）。
  - 通常ラベル。
  - priority。
  - assignee。
  - テキスト（横断タスクID・title 部分一致）。
  - 縮退（health が縮退のタスクだけを抽出し、問題を洗い出す）。
  - タスク保存区分（doc-4 の 3.4）。既定は active のみ。フィルタで draft / completed / archive を明示的に加えられる。加えた区分のタスクは対応する status 列（対応不能なら未対応区画）へ並べ、active と区別する保存区分印（3 章）をカードに付ける。
- **未対応区画とフィルタ**: フィルタは未対応区画にも同じく効く。未対応区画は常設ではなく、そのプロジェクト行に未対応 status のタスクがある場合にだけ現れる。

## 6. 読取不能・不在時の表示

- **ルート読取不能**: 台帳エントリの Backlog ルートが読めない（doc-4 のルート読取不能）場合、そのプロジェクト行を消さず、行全体を読取不能として示す（セルにタスクを出さず理由を示す）。他プロジェクト行の表示には影響させない。具体の見せ方は TASK-13。
- **空セルと不在**: タスクが 0 件のセルは空で示す。「該当タスクが無い」ことと「ルートが読めない」ことは区別する（前者は空セル、後者は行単位の読取不能表示）。
- **縮退タスク**: 縮退（doc-4）タスクは破棄せず、判別できた status で対応列（不能なら未対応区画）に置き、カードに縮退印を付ける。

## 7. 後続への影響

- 対象 repo・Backlog ルート・コミット不在時の表示（読取不能行・空セルの具体な見せ方）は TASK-13。本章はどこに何を出すかの骨格を与える。
- タスクカードから開くタスク詳細画面は TASK-12（doc-8）。カードは詳細への入口に徹し、詳細項目を持たない。
- 同一ルート更新時の再読込（TASK-14）で、カードの並びを安定に保つ（5 章の安定並び）。
