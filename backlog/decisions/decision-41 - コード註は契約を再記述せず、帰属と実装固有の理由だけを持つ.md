## Context

実装全体評価書 (2026-08-01) の可読性節は、同じ契約が設計文書・Rust・TypeScript・Svelte の複数箇所へ
複製されていることを挙げ、**コメントが正しければ意図の復元に有効だが、変更時に同時更新されないと
実装より強く誤った前提を伝える**と述べた。実例が 1 件記録されている — `Modal.svelte` の頭註は
「モーダル経路で未保存入力を失わない」と説明していたが、設定と登録のモーダルを閉じると子フォームが
アンマウントされていた (TASK-86 で直した)。

この判断が要るのは、**畳む対象を決める軸がどこにも無いから**である。画面に出る散文については
doc-11 §8 が 落とす 4 種 と 残す 3 種 を定めているが、あの節は「対象は利用者が読む文だけであり、
コードコメントは含まない」と自分で書いて本タスクへ送っている。AGENTS の Coding style は
「何を書くか」の 4 項を持つが、**既にあるコメントを畳んでよいかについては逆を書いている** —
「これらを満たすためだけに既存のコメントや触っていないコードを消したり書き換えたりせず、
代わりに提起する」。本 decision がその提起の答えである。

### 実測 (2026-08-23、HEAD `64b9e59`)

対象は `src/` の `.ts`・`.svelte`、`src-tauri/src/`、`scripts/`。テストファイルを除く。

- **註は 16,747 行 / 4,631 塊。** 同じ集合の源泉が 36,886 行なので **45%** が註である。
- **doc・decision を名乗る註は 3,800 行 / 2,631 塊 / 120 ファイル。** TASK-79 が 2026-08-07 に
  「コードコメントの設計文書参照 934 行・触っていない」と記録した集合が、4 倍になっている。
- **逐語の写しは 0 件。** doc 13 本・decision 40 本・AGENTS 和英を 1 本の接尾辞オートマトンに載せ、
  4,631 塊それぞれとの最長共通部分列を取った (空白を 1 文字へ畳んでから比較したので、註側の
  折り返しでは切れない)。最長一致は 276 字だが実体は `generate-third-party-licenses.mjs` が引く
  シェルコマンドで、**doc・decision の散文との最長は 58 字**である。
- **引用は 3 種とも解決する。** 註が引く `doc-N §X` は全件が実在する節を指し、`decision-N` の
  未解決は 0 件、註が backtick で名乗る識別子とファイルパスの未解決も 0 件。走査に偽の節番号を
  植えると落ちることを確かめた。
- **頭註は 121 塊 2,392 行**で、うち 32 が 対応表 を持つ (1,152 行。表本体 387 行、うち 164 行が
  doc・decision を引く)。

**したがって、本タスクの受入条件 #1 が字面で名指すもの (「doc の節の全文をそのまま写したコメント」) は
着手前から 0 件である。** 現に在るのは言語をまたいだ再記述で、そちらは逐語一致を 1 文字も作らない。
表題と Description が言う「再記述」を対象に据える。

## Decision

**コード註が持ってよいのは 帰属 と 実装固有の理由 の 2 つで、契約の再記述 は持たない。**

### 見分け

**この文は、この実装が別の形になっても真のままか。** 真のままなら述べているのは契約であって実装では
ないので落とす。実装を変えた瞬間に偽になるなら残す。**述語では分けられない** — 契約の再記述も
「なぜ」の形で書かれるので、why かどうかで判定すると両方が残る。

### 落とす種 — 契約の再記述

**doc・decision が決めていることを、コードの側で述べ直した文。** 要約して残す形も含む。要約した契約は
正本より粗く、**正本が動いても誰も食い違いに気づけない**。節番号だけを落として散文を残す形も含む —
残るのは出どころを失った契約の写しである。

### 残す種 — 帰属

**契約の在処を指す `doc-N §X`・`decision-N`。1 つの主張につき 1 つ置く。** doc-11 §8 は画面の側で
設計文書参照を「1 つも残さない」と定めているが、**その規則をコードへ持ち込まない** — あの禁止の
根拠は「利用者はその文書を読めない」ことであり、コードの読み手は読める。

### 残す種 — 実装固有の理由

**なぜこの境界・順序・縮退を選ぶか、退けた明白な代案とその理由、外から与えられていて実装からは
読めない制約。** 実装が別の形になれば偽になる文である。

### 対応表 は残し、"is" 欄は指示対象に限る

頭註の 対応表 (doc の用語 → このファイルの識別子) は**節の再記述ではなく命名の根拠なので残す**
(2026-08-23、オーナーの判断)。落とすと、次に同じ語へ別の識別子を当てる余地が戻る。**ただし
"is" 欄が持つのは「この識別子が何を指すか」1 つで、その値がどう決まるかは doc が持つ** —
`detail.ts` の 主要属性 が「6 つ、3 段 2 列。assignee は本文側」まで書いていたのは doc-8 §3 の
本文であり、この型は詰め直す。

### 走査が押さえるのは引用の解決だけである

`src/lib/comment-citation.test.ts` が押さえるのは、**註が名乗る節・decision・識別子・パスが現に
在ること**である。**契約の再記述かどうかは述語で判定できない**ので、走査は書かない — 落とすべき文と
残すべき文が同じ述語を持つ以上、字面で数えた総数は総数にならない (TASK-128 の 1R の [P2] と同型)。
**「走査を足したから以後は大丈夫」とは言えない。** 走査が守るのは腐りの 1 種、引用が指す先の消滅
だけである。

## Consequences

- **今回畳んだのは 6,182 行である** — 頭註 121 塊 2,392 行と、本文中で 8 行以上かつ doc・decision を
  名乗る 339 塊 3,790 行。**8 行という切り口は 1 セッションで判定できる量から決めた作業上のもので、
  契約ではない。** 残る約 10,500 行の本文註は判定していない。**「軽微だから残した」ではない** —
  同じ型が在るかを測っていない。
- **AGENTS.md と AGENTS.ja.md の Coding style / Comments 節が本 decision を引く。** あの節の
  「既存のコメントを畳むな、提起せよ」は残り、**提起の答えが本 decision であることを 1 行で示す。**
- **doc-11 §8 は動かない。** あの節の対象は利用者が読む文のままで、本 decision がその外側を引き受けた。
  §8 が「そちらは TASK-107」と書いている行の指す先が、本 decision である。
- **註を書く回は、その文が実装に依存しているかを 1 文ずつ問う。** AGENTS の 4 項は「何を書くか」を
  述べており、本 decision はそこへ**判定の手順**を足す。
- **後続への影響**: 残る本文註の判定は別タスクが持つ。**そのタスクが最初にすることは数え直しである** —
  本 decision が書いた 16,747・3,800・6,182 はこの日の値で、註を触る回ごとに動く。
