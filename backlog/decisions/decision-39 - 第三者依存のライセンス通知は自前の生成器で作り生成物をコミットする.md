## Context

配布する 3 形式のバンドルは、同梱する第三者依存の licence 本文を運ばなければならない。
`src-tauri/tauri.conf.json` の `bundle.resources` が `../LICENSE` と `../THIRD-PARTY-LICENSES.txt` を
名指ししており、**この 2 つはどの bundler も自分で解決する** — `src-tauri/` より上を指しているので、
どれかが運び損ねうる。

本 ADR は 2 語を導入する。

- **通知ファイル** … リポジトリ直下の `THIRD-PARTY-LICENSES.txt` を指す。バンドルが運ぶ実体であり、
  リリースには単独の資産としても添付される。
- **生成器** … 通知ファイルを書き出す `scripts/generate-third-party-licenses.mjs` を指す。

**AGENTS の Dependencies 節が求める確認（新規本番依存の選定理由と導入範囲）に触れる分岐だったので、
ユーザーが 2026-08-14 に選定した（TASK-159）。** 本 ADR はその選定と、同じ回に一緒に決まった 3 つの
採否を、後から数え直せる形で記録する。**2026-08-19 に doc-13 を新設した回に書き起こしたもので、判断そのものは
2026-08-14 のものである** — それまで記録は AGENTS の Release 節と生成器の頭註にしか無かった。

## Decision

### 1. 生成器は依存を増やさない — `cargo-about` を採らない

npm 側は `pnpm licenses list --prod --json`（pnpm 自身のサブコマンドなので `packageManager` が既に
版を固定している）、cargo 側は `cargo metadata` と生成器の中の tar 読みだけで作る。

並べた候補は `cargo-about` である。**3 つの理由で退けた。**

- **cargo 側しか覆わない。** npm 側の一覧はどのみちこのリポジトリで書くことになり、生成器が 2 つになる。
- **リリースのたびにコンパイルされる。** 資産を作る経路に、資産と関係のないビルドが 1 つ増える。
- **`accepted` 許可リストが、通知なら記録するだけで済む licence の変更でリリースを止める。**
  通知の目的は「何が入っているか」を述べることであって、入れてよいかを判定することではない。

`cargo-about` が持ち込むはずだった SPDX 本文の集まりは、このリポジトリでは `scripts/spdx/` に置く。

### 2. 生成物はコミットする — CI で作らない

`tauri.conf.json` が通知ファイルを `bundle.resources` に挙げているので、**ランナーの上にしか存在しない
資材は、README の「ソースからのビルド」に従う全員の `pnpm tauri build` を壊す。**

コミットして安全なのは、**出力がバイト再現可能だからである。** 生成器は時計も、パスも、機械ごとに
違う値も読まず、書き出す一覧はすべて整列している。

### 3. crate の集合は 5 つのリリース対象トリプルの和集合とする — 無フィルタのグラフを採らない

`cargo metadata --filter-platform` を 1 トリプルにつき 1 回流して和を取る。**無フィルタのグラフは
lockfile が記述しうるすべてのプラットフォームを解決するので、Android・wasm・Redox・iOS・GNU ABI の
Windows の crate がこのバンドルに入っていると通知が主張することになる。**

**一覧はリリースが組むバンドルに従う。** arm64 の Linux 行を足した回に `aarch64-unknown-linux-gnu` が
入った（TASK-172）。2 つの Linux トリプルは今日のところ同じ crate を解決するが、後から
`cfg(target_arch)` で入る依存が arm64 のバンドルで一覧から漏れるのを防ぐために置いてある。

### 4. licence 本文は `.crate` tarball から読む — 展開済みのソースを採らない

cargo のレジストリキャッシュにある `.crate` を生成器が自分で開く。**`cargo fetch --target` は
ビルドしないプラットフォームぶんもキャッシュを埋めるが、展開はビルド時に起きる** — どの 1 台でも
展開済みの集合はそのホストぶんしか覆わないのに、この通知は 5 トリプルを一度に覆わなければならない。

### 5. 本文を持たない識別子は生成器を止める — 本文をでっち上げない

自前の licence 本文を publish していない crate があり、その識別子の標準本文が `scripts/spdx/` から
立て替わる。**`scripts/spdx/` に本文の無い識別子が現れたら、生成器は止まる。** 止まること自体が目的で、
それは誰も見ていない licence をこのツリーが取り込んだという意味だからである。

## Consequences

- **手順と実測値の正本は doc-13 §4 である。** 再生成のコマンド、通知ファイルの頭が記録する digest、
  `.gitattributes` がその digest を成り立たせていること、バンドルが通知を運ぶ経路、そのときどきの
  crate 数はあちらが持つ。本 ADR は採否だけを持ち、数を持たない。
- **依存を足す回は通知ファイルを再生成してコミットする。** 忘れても `src/lib/third-party-licenses.test.ts`
  とリリースワークフローの検査が落ちるので、「誰かが思い出す」ことには掛かっていない。
- **リリースが出すバンドルを増やす回は、生成器の対象トリプルも数え直す。** §3 の一覧はリリースの
  バンドルに従うと決めた以上、バンドルを 1 つ足しても何も落ちないのは仕様である。
- **この層の他の採否は decision-7・decision-26（sidecar を同梱しない）と decision-30（自己更新を持たない）が
  持つ。** 本 ADR はそれらを変えない。
