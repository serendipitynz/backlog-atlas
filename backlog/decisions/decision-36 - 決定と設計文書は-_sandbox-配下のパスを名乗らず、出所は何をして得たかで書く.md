## Context

**README は読者を 2 つのディレクトリへ送る** — 「設計上の決定は `backlog/decisions/`、仕様は
`backlog/docs/` にあります」（README.ja の 1 文、README も同じ）。**タスクもマイルストーンも
名指ししていない。** リポジトリは 2026-08-14 にパブリックになっており、そこへ来た読者が読むのは
この 2 つである。

**その 2 つが、リポジトリに入らないディレクトリの下のパスを 28 箇所で名乗っていた。**
`_sandbox/` は `.gitignore` の 25 行目で無視されるので、**clone した読者のツリーには存在しない。**

語と指示対象は TASK-169 の対応表 初版で本文より先に固定した。**新語は 1 つも置いていない。**

### 実測 (2026-08-18)

**数え上げは `git grep` で行い、種類の判別は 28 箇所を 1 行ずつ読んで行った。**

- **面ごとの出現数** — `backlog/decisions/` が 25、`backlog/docs/` が 3、`backlog/tasks/` が 153、
  `backlog/milestones/` が 0、`backlog/` の外が 7（`.gitignore` 1・`biome.jsonc` 1・`src/` の
  コードの註 5）。**起票時の「約 140 箇所・distinct 58」は `backlog/` 全体を数えた値で、いまは
  175・71 である。**
- **読者が送られる 2 つの面の 28 箇所は、21 のパスと、パスでない 1 つの出現から成る。**
  1 行に 2 つ入っている箇所は無い（行数と出現数がどちらも 28）。
- **種類は 6 つで、4 つではなかった**（起票時は測定スクリプト・対応表・実装報告書・画像の 4 つを
  挙げていた）。対応表 13・測定スクリプトとハーネス 7・実装報告書と品質評価 5・測定の記録 1・
  画像 1・**`_sandbox/` そのものを対象として名指しする文 1。**
- **21 のパスのうち 6 つは、オーナー自身の作業ツリーでも既に辿れない。** 対応表 5 つは
  `referent-table/` へ畳んだ回に一斉にずれ（3 つは `handoff/referent-table/` の下、2 つは
  `_done/referent-table/` の下に現存する）、画像 1 つ（`TASK-82.png`）は消えている。
- **同じ腐りがコードの註にも起きている** — `src/` の 5 箇所のうち 2 箇所（`mark.ts` が引く対応表と、
  `markdown-figure.component.test.ts` が引く測定の置き場）が現存しないパスを名乗っている。
- **腐りを検知する機構は 1 つも無かった。** `_sandbox/` は git の外にあるので、リポジトリの中の
  どの検査もこれらの主張の真偽を確かめられない。

### 3 案のうち 1 と 3 を採らない理由

起票時に挙がった 3 案は、そのままにする（案 1）・パスを名乗らない（案 2）・参照先をリポジトリへ
入れる（案 3）である。**2026-08-18 にオーナーが 6 種すべてについて案 2 を選んだ。**

- **案 1 が前提にしていた「辿れないことは害ではない」は、上の実測で崩れている。** 前提は
  「公開の後に読者が辿れなくなる」だったが、**辿れないのは読者だけではなく、6 つは書いた側でも
  既に辿れない。** 出所を記録した事実が残る、という案 1 の利点は残るが、**それはパスを落としても
  同じだけ残る** — 落ちるのは在り処だけである。
- **案 3 は、測定スクリプトとハーネスの 7 箇所について実際に検討した。** 読者が決定の主張を自分で
  検算しうる唯一の種類だからである。**採らなかったのは、7 箇所のうち 4 箇所がスクリプトではなく
  ハーネス（`app-check/`・`text-scale-check/`）を指しており、それらは playwright に本物の
  コンポーネントを載せて測る作りで、移せば維持対象の production 相当物が増え、依存ゲートにも
  触れるためである。** スクリプト 3 本だけを移す案は種類の中で扱いを割ることになり、
  **規則が 1 つでなくなるぶんの費用が、読者が得る検算可能性に見合わないとオーナーが判断した。**

### decision-27 §4 との関係

**§4 は「実測註はリテラルのまま残す」と述べており、その根拠の 1 つが「リテラルの書き換えが
再実測を促す強制力である」である。** 形だけを見れば、パスも同じ理由で残すべきに見える。
**本決定はその類推を採らない。理由は実測である。**

- **版リテラルの強制力は現に働いている** — 版を上げる回のセッションは `backlog/decisions/` の
  実測註を読みに行くので、書き換えの契機がその読み手のところに在る。
- **パスについては働かなかった。** `_sandbox/` を畳み直した回のセッションは `backlog/decisions/` を
  1 行も読んでおらず、**5 箇所が同時に、何も落とさずに偽になった。** 強制力があるという主張は、
  この 5 箇所によって反証されている。

**§4 は動かさない。** 本決定が扱うのは、実測註のうち「どこに置いてあるか」を述べる部分だけで、
版表記には触れない。

## Decision

### 1. 決定と設計文書の本文は `_sandbox/` 配下のパスを名乗らない

`backlog/decisions/` と `backlog/docs/` の本文に、`_sandbox/` の下のファイル名・ディレクトリ名を
書かない。**これは出所の記述をやめることではない** — やめるのは在り処を名乗ることだけである。

### 2. 出所は、何をして得たかで書く

パスを落とした後に残す句は、**誰が・いつ・何をして得たか**を述べる。「作業場のハーネスに本物の
`App.svelte` を載せて測った」「対応表に本文より先に固定した」「実装報告書の指摘 2」がその形である。
**どこに置いてあるかは述べない。**

**日付と、測った対象と、得た値は落とさない。** 落とすのは在り処だけである
（decision-27 §4 が求める版リテラルもここに含まれない）。

### 3. `_sandbox/` そのものを対象として名指しする文は、この規則に当たらない

decision-32 が Biome の縮退を述べるときの「`_sandbox/` と `src-tauri/target/` を舐めて 49,056 件を
報告した」は、**読者が辿る先ではなく、どの作業ツリーにも在るディレクトリについての陳述である。**
`.gitignore` と `biome.jsonc` の記述も同じ側にある。**`_sandbox/` の後ろに名が続かない出現は通る。**

### 4. 範囲は 4 つ足して 2 つ外す。外す 2 つの理由は次のとおりである

**規則は AGENTS 和英と README 和英にも掛かる。** README が読者を送る先を述べているのが README
自身であり、AGENTS は作業する者がこの規則を読む場所だからである。**この 4 ファイルの現在値は
0 箇所なので、足しても既存の文は 1 つも動かない** — 足すのは、同じ壊れ方がそこへ来るのを止める
ためだけである。

**`backlog/tasks/` の 153 箇所とコードの註の 5 箇所には掛からない。**

**これは「そちらは辿れる」という主張ではない。** 上の実測のとおり、コードの註 5 箇所のうち 2 箇所は
既に死んでいる。掛けない理由は次の 2 つである。

- **タスクの 153 箇所のうち 137 箇所は Done タスクの記録である。** 書き換えることは、済んだ
  セッションが何を見て何をしたかの記録を後から変えることであり、記録の側の性質が変わる。
  **残る 16 箇所は次に触る者への手掛かりで、そのパスを辿るのは作業者自身である** — 読者ではない。
- **コードの註は、そのコードを直す者が再測定に使う手掛かりである。** 読者が設計の根拠として
  読みに来る面ではない。

**新しく書く回は、タスクとコードの註でも同じ形で書いてよい**（在り処より、何をして得たかのほうが
腐らない）。**既存は書き換えない。**

### 5. 規則は走査が保つ

`src/lib/sandbox-reference.test.ts` が `backlog/decisions/`・`backlog/docs/`・AGENTS 和英・
README 和英の全文を読み、`_sandbox/` の後ろに 1 文字でも名が続く出現があれば落ちる。**§3 の「そのものを名指しする文」は
通る** — 通す条件が「後ろに名が続かないこと」なので、§3 の判定がそのまま走査の判定になっている。

**「名」を ASCII の字種で数えない。** この repo の管理ファイルはどれも日本語で名が付いているので、
ASCII の一覧で書くと日本語の名を持つパスがそのまま通る。**走査は逆に「参照が終わる 2 通り」を数える** —
code span を閉じる backtick と、素で書いたときの空白である。**code span に入れずに書いた `_sandbox/` に
文が直結すると偽陽性になるが、誤りの向きはそちらでよい** — この repo の書き方でないものが大きな音で
落ちるほうが、書き方であるものが黙って通るより安い。

**走査はもう 1 つの形も落とす** — 対応表を、それを作ったタスクではなくファイル名で名乗る形である。
**`_sandbox/` を伴わずに無視ツリーのファイルを名乗る形は、実測でこの 1 族だけ現れた**
（decision-23 が起点の表をファイル名で書いており、その名は接頭辞付きの隣と同じく死んでいた）。
**この 2 本で捕まらない形は残る** — 別の族の素のファイル名はどちらのパターンにも当たらない。
**それが、規則を §2 の側（何を書くか）で述べ、禁止だけで述べない理由である。**

**走査自身が違反の実例を綴れないことは、この規則の帰結である。** 直っていない形を本文へ引用すると
走査が落ちるので、**決定の側は形を記述で述べ、実例は試験の植え込みが持つ。**

**走査が無いと、この規則は書いた回の次から黙って戻る。** 上の実測が示しているのは、
`_sandbox/` を触る回のセッションが `backlog/decisions/` を読まないという事実そのものなので、
**人が思い出すことに賭ける形はここでは既に一度失敗している。**

**走査は自分が読む集合も押さえる。** 2 つのディレクトリの `.md` が 1 件も取れない状態でも
「違反 0 件」は成り立つので、件数の下限と、規則が書かれた 2 ファイル（本決定と doc-11）が
集合に入っていることを別に主張する。**両パターンは植え込みで確かめる** — 書き換え前の実物の
2 行をその場で作り、走査が見つけることを要求する。

## Consequences

- **28 箇所を書き換えた** — `_sandbox/` の 27 箇所（28 箇所のうち §3 に当たる 1 箇所を除く）と、
  素のファイル名 1 箇所（decision-23）である。**内訳は decision-17・18・19・22・23・24・25・27・
  28・30・31・32・33・34 と doc-11 で、決定 14 件と設計文書 1 件。** 死んでいた 5 つの対応表の
  参照と、消えていた画像 1 つの参照は、これで**在り処を名乗らない形になり、偽の主張ではなくなった。**
- **読者は測定手順を自分で走らせられない。** これは案 2 を採ったことの帰結で、**案 3 を退けた
  時点でオーナーが承知している。** 決定が述べる値そのものと、何をして測ったかは本文に残る。
- **decision-22・23・24・25・27・28・30・31・32・33・34 が持つ「対応表に先行確定した」という
  記述の形が揃った。** 以後の決定もこの形で書く — **版番号（第 N 版・初版）は残す**（どの版の表で
  固定したかは、在り処ではなく何をしたかの一部である）。
- **`backlog/tasks/` の 153 箇所とコードの註の 5 箇所は、腐ったまま残っている。** これは
  Decision §4 が理由付きで残したものであり、**発見しても欠陥として起票しない。**
- **後続への影響** — `backlog/decisions/` か `backlog/docs/` に新しい出所の註を書く回は、
  パスを書くと `pnpm test` が落ちる。落ちたときに直す先は註の書き方であって、走査の除外ではない。
