## Context

decision-12 は **priority は族の色を借りない**と定めた。high / medium / low を `--fg`／`--bg` の
濃淡と枠線だけで区別する判断で、理由は当時の high `#c0392b` が読取不能の族の色と、medium
`#b8860b` が不整合（当時の縮退）の族の色と同色であり、族を汚染することだった。画面設計案 04・05
も同じ推奨を刷っている（doc-12 §5・§6.5）。

その判断の前提が TASK-77（decision-22）で変わった。**カード左 3px の族色が外れた** — 不整合を
カードで述べるのは印グリフ ⚠️ だけになり、カードの縁は何も述べていない。同時に、利用者が
Backlog の画面から Atlas へ来るという事情は変わっておらず、**backlog.md の web UI はカードの
左の縁を priority で彩色している**（実測: `high` → `border-l-4 border-l-red-500`、`medium` →
`yellow-500`、`low` → `green-500`、値なし → `gray-300`。dark はいずれも 400 番台）。同じ台帳を
見る 2 つの画面が、同じ位置の同じ装置を別の意味に使っている状態である。

争点は 4 つあり、いずれもユーザーが 2026-08-06 に確定した — 縁が取る色（backlog.md 準拠の
3 色相）、priority チップも彩色するか（しない）、priority 未設定・未知に縁を出すか（出さない）、
閾値（3:1）。指示対象の対応表は `_sandbox/handoff/referent-table-task-78.md` 第 2 版に先行確定した
（起点は `referent-table-task-77.md` 第 2 版）。本決定はその表の語で書く。

## Decision

### 優先度の縁

**優先度の縁** … タスクカードの左辺 3px に置き、そのタスクの priority を色で述べる縁を指す。
TASK-77 が族色を外して空けた、同じ位置の同じ装置である。

- **描くのは priority 3 段だけ** — frontmatter の priority を正規化（前後の空白を落とし小文字化）
  した結果が `high`・`medium`・`low` のいずれかに一致するとき、その段の色で縁を描く。
- **正規化は絞り込みの priority ファセットと同じ 1 つの関数**（`src/lib/card.ts` の
  `normalizePriority`）による。別々に正規化すると、絞り込みが `high` と認めないタスクに縁だけが
  付く状態を作れる。
- **カードの幅は変えない。** 縁のぶんだけ左の内側余白を減らし、縁のあるカードと無いカードで
  文字の左端が揃うようにする。族の縁はこれを要さなかった（不整合は稀である）が、priority は
  ほとんどのカードに付くので、揃えないと 1 セルの中で行頭が 2px ずつ食い違う。

### priority 未設定 と priority 未知 には縁を出さない

- **priority 未設定** … frontmatter に priority が無い状態。**priority 未知** … priority はあるが、
  正規化しても 3 段のどれにも一致しない状態（例: `urgent`）。
- **どちらにも縁を出さない。** 縁が無いこと自体が「この 3 段のどれでもない」を述べる
  （decision-6 の正常な不在は中立表示）。backlog.md は未設定にも灰色の縁を出すが、Atlas では
  採らない — 下の収録条件を満たす無彩の色値は `--fg` しかなく、灰色の縁を出すと
  「中立表示は収録条件の対象外」という例外を 1 つ増やすことになるためである。
- **priority 未知 を 3 段のどれかへ寄せない。** 値はあるのだから、寄せた時点で画面が
  frontmatter の書いていないことを述べる。**priority チップは原文の語をそのまま出し続ける**ので、
  未知の値が隠れるわけではない — 色が付かないだけである。

### 優先度色

**優先度色** … 優先度の縁が priority 3 段のそれぞれに引く 3 つの色値を指す。`--priority-high`・
`--priority-medium`・`--priority-low` として表示テーマ（decision-12）へ足す。

- **族ではない。** `--mark-*` の集合に入らず、印がこれを借りることもない。`--info`・`--sel` と
  同じく「族ではない色」の側に置く。族は印の色を選ぶ単位（decision-22）であり、優先度の縁は
  印ではない。
- **色相の役割は backlog.md から取る** — high＝赤・medium＝アンバー・low＝緑。順序を色で読めるのは
  この慣習によるので、族の色相を避けるために別の 3 色相を選ぶ案は退けた（退けた案の代償は、
  順序が priority チップの語だけに載ること）。
- **上流の値そのままでは収録条件を満たさない。** 実測すると backlog.md の `yellow-500` は
  白地に対して 1.91:1、`green-500` は 2.22:1、`red-500` は 3.82:1 で、3 つのうち 2 つが下の 3:1 を
  下回る。**明度だけを動かして満たす** — decision-12 が借用パレット 8 組に対して採ったのと同じ
  調整であり、上流の配色と完全には一致しない。
- **medium の色相は黄土（不整合）から離す。** backlog.md の `yellow-500` は色相 86° で、収録済み
  10 テーマの `--mark-inconsistent` は 75〜90° にある。**優先度色の medium は 61〜62°（アンバー）**を
  取り、同じカードの上に並ぶ不整合印との距離を作る。high の 25°（赤）は `--mark-unreadable` の
  3〜31° と重なるが、こちらは色相を動かすと「赤＝高」が失われるので動かさない（下の
  「問題の縁と形を共有する」を参照）。

### 優先度の縁の収録条件

**優先度の縁の収録条件** … 優先度の縁の色と、それが接する面（`--panel`・`--inset`・`--bg`）の色との
比が、収録するすべての表示テーマ・すべての面で **3:1 以上**であること。

- 3:1 は WCAG 2.2 の 1.4.11 Non-text Contrast が非文字要素に定める下限で、**優先度の縁は語を持たない
  非文字要素**なのでこれが対応する下限である。decision-22 の印グリフの収録条件と同じ根拠・同じ値を
  取る。
- **印チップの 4.5:1 は適用しない。** あの比は「族の色」と「族の色 12% 混色を面へ合成した背景」の
  比であり、縁にはその混色背景が無い（decision-22 が印グリフについて述べたのと同じ理由）。
- **接する面を 3 つとも見る。** 縁の内側はカード面 `--panel`、外側はレーンセルの地 `--bg` である。
  `--inset` を併せて持つのは、後からカードをくぼみ面へ置く画面が出たときに条件を開き直さずに
  済ませるためで、印グリフの収録条件が 3 面を挙げているのと同じ扱いである。
- **収録済み 10 テーマの実測**（2026-08-06、`src/app.scss` から算出）: 10 テーマ × 3 段 × 3 面の
  全 90 セルで **最小 4.60:1**。判定は `src/lib/theme.test.ts` が `app.scss` から再計算して行い、
  **優先度色が族の色そのものでないこと**も同じ試験が押さえる。

### priority チップは無彩 3 段のまま

- **反転するのは優先度の縁だけで、priority チップは decision-12 のまま**（high＝`--fg` 塗りに
  `--bg` 文字、medium＝`--line-strong` の輪郭、low＝`--line` の輪郭に `--muted` 文字）。
- 理由は閾値が別だからである。**チップは語を持つ文字要素**なので、対応するのは印チップ配色規則の
  4.5:1 であって非文字要素の 3:1 ではない。優先度色は 3:1 で選んだ値なので、そのまま文字色には
  使えない。1 つの色値に 2 つの規則を背負わせず、色は縁、語はチップ、と担当を分ける。

### priority チップの角丸は 3px

- doc-11 §2.2 の角丸は「チップ 3px / カード・ボタン 4px / パネル 6px / ラベルピル 999px」であり、
  priority チップはチップの 4 系統（doc-11 §3）の 1 つなので **3px を取る**。実装が 999px を
  持っていたのは、この表からの逸脱である。**契約は変えていない** — 実装を表へ合わせるだけである。
- **通常ラベルの 999px は維持する。** 画面設計案 04 の契約 #4「Type とラベルを混ぜない」が
  通常ラベルに与えた形であって、priority のものではない（doc-12 §5）。

### 問題の縁と形を共有する

**優先度の縁は問題の縁（doc-11 §2.3）と同じ装置を同じ色相で使う。** これを承知のうえで採る。

- 赤の左端は、カードでは high、**レーンヘッダ行では読取不能**（`Swimlane.svelte` の
  `border-left: 3px solid var(--mark-unreadable)`）、上部帯では帯の族を述べる。
- **TASK-77 が解いたのは「同じカードの縁が族と priority の両方を述べる」衝突だけ**である。
  カードの外にある問題の縁との衝突は解けていない。
- **区別は色相ではなく、何がその縁を持っているかで行う。** カード（1 件のタスク）と
  レーンヘッダ行（1 プロジェクト行）と上部帯（画面全体）は大きさも位置も別の表示要素であり、
  問題の縁を持つ 2 つは語を伴う（「読取不能」と帯の本文）。**優先度の縁だけが語を伴わない**が、
  同じカードの priority チップがその語を持っている。
- したがって decision-12 が退けた経路（族の色を priority が借りる）は**戻っていない** — 優先度色は
  族の色そのものではなく、収録条件の試験がそれを押さえる。戻ったのは色相の近さだけである。

### 画面設計案 04・05 との関係

画面設計案 04（カードサイズ）と 05（配色と契約）は、どちらも priority を無彩 3 段にする推奨を
刷っている（doc-12 §5・§6.5）。**本決定はその推奨に対する反対の決定である。** 前提が変わった
ためで、変わったのは 2 点 —

- 04・05 が書かれた時点では、族の色がカード左 3px に載っていた。**decision-22 でそれが外れた**ので、
  「カードの縁で族と priority が同色になる」という 04・05 の懸念の対象が無くなった。
- 04・05 は縁の彩色を扱っていない。無彩 3 段の推奨対象は priority チップであり、**本決定は
  チップについては 04・05 の推奨を維持している**。

doc-12 は転記であって決定ではないので、原文の推奨はそのまま残す（doc-12 §1）。後から画面設計案を
読んだ人が反対の推奨に突き当たったときの参照先は本項である。

## Consequences

- 望ましい帰結
  - カンバンで priority を距離をおいて読める。priority チップの語は 1 枚のカードを見れば分かるが、
    列に並んだ 20 枚から high を拾う読み方は色でないと成立しない。
  - backlog.md の web UI と同じ位置・同じ色相の役割になり、2 つの画面を行き来する利用者が
    読み方を切り替えずに済む。
  - TASK-77 が空けたカードの縁が埋まり、「何も述べていない縁」が残らない。
- 費用・制約
  - **表示テーマの色値が 3 つ増える。** 収録条件の検算は 10 テーマ × 4 値 × 3 面（印）に加えて
    10 テーマ × 3 段 × 3 面（縁）になり、テーマを足す作業がその分増える。decision-12 の
    「検算を怠ると画面上は気付けない」はこちらにも効く。
  - **赤の左端が画面上で 2 つの意味を持つ。** 区別は要素の別で行うことになり、色相だけを見て
    判断できない（decision-22 が族について残した制約と同型）。
  - **priority 未知 は色で区別できない。** priority 未設定 と同じく縁を持たないので、両者の別は
    priority チップの有無だけが述べる。
- 後続への影響
  - **TASK-79**（画面から過剰な説明文と設計文書参照を落とす）は、priority チップの語を落とす対象に
    しない。縁は語を持たず、チップが唯一の語である。
  - **TASK-80**（画面設計案と実装の差分）は、priority の彩色について 04・05 と実装が食い違う点を
    差分として挙げない。本決定が意図した相違である。
  - 表示テーマを足す作業は decision-12 が正本のままで、本決定は検算する値を 3 つ足すにとどまる。
