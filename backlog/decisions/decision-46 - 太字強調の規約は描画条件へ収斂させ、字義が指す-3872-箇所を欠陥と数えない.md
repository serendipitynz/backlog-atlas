## Context

AGENTS 和英の 作業上の規約 は「日本語の Markdown では、閉じる `**` の後に文が続くなら半角スペースを
1 つ置く」と書いており、条件を付けていない。理由として挙げられているのは CommonMark の
right-flanking で、`**〜です。**Atlas` は閉じ側の直前が `。` で直後が語なので閉じられず、`**` が
そのまま本文に出る（**直後が約物なら閉じられる** — `**第一。**（補足）` は正しく描画される）。TASK-161 はこの崩れる分を 44 ファイル・426 個直し、`src/lib/emphasis-closing.test.ts` を恒久的な
検査として置いた。

**残っていたのは、規約の字義が検査より広いことである。** `**Ubuntu なら 24.04 以降**で` は閉じ側の
直前が `降` なので正しく描画されるが、字義はそこにも半角スペースを求める。TASK-161 の回に測った差が
3,454 箇所で、その扱いを決めるのが TASK-194 である。**それまで両 AGENTS は「`pnpm test` が通ることは
字義充足の根拠にならない」と書き、3,454 箇所を触らないまま残していた。**

争点語は TASK-194 の対応表で本文より先に固定した（初版 2026-09-06、害の軸と集合の包含を第 2 版で訂正）。以下で使う
**字義超過箇所**（規約の字義が半角スペースを求め、かつ描画は成功している箇所）・
**描画破綻形**（閉じ側の直前が約物で直後が語であり、閉じ側が閉じられない並び）・
**句内終止**（閉じ側の直前が語であり、太字の範囲が句の途中で終わっている字義超過箇所）・
**文末終止**（閉じ側の直前が約物であり、太字の範囲が文の切れ目で終わっている字義超過箇所）
はその表の語である。

### 実測 (2026-09-06)

数え方は `emphasis-closing.test.ts` と同じ素の markdown-it で全文を描画し、`</strong>` の直後 1 文字が
空白でもタグの開始でもない箇所を数えた。対象は `backlog/tasks`・`backlog/docs`・`backlog/decisions`・
`backlog/milestones` と散文 4 ファイル。

- **字義超過箇所は 3,872 である。** tasks 1,709・docs 1,425・decisions 669・milestones 0・散文 69。
  2026-08-19 は 3 ディレクトリで 3,454、散文で 64 だったので、**18 日で 3 ディレクトリが +349、散文が
  +5 である。** **差は放っておくと開く。**
  **この 3,872 は本決定を書く前のツリーの値である。** 本文と AGENTS 和英の改訂を入れた後は 3,880 で、
  内訳の差は decision-46 自身の +7 と散文の +1 である。**その 8 を追う必要は無い** — 下の Decision が
  字義超過箇所を違反でなくするので、この値は 2026-09-06 の記録として置かれるだけである。
  **2 つ書いたのは、測った対象がどちらであるかを後から決められるようにするためである。**
- **閉じ側の直前と直後を組にすると、3,872 は 3 つにしか割れない。** 語 → 約物 2,655、語 → 語 1,049、
  約物 → 約物 168。**約物 → 語 は 0 である。**
- **その 0 は実測値ではなく CommonMark からの帰結である。** 直前が約物で直後が語だと閉じ側は
  right-flanking を満たさず閉じられないので、`<strong>` が生まれず、数える対象になりようがない。
  **すなわち 描画破綻形 は 字義超過箇所 に 1 件も含まれ得ない。** **実測なのは別のことで、ツリーに
  描画破綻形 が 1 件も無いこと、すなわち `emphasis-closing.test.ts` が緑であることである**（同日に確認）。
- **半角スペースを入れて読みやすくなる並びは、3,872 のどれでもない。** **何が壊れるかを決めるのは
  直後の文字であって、上の 句内終止 と 文末終止 の区分ではない。** 直後が語の 1,049 件では
  `**〜規則**へ改めた` が `規則 へ改めた` になり、語とそれに続く助詞・述語の間が割れる。
  直後が約物の 2,823 件では `**書けない**（〜` が `書けない （〜` になり、約物の前が空く。
  **両 AGENTS は末尾で「`:` や `（` の前の半角スペースは、得るものより崩すもののほうが大きい」と
  既に書いており、測ると後者はその 2,823 件すべてである。** **前者はその文が触れていなかった形で、
  害の理由は別だが結論は変わらない。**
- 案 A（字義どおり書き換える）の費用の内訳も測った。**字義超過箇所のうち 440 件は Done タスク 93
  ファイルの本文である。**

### 規約の理由と、規約の字義が指す先が食い違っている

**AGENTS が規約の理由として挙げている例文の形は、規約の字義が指す 3,872 箇所に 1 件も現れない。**
例文 `**〜です。**Atlas` は 描画破綻形 そのものであり、それは検査が押さえる形の 1 つである。
**理由は検査の側にあり、字義だけが検査の外へはみ出していた** — はみ出した先には、直すと悪くなる
箇所しかない。

## Decision

**規約の発火条件を、閉じ側の直前が約物で、直後が空白でも約物でもない場合に限る。** 改訂後の文は
「日本語の Markdown では、閉じる `**` の直前が句読点で、直後が空白でも約物でもないなら、半角スペースを
1 つ置く」である。**直後についての条件を落として「直前が約物なら」で止めてはいけない** — 止めると
文末終止 168 件が違反として残り、下の「3,872 は違反でなくなる」と矛盾する。**この 2 条件は 描画破綻形
の定義そのものなので、規約が名指す集合はその形と過不足なく一致する。** **それは `emphasis-closing.test.ts` が押さえる形の 1 つであって、押さえて
いる集合そのものではない** — 下の Consequences が差を書く。**規約の集合は検査の集合の真部分集合に
なる。**

3 案から選んだ。**案 A（字義どおり 3,872 箇所を書き換える）は退けた** — 機械適用すると全件で組版が
悪化し、実体は 3,872 件それぞれについて文を書き換えて回避するかを判断する作業になる。うち 440 件は
Done タスクの本文で、**decision-36 §4 が `backlog/tasks/` を `_sandbox/` パスの走査から外した理由
（終わったセッションの記録を書き換えることになる）が同じ形で掛かる。** **案 C（現状維持）も退けた** —
書き換えは 0 件で済むが、「守れと書いてあるが、守ると読みにくくなるだけの規則」が残り、実測値が
18 日で +354 動く以上、両 AGENTS はその数を測り直し続けることになる。**そのどちらも、規約の理由が
既に検査の側にあるという上の事実を変えない。**

**両 AGENTS から、字義と検査の差を述べる段を落とす。** 具体的には「規則の字義はこの検査より広く、
差は N 箇所である」「`pnpm test` が通ることは字義充足の根拠にならない」「新しく書く文は字義どおりに
書く」「TASK-194 が決めるのは〜」の 4 つで、**改訂後はどれも指す先が無い。** **代わりに本決定を
1 行引く。**

**decision を残すと判じた**（TASK-194 の AC #3）。**理由は 2 つで、どちらも AGENTS へ書くには長い。**
1 つは、上の 約物 → 語 が 0 である理由が CommonMark の帰結であって実測ではないことで、これを持たない
読み手には規約を狭めたことが根拠の無い緩和に見える。もう 1 つは、**この改訂が「新しく書く文は字義
どおりに書く」という、複数のセッションが現に従ってきた指示を取り下げることである** — 記録が無いと、
後のセッションが手元の規約を記憶より狭いと見て「復元」しうる。

## Consequences

- **字義超過箇所 3,872 は違反でなくなり、その 1 件も書き換えない。** 規約を述べる 3 か所
  （AGENTS 和英とテスト頭註）は動くが、**数えた 3,872 箇所の本文はどれも元のままである。**
- **規約と AGENTS の例文が同じ形を指すようになり、その形は検査が押さえるものの 1 つになる。**
  検査が緑であることが、そのまま規約が守られていることの根拠になる — **改訂前はこれが成り立たず、
  両 AGENTS がそう明記していた。** **成り立つのは包含の向きが規約 ⊂ 検査 だからで、両者が等しいから
  ではない。**
- **測り直す義務が消える。** 3,454 は 2 つの AGENTS と 1 つのテスト頭註に書かれ、18 日で偽になっていた。
  **本決定の 3,872 は 2026-09-06 の記録であって、追随を要する値ではない。**
- **失うものがある。** 太字の範囲が句の途中で終わる書き方（句内終止 3,704 件がその形である）を、
  規約はもう何とも言わない。**それは読みやすさの問題としては残るが、半角スペースで直る問題では
  なかった** — 直し方は文の区切り方を変えることであり、規約が求めていた操作とは別物である。
  **本決定はそれを規約にしない。** 書き方の助言を規則の形で置くと、守れているかを誰も数えられない
  規則が 1 つ増えるだけだからである。
- **検査の範囲は変わらない。** `emphasis-closing.test.ts` は 描画破綻形 を押さえ続ける。頭註だけを、
  検査より広い字義がもう無いことを述べる形へ改める。
- **規約の集合は検査の集合と等しくならない。真部分集合になる。** ただし**この 2 つは同じ種類のもの
  ではない。** **検査は入力の形を列挙していない** — 描画の結果に表明を掛けている。markdown-it が
  諦めて残した `**` が無いことと、太字になった範囲が著者の区切った範囲であることの 2 つである。
  **規約が防ぐのは、その表明が落ちる入力の 1 つの形にすぎない。** 4 連の衝突
  （`**第一。****第二**とは`）もその形に入る — 閉じ側の直前が `。` で直後が約物でも空白でもないので、
  `**第一。** **第二**とは` にすれば両方が正しく描画される（2026-09-06 実測）。
- **したがって「検査だけが捕まえる入力」を数え上げない。** 数え上げは重なるうえに漏れる — 検査が
  植えている入れ子の標本は規約違反であると同時に範囲の食い違いであり、`これは **強調` は開き側が
  正しいのに閉じ側が無く、そのどちらでもないまま `**` を 1 つ残す（同日実測）。
  **真部分集合であることは証人 1 つで足りる**: `には**「〜」** と書いた。` は閉じ側の後に半角
  スペースがあるので**規約を満たしており**、それでも開き側が左隣接でないので描画されず、`**` が
  2 つ残って検査は赤になる。**よって書けるのは「緑は規約充足を含意する」までで、逆は言えない。**
- **その証人の隙間は、閉じ側の 3,872 箇所に触れずに閉じられる。** `には**「〜」**と書いた` は
  **開き側の前と閉じ側の後の両方に半角スペースが要り、片方だけでは描画されない**（同日実測）。
  後半はいまの規約が現に求めているもので、足りないのは開き側の前についての規則である。
  **それは閉じ側について何も言わないので、本決定が退けた 3,872 箇所を採ることにはならない。**
  **本決定はその規則を置かない。** 本決定が決めるのは閉じ側の規約の範囲であり、開き側の規則を足すか
  どうかは別の問いだからである — **その形がツリーにいくつあるかは数えていない。** **置くとしたら
  別のタスクの判断であり、そのときは数えるところから始まる。**
