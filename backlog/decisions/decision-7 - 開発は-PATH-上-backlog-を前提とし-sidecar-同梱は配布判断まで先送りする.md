## Context

開発時に利用者の PATH 上の `backlog` を呼ぶ前提を確認し、どの時点で sidecar 同梱を
検討するかを決める（TASK-2・TASK-9 に依存、TASK-15）。**sidecar 同梱**とは、アプリ
配布物に含めた Backlog CLI 実行ファイルをアプリから呼び出す配布方法を指す（doc-1）。
これは配布方法の選択であり、Backlog Atlas がタスク正本を所有することを意味しない
（doc-2）。用語を先に固定する。

- **最低バージョン要件** … Atlas が動作保証する Backlog CLI／ファイル形式の下限
  バージョン。これ未満は動作保証外とする。
- **同梱検討契機** … PATH 上 backlog 前提から sidecar 同梱の検討へ移る時点・条件。

前提。decision-1 は Tauri を採用し、その決め手の一つが「sidecar 同梱を `externalBin`
と sidecar Command API で一級サポートし、TASK-15 の選択肢を素直に残せること」だった。
doc-5（更新アダプター）は実行ファイルの解決だけを差し替え可能にし、呼び出し先の実体
（PATH 上か同梱か）に依存しない設計にしてある。読み取りはファイル解析（decision-2）
で、動作確認済みは本決定の時点で Backlog v1.47.1、現在の値は下の「最低バージョン要件」が持つ
（doc-4・doc-5。値を本節へ写さないのは decision-27 による）。すなわち初期版は、既に
「PATH 上 backlog を前提にしても、後から同梱へ差し替えられる」構造になっている。

sidecar 同梱を初期版で先取りしない理由。

- 初期用途は個人利用のローカルアプリ（doc-2）で、開発者＝利用者の PATH に backlog が
  既に入っている。同梱は導入容易性（第三者配布時に CLI 個別導入を不要にする）の
  ための施策で、個人利用の初期版では便益が薄い。
- 同梱は CLI 実行ファイルのバージョン管理・プラットフォーム別バイナリの用意・更新
  追随という継続コストを生む。読み取りがファイル形式に依存する（decision-2）ため、
  同梱版と利用者環境のファイル形式期待がずれる新たな不整合面も増える。
- doc-5 が実行ファイル解決を差し替え可能にしているため、同梱は「後から足せる」。
  初期版で確定を急ぐ必要がない。

## Decision

開発時は利用者の PATH 上の `backlog` を用いることを前提とする。sidecar 同梱は初期版で
採用せず、配布方法を実際に決める段階（同梱検討契機）まで先送りする。

### 最低バージョン要件

- 動作確認済みの Backlog **v1.48.0 を最低バージョン要件**とする（2026-08-01 に v1.47.1 から
  改訂。TASK-58）。読み取り層（doc-4）と更新アダプター（doc-5）は、この版で確認した
  frontmatter/SECTION スキーマと CLI サブコマンド・オプションを前提にする。
  **この行が値の散文側の正本であり、コード側の正本は `update.rs` の `MIN_VERSION` である**
  （decision-27。他の decision・doc はこの値を写さず本項を参照する）。
- **本決定を書いた時点の最低バージョン要件は v1.47.1 だった。** TASK-58 が v1.48.0 を実測し、
  Atlas が依存する挙動が v1.47.1 と v1.48.0 の双方で成立することを確かめたうえで、下の
  「版が上がった際に動作確認して更新する」に従って要件を v1.48.0 へ移した。v1.47.1 でも
  動く操作しか使っていないので、これは能力上の要求ではなく、**doc の「実測」記述の基準版を
  1 つに保つための選択**である（2 つの版の挙動を並記した doc は、どちらを読めばよいか
  決まらない）。v1.47.1 と v1.48.0 で意味の変わるオプションは doc-5 §3.4 に記録した。
- 起動時に PATH 上の `backlog --version` を固定引数・シェル非連結（doc-5）で取得し、
  最低バージョン要件を満たすか検査する。満たさない・`backlog` が見つからない場合は、
  更新機能を無効化して読み取り専用で起動するか、要件を明示して起動を促す（管理
  ファイルの直接解析による読み取りは CLI 不在でも成立するため、読み取りだけは動く）。
- 上限は固定しない。未知の上位版は、読み取り層の想定外スキーマ検知（doc-4）と操作
  写像の未知オプション検知（doc-5）で縮退させ、破壊的動作を避ける。

### 同梱検討契機

次のいずれかが生じた時点で sidecar 同梱を検討する。それまでは PATH 前提を保つ。

- **第三者配布に踏み出すとき**: 開発者＝利用者以外へ配布し、利用者に backlog の個別
  導入を求めない体験が要るとき（doc-2 が初期化に含めないとした公開・配布に進むとき）。
  **この契機は 2026-08-12 に到来し、判断は decision-26 が持つ**（TASK-99。v0.1.0 の公開と
  リポジトリのパブリック化がこれに当たる）。**判断は「同梱しない」で、PATH 前提を保つ。**
  したがって本項は消化済みであり、**第三者配布そのものを理由に再び判断を開かない** —
  配布は既に始まっており、それ自体は新しい事実ではなくなるためである。下の 2 項は生きている。
- **バージョン整合を配布側で固定したいとき**: 利用者環境の backlog の版差が動作保証を
  難しくし、動作確認済み版を配布物に固定したくなったとき。
- **CLI 前提の導入摩擦が実利用を妨げるとき**: PATH 上に backlog が無い利用者が増え、
  導入の手間が採用の障壁になったとき。

同梱を採用する際は、Tauri の `externalBin`／sidecar Command API（decision-1）で
実装し、doc-5 の実行ファイル解決だけを PATH 解決から同梱バイナリ解決へ差し替える。
アダプターの操作写像・作業ディレクトリ・引数配列渡しは変えない。**この差し替えだけで済む
構造は decision-26 が同梱を採らないと決めた後も保つ**ので、残る 2 契機で再検討が起きた
場合にも選択肢は失われない。

## Consequences

- 望ましい帰結
  - 初期版の実装・配布が単純になる。CLI のプラットフォーム別バイナリ管理・更新追随の
    継続コストを負わない。
  - 読み取りは CLI 不在でも成立するため、backlog 未導入でも読み取り専用で起動できる。
- 費用・制約
  - 利用者は PATH に最低バージョン要件を満たす backlog を用意する必要がある。
  - 第三者配布時には、この前提が導入摩擦になりうる（そのときが同梱検討契機）。
- 後続への影響
  - 同梱採用時も doc-5 の実行ファイル解決の差し替えだけで済み、操作写像は不変。
  - 最低バージョン要件は、Backlog の版が上がった際に動作確認して更新する（doc-4・
    doc-5 のサポート範囲と同期させる）。
  - **要件を上げるときに何を書き換えるかは decision-27 が定める**（TASK-154）。値の写しは
    残っておらず、doc は実測基準版を 1 回宣言するだけである。一方、実測の出所を述べる註は
    リテラルのまま残してある — それを書き換える行為が再実測の契機だからで、要件を上げる
    作業はその再実測を含む。
