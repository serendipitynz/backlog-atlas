## Context

TASK-104 は、v0.1.0 の後の版を利用者へ届ける経路を決める。起票は判断の時期も定めていた —
updater の受け皿はビルド時に要るので、TASK-101 が v0.1.0 のバンドル構成を固める前に判断しないと
選択肢が失われる、というのが m-2 に置いた理由である。

**起票の「更新経路」は 3 つを束ねている。**語と指示対象は
`_sandbox/handoff/referent-table/referent-table-task-104.md` 第 1 版で先に固定した。以下で使う
**自己更新**（アプリ自身が新しい版を取得して自分の配布物を置き換える経路）・**版の告知**
（新しい版が出たことを利用者が知る手段。取得と入れ替えの操作は含まない）・**手動入れ替え**
（利用者が配布物を取得して自分で入れ替える操作）・**遡れない受け皿**（公開する版のバンドルへ
入れておかないと、その版の利用者へ後から自己更新を届けられなくなる部分）・**署名鍵の保管義務**
（自己更新を始めた後、秘密鍵と passphrase を保管し続ける義務）・**更新エンドポイント**
（更新マニフェストを配る HTTPS の URL）・**自プロセスの外向き通信**（Atlas のプロセス自身が
開く外向き接続。子プロセスの CLI が開くものは含まない）はその表の語である。

**AC #2 と AC #3 は排他ではない。**起票は「持つ場合」に鍵とエンドポイント、「持たない場合」に
版の告知を求めているが、**版の告知はどちらの判断でも要る** — 自己更新を持っても、何が変わったかを
利用者が読む先はリリースノートである。したがって判断の対象は自己更新 1 つで、版の告知は
その帰結ではなく並立する成果物である。

### 実測 (2026-08-13)

`tauri-plugin-updater` 2.10.1（crates.io の最新安定版）を、作業場に複製した `src-tauri/` へ実際に
足して測った。手順と全数値は `_sandbox/updater-cost/measurement-2026-08-13.md` にある。
**変更前も測った** — 変更後だけでは増分の原因を取り違える。

- **実行ファイルが 13,814,928 B から 17,450,384 B へ増える**（+3,635,456 B、+26.3%）。
  macOS aarch64 の `cargo build --release` の出力で、plugin を `.plugin(…)` で登録したうえで
  測った値である（宣言だけではリンカが落とす余地がある）。
- **crate が 443 から 479 へ増える**（+36 行、別名 34）。**骨は TLS スタック一式**である —
  `rustls`・`ring`・`rustls-webpki`・`webpki-root-certs`・`tokio-rustls`・`hyper-rustls`・
  `rustls-native-certs`・`rustls-platform-verifier`・`schannel`・`security-framework`・
  `untrusted`・`subtle`・`zeroize`。残りは署名検証（`minisign-verify`）、書庫の展開
  （`zip`・`tar`）、一時ディレクトリ、macOS の AppleScript（`osakit`）である。

crate の実装から読み取った事実が 3 つある。いずれも判断の範囲を起票の本文より正確にする。

- **遡れない受け皿は `pubkey` と plugin 登録の 2 つだけである。**`pubkey` は必須項目で設定から
  実行ファイルへ入る（`tauri-plugin-updater-2.10.1/src/config.rs:118`）のに対し、
  `bundle.createUpdaterArtifacts` の既定は `false`
  （`tauri-utils-2.9.3/src/config.rs:1571` と 1540 の `impl Default for Updater`）で、
  **これは版ごとの成果物に署名を付けるかを決める設定なので、後から有効にしても遡って困らない。**
  起票の「バンドル設定がビルド時に必要」は、実際にはこの 2 つを指す。
- **自己更新の通信に CSP は関係しない。**更新マニフェストの取得は Rust 側の `reqwest` で行われ
  （`src/updater.rs:23`、`check` は 385-500）、フロントエンド側は
  `invoke('plugin:updater|check')` を呼ぶだけである（`guest-js/index.ts:139`。ビルド済みの
  `api-iife.js` に `fetch(` は 0 件）。WebView が開く接続ではないので `connect-src` の対象では
  なく、IPC は既に許されている。**decision-28 §3 の表の「IPC 以外の通信をする」行が指しているのは
  WebView の通信で、自己更新の通信はその外側にある** — 表の行はそのままで正しい。
- **Linux の deb/rpm は更新の適用に昇格を要求する。**`pkexec` → `zenity`／`kdialog` で
  passphrase を取って `sudo` → 端末の `sudo` の順に試す（`src/updater.rs:1105-1145`）。
  AppImage だけは自分のファイルを書き換えるので昇格が要らない（同 976-1048）。

### 先行する判断との関係

- **decision-14 は同じ費用を数えて却下している。**GitHub の参照手段を選んだとき、
  `reqwest` に TLS feature を足す案の却下理由は「rustls・ring・webpki-roots（または OS の TLS
  実装）が新規に増える」であり、採用理由の 1 つは「新規クレートが増えないため、ビルド時間・
  監査対象・供給網の面が変わらない」だった。**上の実測は、その集合が実際に増えることを数で
  確かめたものである。**自己更新を採ることは、あの表の却下理由を別の目的のために受け入れ直す
  ことになる。
- **decision-26 の論法がそのまま効く。**同梱を却下した第 1 の理由は「費用が便益に見合わない。
  …その利用者は Backlog.md の管理ファイルを既に持っている者である」だった。自己更新が省くのは
  手動入れ替えで、その相手も同じ利用者である。
- **自プロセスの外向き通信はいま 0 本である。**`src-tauri/` に HTTP クライアントの依存は無く、
  `src-tauri/src/**` に `reqwest`・`ureq`・`TcpStream` は 1 件も出ず、`src/**` に `fetch(`・
  `XMLHttpRequest`・`WebSocket` も 1 件も出ない。外部との通信はすべて、利用者が導入・認証した
  CLI の子プロセス（`gh`。decision-14）が行っている。

## Decision

**v0.1.0 は自己更新を持たない。**更新の受け皿（`pubkey` と plugin 登録）をバンドルへ入れず、
版が進む道は手動入れ替えである。**そのことを意図的な選択として README に書く。**

理由は 3 つで、いずれも上の実測と先行判断に基づく。

1. **便益の相手がまだいない。** 自己更新が省くのは手動入れ替え 1 回ぶんで、その相手は
   `npm install -g backlog.md` を打って CLI を入れた利用者である（README「Requirements」）。
   v0.1.0 は最初の公開なので、受け皿を今入れないことの費用は「後に自己更新を入れる版が出たとき、
   それまでの利用者が 1 回だけ手で入れ直す」に留まる。**受け皿の欠落は利用者を失わせるのではなく、
   移行を 1 回遅らせるだけである。**
2. **費用が構造の側にある。** 自プロセスの外向き通信が 0 本から 1 本になる。いま Atlas が外部と
   通信する経路はすべて、利用者が導入・認証した CLI の子プロセスにあり、decision-14 はその形を
   保つために TLS スタックを増やす案を却下した。上の +36 crate はその集合そのものである。
   **配布物の 3.47 MiB より、この 1 本のほうが判断材料として重い** — 大きさは戻せるが、
   自分で通信するアプリになったことは戻しにくい。
3. **義務が公開後ずっと残る。** 署名鍵の保管義務は、自己更新を始めた版が使われ続ける限り続く。
   失えばその鍵で始めた列は続けられず、利用者は結局手動入れ替えへ戻る。**すなわち自己更新の
   保証は鍵の保管の確からしさを超えない。**単独保守のリポジトリでその保管を約束するより、
   最初から手動入れ替えを述べるほうが、利用者に対して正確である。

**この判断が引き受ける代償は、修正が利用者へ届く速さが利用者任せになることである。**Atlas が
読むのは利用者自身のローカルファイルなので外部入力の面は狭いが、0 ではない（`{@html}` が 1 か所。
decision-25）。**下の再検討の契機は、この代償が実際に効いた場合の入口として置く。**

### 版の告知

**新しい版が出たことを利用者が知る手段は、GitHub Releases とその watch である。**README（和英）が
次の 3 つを書く（TASK-90 の AC #5）。

- v0.1.0 が**意図的に**手動更新のみであること。実装が間に合わなかったのではなく選択である。
- 新しい版は GitHub Releases に出ること、そこを watch すれば通知が届くこと。
- 更新の操作は、新しい配布物を取得して入れ替えることであること。

**アプリ内の版の告知は m-3 で扱う**（TASK-157。2026-08-13 に本決定と同じ回で起票した）。
版の告知は自己更新と違って**取得も入れ替えも行わない**ので、本決定が数えた費用のどれも負わない
— とりわけ `gh` は既に解決済みの外部コマンドなので（decision-29）、`gh release view` を子プロセス
として使えば新規依存も自プロセスの外向き通信も増えない。**それでも m-2 に入れない**のは、
README と Releases だけで版の告知が成立しており、公開阻害に当たらないためである。

### 再検討の契機

次のいずれかが生じたら本決定を見直す。**「利用者が増えた」だけでは開かない** — 増えた利用者が
何に困っているかが、下のどれに当たるかで判断する。

- **修正の到達が実際に問題になったとき**: 直した不具合が、利用者の手元の古い版で起き続けていると
  確かめられたとき。理由 3 の代償が現実になった場合の入口である。
- **手動入れ替えの摩擦が採用の障壁になったとき**: 版を上げないまま使い続ける利用者が多数を占め、
  その理由が入れ替えの手間だと分かったとき。
- **鍵の保管に第三者の裏付けが付いたとき**: 単独保守でなくなるか、鍵の保管が個人の管理から
  離れたとき。理由 3 が消えるのはこの場合だけである。

再検討で自己更新を採る場合、**その版のバンドルから受け皿が入り、それ以前の版の利用者は
手動入れ替えで 1 回だけ移る。**この経路は本決定の時点で分かっているので、再検討は「失われた
選択肢を取り戻す」作業ではない。

## Consequences

- 望ましい帰結
  - **自プロセスの外向き通信が 0 本のまま保たれる。**Atlas が外部と通信する経路は、利用者が
    導入・認証した CLI の子プロセスだけである、という説明が v0.1.0 でも真のまま残る。
  - 配布物が Atlas 自身の大きさに留まる（decision-26 の実測で `.app` 14 MB）。TLS スタック・
    署名検証・書庫展開が監査対象にも供給網にも入らない。
  - **署名鍵が存在しない。**紛失も漏洩も起こりえないので、CI シークレットが 1 つも増えず、
    TASK-100 が扱う macOS の署名資格情報だけが秘密として残る。
- 費用・制約
  - **利用者は自分で新しい版を取りに行く。**README がそれを述べるが、述べても読まない利用者は
    古い版のまま使い続ける。**修正の到達は保証できない。**
  - **v0.1.0 の利用者は、将来自己更新が入っても自動では移れない。**受け皿がその版に無いため、
    1 回だけ手動入れ替えが要る。
  - **版の告知が Atlas の外にある。**GitHub Releases を watch していない利用者には何も届かない。
    アプリ内の版の告知（TASK-157）が入るまでこの穴は残る。
- 後続への影響
  - **TASK-101**（リリースワークフロー）は updater の受け皿を入れない。AC #7 の分岐は
    「持たない」側で、`tauri.conf.json` に `plugins.updater` も `bundle.createUpdaterArtifacts` も
    置かず、どちらの分岐を採ったかがワークフローまたは設定のコメントから読めるようにする。
    **decision-26 と併せて、バンドル構成は `externalBin` も updater も持たない。**
  - **TASK-90**（README）は AC #5 の分岐を「持たない」側で書く。上の 版の告知 の 3 点である。
  - **TASK-102**（パブリック化と v0.1.0 公開）は、手動更新のみと述べた README のまま公開する。
  - **CSP は変えない。**引き継ぎ指示書の「タスク別の注意」は、自己更新を持つ判断なら
    `connect-src` を緩める必要があると書いていたが、上の実測のとおり自己更新の通信は WebView の
    外側にある。**この注意は判断の結果によらず誤りなので、指示書から落とす。**
  - **decision-7・decision-26 は動かない。**本決定は Atlas 自身の配布に関する判断で、Backlog CLI の
    同梱とは対象が違う。同梱検討契機の残る 2 項も、本決定の再検討の契機とは別に生きている。
