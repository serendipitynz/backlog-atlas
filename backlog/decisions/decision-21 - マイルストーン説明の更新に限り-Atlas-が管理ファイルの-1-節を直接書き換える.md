## Context

作成後のマイルストーンの説明を Atlas から直せるようにするかを決める（TASK-65）。

Backlog CLI v1.48.0 の `milestone` が持つサブコマンドは `list`・`add`・`rename`・`remove`・
`archive` の 5 つで、`update`／`edit` は無い（2026-08-06 に `milestone --help` と各サブコマンドの
`--help` で再実測。TASK-58 が 2026-08-01 に v1.48.0 全体を測った結果の再確認）。説明は
`milestone add -d` で作成時にのみ設定でき、`rename` は frontmatter の `title` とファイル名だけを
変える。したがって作成後に説明だけを直す経路は CLI に無い。

CLI の中だけで直そうとすると `milestone remove` ＋ `milestone add -d` になるが、これは説明の
更新ではない。2026-08-06 に使い捨てルートで実測したところ、削除は管理ファイルを
`archive/milestones/` へ移し（doc-9 §4.2.1 の再確認）、作り直したマイルストーンは新しい id を
採った（`m-1` → `m-3`）。id が変わると、そのマイルストーンを参照しているタスクの frontmatter
`milestone` 値が全部外れ、archive に旧ファイルが残る。説明 1 つのために台帳上の同一性を捨てる
ことになるので、この経路は採らない。

一方、これを Atlas 自身の書き込みで埋めることは、次の 2 つが禁じている。

- **AGENTS.md §Updates / AGENTS.ja.md §更新**: Backlog のタスク・文書・マイルストーンの更新は
  Backlog CLI 呼び出しへ委譲し、管理対象の Markdown ファイルを直接変更しない。
- **decision-2 Decision 節**: 読み取りは直接解析、更新のうち Atlas が起こすものは Backlog CLI へ
  委譲する（読み書きで経路を分ける）。ただし同節は既に 1 つの例外を認めている — 利用者が明示的に
  選ぶ外部エディタ経路（doc-8 §7）では、利用者の外部エディタが管理ファイルを直接編集する。そこで
  書くのは利用者であって Atlas ではない。

2026-08-06 に、次の 3 案をユーザーへ提示した。

- **(a) Atlas が説明の本文だけを直接書き換える例外を認める**（本決定が採る案）
- **(b) 外部エディタ経路をマイルストーンへ広げる** — decision-2 が既に認めている例外の適用範囲を
  広げるだけで、契約変更は最小になる。退けた理由は、利用者が frontmatter ごと生の Markdown を
  編集することになり、壊れた frontmatter は doc-4 §5 の縮退表示で受けるだけで、GUI の中で説明を
  直す経験にならないこと。TASK-65 の受入条件 6 件はいずれも Atlas 側の書き込みを前提にしている。
- **(c) CLI が `milestone update` を持つまで提供しない**（現状維持）

ユーザーは (a) を選択した。併せて、説明を空にできるようにするかも同日に確定した（後述）。

## Decision

**マイルストーン説明の更新に限り、Atlas が管理ファイルの説明の本文範囲だけを直接書き換える。**
AGENTS.md / AGENTS.ja.md の §Updates／§更新と decision-2 の「管理ファイルを直接変更しない」に
対する例外であり、その 2 つを本決定で改訂する。反転するのは「Atlas は管理ファイルへ書かない」の
1 点だけで、読み取りを直接解析とすること（decision-2）と、CLI に写像先がある更新は CLI へ
委譲すること（decision-2、doc-5 §3）は動かさない。

**説明の本文範囲**とは、マイルストーンの管理ファイルの `## Description` 見出し行の次の行から、
次の `##` 見出し行の直前まで（無ければファイル末尾まで）を指す。読み取り層が
`Milestone.description` として読む範囲と同一であり、同一であることは両者が同じ関数で範囲を
求めることによって保つ。範囲を 2 か所で書くと、読める文字列と書ける文字列が黙って食い違う。

**直接書き込み操作**とは、更新操作（doc-5 §1）のうち、写像先が Backlog CLI のサブコマンドでは
なく Atlas 自身のファイル書き込みであるものを指す。本決定の時点での唯一の実例が
マイルストーン説明の更新である。

例外が及ぶのは、次の 3 条件を**すべて**満たす更新操作に限る。1 つでも欠けるものは、従来どおり
CLI に手段が無ければ提供しない。

1. **CLI にその値を書く経路が現に在る** — マイルストーンの説明は `milestone add -d` が書いており、
   ファイル上の書式は CLI が定めている。Atlas は新しい書式を発明せず、CLI が書いたものと同じ形の
   バイト列を置く（2026-08-06 実測: `---\nid: m-N\ntitle: "T"\n---\n\n## Description\n\n<説明>\n`。
   SECTION コメント対ではなく素の `##` 見出しである）。
2. **frontmatter とファイル名に触れない** — 触れるものは CLI の側に手段がある（`rename`）か、
   参照追随書き換え（doc-9 §4.2）を伴うかのどちらかであり、直接書き込みへ移す理由が無い。
3. **読み取り層が読む範囲と書く範囲が同一である** — 画面に出ている文字列がそのまま書き戻る範囲
   でなければ、利用者は自分が何を置き換えるのかを画面から読めない。

**書き込み方法**は次のとおり。

- **一時ファイル置換**（decision-17、`store::replace`）で行う。成功時は置き換えたファイル全体が
  destination の名前の下に現れ、途中の失敗では旧ファイルがそのまま残り、一時ファイルも残らない。
  新しい保存機構は作らない。
- **更新前競合の検出**（doc-9 §4）を通す。書き込みは更新操作の実行段に置き、対象の
  書き換え対象集合はマイルストーンの管理ファイル 1 件である。記録済み読取版指標と現ファイルの版が
  一致しない場合は書き込まず、更新前競合として返す。この関門は `SyncState::guarded_update` の
  内側にあり、書き換え対象集合はドメインモデルから導かれるので、呼び出し側が対象を差し替えて
  回避することはできない。
- **書き換え対象集合はマイルストーンのファイル 1 件**で、参照追随書き換えを伴わない。説明の更新は
  マイルストーンの id も title も変えないので、参照しているタスクは書き換わらない。
- **`## Description` 見出しを持たないファイルには書かない**。見出しごと作ることは書式の発明に
  当たり、条件 1 に反する。理由を述べて拒む。

**説明は空にできる**（2026-08-06 にユーザーが選択）。CLI は `-d` を省略すると
`Milestone: <name>` を置くので、説明の無いマイルストーンを CLI は作らない。それでも空を許すのは、
利用者が書いた説明を消す手段が他に無く、消した状態が可逆（また書けば戻る）だからである。同じ
判断を文書のタグ全消し（doc-10 §5、TASK-109）で既に下している。空にした場合、説明の本文範囲が
空になり、画面は「説明なし」を出す。

**行頭が `##` の行を含む説明は入力検査で拒み、理由を出す。** CLI は `-d` の値を検査せずに書くので
`## Notes` を含む説明は実在し得るが（2026-08-06 実測）、読み取り層は次の `##` で説明の本文範囲を
切るため、そのまま許すと保存した文字列の一部が次の読み込みで画面から消える。拒む位置は入力欄で
あり、doc-10 §7 の「ラベルにカンマを含められない」と同じ型の入力検査である。

## Consequences

- 望ましい帰結
  - 作成後に説明を直せる。マイルストーンの id と、それを参照するタスクの `milestone` 値は
    動かないので、説明を直すことが台帳上の同一性を壊さない。
  - 保存の耐久性と競合検出は既存の仕組み（decision-17・doc-9 §4）をそのまま引くので、
    新しい保証水準を宣言しない。
  - 提供しない操作区画（doc-10 §1）からマイルストーンの項目が無くなる。
- 費用・制約
  - **CLI のオプション検査を受けない**。書いたバイト列は CLI が検証しないので、書式の追随は
    Atlas の責任になる。これは外部エディタ経路（doc-8 §7）が既に負っているものと同種の責任だが、
    そちらは利用者の書き込みで、こちらは Atlas 自身の書き込みである点が違う。範囲を説明の本文に
    限り、frontmatter に触れないのはこの責任を最小にするためである。
  - **照合後競合窓**（doc-9 §4.1）は無くならない。版の照合とファイルの置換の間に入った外部変更は
    捕まえられない。窓は CLI 経由より短い（別プロセスの起動を挟まない）が、ゼロではない。
  - **例外が 1 件から増えるときは、上の 3 条件で判定する。** 条件を満たさないもの — 文書の削除
    （ファイルそのものを消す）・参照の全消し・assignee の解除・依存の全消し（いずれも frontmatter）
    — は本決定では通らない。「CLI に手段が無い」だけでは直接書き込みの理由にならない。
- 後続への影響
  - AGENTS.md §Updates と AGENTS.ja.md §更新を同内容で改訂する（本決定と同じ PR）。
  - doc-5 §1 に直接書き込み操作を定義し、§3 の操作写像へマイルストーン説明の更新を足し、
    §3.1 から「マイルストーン説明の更新」を外し、§3.2 の「作成後の説明編集は GUI に出さない」を
    改訂する。
  - doc-10 §6 の「作成後の説明の編集は提供しない」と、その理由を 2 か所に出す規則を撤去する。
    §9 の提供しない操作区画の件数は 2 件から 1 件（文書の削除のみ）になる。
  - doc-12 §8.4 は画面設計案 07 の**転記**なので直さない。原文が「作成後の説明の編集は提供しない」
    と述べており、そこから外れることは doc-10 §6 に逸脱として記録する（同節 3 件目、画面全体では
    5 件目）。
  - **CLI が `milestone update` 相当を持った場合は、この操作を CLI へ戻す。** そのときこの決定は
    条件 1 を満たす別の操作が現れるまで実例を持たなくなるが、3 条件そのものは残す。
