## Context

Windows で Backlog CLI が解決できず、doc-5 の更新アダプター全体（タスク作成・更新・
マイルストーン・文書）が発行不能になる（TASK-60、2026-08-01 に実機で確認）。decision-11 は
「macOS・Linux・Windows で同一に動く必要がある」と述べており、これは表明済みの要件に対する
欠陥である。用語を先に固定する。

- **実行ファイル解決の順序** … Backlog CLI のプロセスを起動する前に、どの絶対パスまたは
  プログラム名を `Command::new` へ渡すかを決める、上から順に試す規則の列。doc-5 §4 が
  「実行ファイルの解決だけを差し替え可能にする」と書いた継ぎ目の中身にあたる。
- **shim** … npm が global bin ディレクトリへ置く、`cli.js` を起動するための中継ファイル。
  Windows は `backlog`・`backlog.cmd`・`backlog.ps1` の 3 本、macOS・Linux は `cli.js` への
  symlink 1 本（2026-08-01 実測）。
- **プラットフォーム別実行ファイル** … backlog.md パッケージが `backlog.md-<platform>-<arch>`
  サブパッケージとして持つ、インタプリタを介さず起動できる単一の実行ファイル。

原因は 2 つの事実の組み合わせで、PATH の設定とは無関係である。

1. npm が Windows の bin ディレクトリへ置くのは shim 3 本だけで、`backlog.exe` を置かない
   （実機実測。`Get-Command backlog` の `CommandType` は `ExternalScript`）。
2. Rust 標準ライブラリの Windows 実装は、拡張子を含まない名前に `.exe` のみを付けて PATH を
   探し、`PATHEXT` を歩かない（`resolve_exe` が `set_extension("exe")` を無条件に適用する）。
   `update.rs` は `Command::new("backlog")` である。

同じ環境で `git`（`git.exe`）と `gh`（`gh.exe`）は解決できる。差は拡張子だけである。

**シェルを経由する必要は無い。** 2026-08-01 に npm パッケージを解剖したところ、
プラットフォーム別実行ファイルが存在した（macOS で `backlog.md-darwin-arm64/backlog`、
70,612,322 バイト。直接起動して `--version` が 1.48.0 を返す）。shim 3 本と `cli.js` は、
いずれも最終的にこの実行ファイルを spawn しているだけである（`resolveBinary.cjs` が
`require.resolve` で引く）。したがって `.cmd` / `.ps1` を起動する必要は無く、本物の PE の
絶対パスを `Command::new` へ渡せばインタプリタはチェーンに入らない。AGENTS の
「シェル文字列へ連結せず固定引数配列で実行する」と decision-15 が `ShellExecuteW` を選んで
避けた問題の双方を、**新しい例外を足さずに**満たす。AGENTS.md / AGENTS.ja.md は改訂しない。

決定にあたって検討した候補は TASK-60 の Description にある 4 つで、採否は次のとおり。
(b) PATH を自前で歩く は bin ディレクトリに `.exe` が無いので単体では解決しない。
(d) sidecar 同梱 は解決問題を消すが、版管理・プラットフォーム別バイナリ・更新追随の継続
コストを decision-7 が挙げたとおり負う。**同梱の可否は decision-7 の同梱検討契機に属する
判断であり、TASK-99 が扱う。** 本決定はそれを先取りせず、同梱が採られた場合に順序の 2 段目
が丸ごと不要になることを受け入れる。残る (a) と (c) は排他ではないので併用する。

## Decision

Backlog CLI の実行ファイルを、次の**実行ファイル解決の順序**で決める。上から順に試し、
最初に得られたものを `Command::new` へ渡す。解決の全体を doc-5 §4 の継ぎ目の内側
（`BacklogCli` の実装）に閉じ、操作写像・作業ディレクトリ・引数配列渡しは変えない。

1. **アプリ設定 `backlog_cli`**（decision-13 の設定ファイルに足す任意項目。値は実行ファイルの
   絶対パス）。値があれば、存在検査をせずそのまま使う。**存在しないパスを書いた場合も
   自動解決へ落とさない** — 落とすと綴り誤りが「なぜか別のものが動く」形で隠れ、利用者が
   直せる誤りが直せない誤りになる。起動失敗はそのパスを名指しして doc-5 §5 の起動失敗として
   報告する。
2. **Windows で、PATH 上に直接起動できる `backlog.exe` が無く、shim から
   プラットフォーム別実行ファイルへ到達できる場合**、その絶対パス。shim を見つけた
   ディレクトリを起点に、npm の global prefix が取る 2 通りの配置
   （`<bin>/node_modules/…` と `<bin>/../lib/node_modules/…`）と、サブパッケージが
   `backlog.md` の下にある場合と巻き上げられている場合を試す。**`backlog.exe` が
   PATH 上にある環境ではこの段を使わない** — Scoop 等の配布物や将来の sidecar が置いた
   ネイティブの実行ファイルを、npm のレイアウトで上書きしないためである。
3. **プログラム名 `backlog`**。macOS・Linux はここに到達し、`Command::new("backlog")` に
   よる PATH 解決という**現行の挙動そのもの**になる。Windows でも、1 と 2 が空振りした場合の
   最後の手段としてここへ来る（`backlog.exe` があれば OS が解決する）。

順序の 2 段目が参照する npm の内部レイアウトは実装詳細であり、npm 以外の導入形態
（Homebrew・bun・Scoop）では外れる。**外れた場合の回復手段が 1 段目である**：利用者は
設定ファイルへ絶対パスを 1 行書けば解決できる。1 段目を持たない設計は、外れた環境の利用者に
打つ手を残さない。

`backlog_cli` は当面**設定ファイル直書きのみ**とし、設定画面には出さない。UI 全面改修
（TASK-61〜79）が進行中で文言と配置が動いており、TASK-75 が設定ファイルを OS の
ファイルマネージャで開く導線を作る。設定画面へ出すかどうかは、その後に判断できる。

実行ファイル解決の順序が全段で空振りしたときの縮退（doc-5 §5、decision-7）は変えない。
表示文だけを改める：現行の「PATH 上に backlog CLI が見つかりません」は、順序が PATH だけでは
なくなるので偽になる。「backlog CLI の実行ファイルを解決できません」とする。

## Consequences

- 望ましい帰結
  - Windows で npm 導入の Backlog CLI が解決でき、更新経路の全面発行不能が解ける
    （decision-11 の「3 OS で同一に動く」を回復する）。
  - macOS・Linux は順序の 3 段目に到達し、渡すプログラム名が `"backlog"` のまま変わらない。
    現行経路を壊さないことが、条件分岐の結果ではなく**順序の構造**として保たれる。
  - シェル・`.cmd`・`.ps1` をどれも起動しないので、AGENTS と decision-15 の制約に新しい例外を
    足さずに済む。
  - npm 以外の導入形態が外れても、利用者は設定 1 行で回復できる。
- 費用・制約
  - 2 段目は npm のパッケージ内部レイアウトに依存する。backlog.md が配置を変えれば外れる。
    外れても 1 段目と 3 段目は効くので、発行不能ではなく設定を要する状態に留まる。
  - `backlog_cli` は設定画面から編集できない期間がある。
  - 設定ファイルのスキーマに項目が 1 つ増え、**`schema_version` を 1 から 2 へ上げる**。
    decision-13 は項目の追加をスキーマ版の管理対象としており、版を上げないと、この項目を
    知らない旧ビルドが新しいファイルを自分の版として読み、serde が未知キーを捨てたうえで
    次の保存が値を消す。版を上げれば旧ビルドは読み取り専用へ縮退してファイルへ触れない。
    既存の版 1 のファイルは影響を受けない（欠けたキーは `#[serde(default)]` で埋まり、
    次の保存が版 2 を書く）。TOML の制約により、スカラーである `backlog_cli` は
    サブテーブルである `external_editor` より前に置く。
  - `backlog_cli` は設定画面に操作要素を持たないが、設定画面の保存は設定値ひとまとまりを
    ファイル全体として書き出すので、**保存経路がこの項目を引き継がなければ手編集の値が消える**。
    引き継ぎは `mergeDraft` の責務とし、非空の `backlog_cli` から始める回帰テストで固定する。
- 後続への影響
  - decision-7 の「開発は PATH 上 `backlog` を前提とする」は**反転しない**。前提は保ったまま、
    「PATH 上に見つかるのが shim だけの環境がある」という実測に合わせて解決の順序を定める。
    decision-7 が sidecar 同梱時に差し替えると書いた「実行ファイルの解決」が、本決定の
    実行ファイル解決の順序である。
  - TASK-99 が sidecar 同梱を採る場合、同梱バイナリが順序の先頭（設定より後、PATH より前）に
    入り、2 段目は不要になる。そのとき本決定を改訂する。
  - doc-5 §4 の「PATH 上の CLI」の記述を本決定に合わせて改訂した。
