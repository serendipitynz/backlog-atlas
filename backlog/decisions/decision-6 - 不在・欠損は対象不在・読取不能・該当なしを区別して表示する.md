## Context

対象 Git リポジトリが無い、Backlog ルートが読めない、タスク ID に対応するコミットが
無い、といった不在・欠損時の画面表示を決める（TASK-10・TASK-11 に依存、TASK-13）。
スイムレーン（doc-7）と詳細（doc-8）の双方での扱いを含める。争点は、見かけが似た
「何も出ない」状態が、原因の異なる複数事象を一括りにしてしまうことである。用語を
先に固定して事象を分ける。

Git 関連の状態は 2 軸に分ける。**Git リポジトリ状態**（project_root が Git リポジトリ
として在るか）と **Git remote 状態**（対象リポジトリに remote が構成されているか）は
独立で、リポジトリが在って remote だけが無いことがある。remote 無しをリポジトリ不在へ
畳み込まない（doc-6 の通り、コミット検索は remote 無しでもローカル Git だけで成立する）。

- **Git 対象不在** … project_root が Git リポジトリでない（`.git` を持たない等）状態。
  ローカルコミット検索・履歴の前提を欠く。remote の有無はこの状態に含めない。
- **Git remote 不在** … Git リポジトリは読めるが、remote が構成されていない（doc-3 の
  Git remote 有無属性が偽）状態。Git 対象不在とは別。ローカルコミット履歴は取れるため、
  remote 依存（コミット・PR 関連解決）だけを縮退させ、ローカル履歴表示は保つ（doc-6）。
- **ルート読取不能** … doc-4 の同名事象。config.yml や tasks が無く Backlog ルート
  全体を読めない事象。
- **コミット該当なし** … Git リポジトリは読めるが、コミット検索（doc-6）が当該
  TASK-ID を含むコミットを 1 件も返さない事象。

これらを同じ「空表示」に丸めると、利用者は「まだコミットしていないだけ」なのか
「repo を認識できていない設定の問題」なのか「Backlog ルート自体が壊れている」のかを
区別できない。原因ごとに次の行動（コミットする／台帳設定を直す／ルートを直す）が
違うため、表示で区別する必要がある。doc-4・doc-6・doc-7・doc-8 は既に各事象を
別事象として扱っており、本決定はその表示表現を確定する。

## Decision

不在・欠損を単一の空表示に丸めず、事象ごとに区別して表示する。原因と次の行動が
伝わる表現を、スイムレーンと詳細の双方で使い分ける。

### 事象ごとの表示

- **ルート読取不能**: 当該プロジェクト行（doc-7）を消さず、行全体を読取不能として
  示し、理由（config.yml/tasks が読めない等）を添える。詳細は開けないか、開いても
  読取不能を示す。他プロジェクト行には影響させない（doc-4）。
- **Git 対象不在**: Backlog ルートは読めるためタスク・スイムレーンは通常表示する。
  Git 履歴欄（doc-8）だけを「Git 対象不在」として示す。project_root が Git リポジトリ
  でないためローカル履歴・関連解決のいずれも出せない旨を添える。
- **Git remote 不在**: Git リポジトリは読めるため、ローカルコミット履歴は通常どおり
  表示する（remote 無しでも成立、doc-6）。remote 依存の解決（コミット・PR 関連解決）
  だけを縮退させ、その部分に「remote 未設定のため関連解決なし」を添える。台帳の Git
  remote 有無属性（doc-3）に紐づく状態であることを示し、設定で解消しうることが分かる
  表現にする。ローカル履歴まで消さない（本決定で分離した要点）。
- **コミット該当なし**: Git リポジトリは読めるため、Git 履歴欄を「対応コミット無し」
  として示す。これは正常状態（未着手・未コミット）でありうるため、エラーではなく
  中立の「該当なし」として出す。Git 対象不在とは別表現にする。

### 空・不在・失敗の区別（スイムレーン）

- **空セル**: 該当タスク 0 件のセルは空で示す（正常）。
- **未分類区画**: 列対応しない status は未分類区画（decision-4）。不在・欠損とは別。
- **読取不能行**: ルート読取不能はセルを空にせず、行単位の読取不能表示にする（上記）。

「該当タスクが無い（空セル）」「status が列に対応しない（未分類区画）」「ルートが
読めない（読取不能行）」を、スイムレーン上で見分けられるようにする。

### エラー提示方針

- **正常な不在は中立表示**: コミット該当なし・空セルは、利用者の作業がまだ無いだけの
  正常状態でもあるため、エラー色・警告記号を使わず中立に出す。
- **設定・破損はエラー提示**: ルート読取不能は、設定または破損の問題として、理由と
  対処の手掛かり（どのファイルが読めないか）を添えてエラーとして出す。Git 対象不在・
  Git remote 不在はその中間で、エラーではなく「未設定」の状態として、台帳属性に紐づく
  ことを示す。Git remote 不在ではローカル履歴を保ったまま関連解決部分だけを縮退させる。
- **解析縮退・競合との区別**: 本決定の不在・欠損は、doc-4 の縮退表示（解析エラー）や
  doc-9 の競合（版ずれ）とは別事象として、別の表現にする。三者を同じ印へ混ぜない。

## Consequences

- 望ましい帰結
  - 利用者が、次に取るべき行動（コミットする／台帳設定を直す／ルートを直す）を
    表示から判断できる。原因の異なる「空」を取り違えない。
  - スイムレーンで、正常な空と異常な読取不能を行・セルの単位で見分けられる。
  - remote 未設定のローカルリポジトリでも、ローカルコミット履歴が消えず参照できる。
    remote 依存（関連解決）と非依存（ローカル履歴）で縮退範囲を分けたためである。
- 費用・制約
  - 表示に、空セル・未分類区画・読取不能行・Git 対象不在・Git remote 不在・
    コミット該当なし・解析縮退・競合という複数の表現を用意し、混同しない表現規則を
    保つ必要がある。
- 後続への影響
  - スイムレーン（doc-7）・詳細（doc-8）は本決定の区別に沿って各表示を具体化する。
  - 解析縮退（doc-4）・競合（doc-9）とは別表現を割り当てる。表現の視覚設計は実装時。
