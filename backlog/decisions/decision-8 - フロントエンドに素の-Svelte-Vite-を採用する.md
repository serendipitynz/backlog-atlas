## Context

decision-1 は Tauri（Rust バックエンド＋ Web フロントエンド）を採用したが、
Web フロントエンドの UI 技術は未確定のまま残した。TASK-25（雛形作成）で三つを
確定させ、その記録は Implementation Notes に置いた。本 ADR はその判断を決定記録
として独立させ、却下した候補と却下理由を明示するものである。判断は 2026-07-23 の
TASK-25 で行われ、本 ADR はその記録である。

TASK-25 が確定させた判断は一つではなく三つある。まとめて「フロントエンド構成」と
呼ぶと却下理由がどれに掛かるか分からなくなるため、本 ADR は次の三つを別々に扱う。

- **UI 記述層の判断** … 画面を記述する UI フレームワークをどれにするか。
- **アプリ枠組みの判断** … ルーティング・SSR 機構・adapter を持つ枠組みを使うか、
  素のフレームワークで済ませるか。
- **ビルド系の判断** … 開発サーバとバンドルの手段をどうするか（無ビルドも含む）。

**採用時に比較した候補**（採用時に比較した候補とは、その依存を採用した時点で実際に
俎上へ載せ、比較のうえ却下した選択肢を指す）は、UI 記述層で React・Vue、アプリ
枠組みで SvelteKit、ビルド系で無ビルドの vanilla、および文書生成向けの Astro で
ある。

評価軸は次の四つとした。

- 本番依存の数と量（AGENTS「Dependencies」の依存最小方針）。
- スコープドスタイルを追加ランタイム依存なしに書けるか（ユーザー方針で Tailwind は
  不採用、スコープドスタイルが基本）。
- doc-7・doc-8・doc-9 が要求する動的 SPA（スイムレーン、タスク詳細、編集セッション、
  競合検出と再読込）を素直に書けるか。
- Tauri の単一ウィンドウ構成に対する過不足。

## Decision

UI 記述層に **Svelte 5**、アプリ枠組みは **素の Svelte**（SvelteKit を使わない）、
ビルド系に **Vite + TypeScript** を採用する。スタイルはコンポーネントスコープド
SCSS（Svelte の `<style lang="scss">`）を基本とし、全体最小限のみ `src/app.scss`
に置く。

### 採用理由

- **Svelte 5（UI 記述層）**: コンポーネントスコープドスタイルが言語ネイティブで、
  追加ランタイム依存なしにスコープド SCSS 方針を満たす。コンパイル時にランタイムが
  ほぼ消えるため、本番依存が候補中で最小になり、依存最小方針に最も適合する。
- **素の Svelte（アプリ枠組み）**: 単一ウィンドウの Tauri SPA にはルーティングと
  SSR 機構が要らない。枠組みを持たない分、本番依存と設定が減る。
- **Vite + TypeScript（ビルド系）**: 上記の SPA 要件を満たすには、コンポーネントの
  コンパイルと型検査が要る。Vite は Svelte の公式プラグイン経路が整っており、
  Tauri の開発サーバ連携も既製の構成で足りる。

### 却下した候補と却下理由

| 判断 | 候補 | 却下理由 |
|---|---|---|
| UI 記述層 | React + Vite | 動作はするが、`react` + `react-dom` がランタイムとして本番依存に残り、Svelte より重い。Tauri はシステム WebView を使うため実害は小さいと整理したうえで、依存最小方針を理由に作成者が Svelte を選択した。 |
| UI 記述層 | Vue | React と同じくランタイムが本番依存に残る。スコープドスタイルは満たすが、依存量で Svelte に劣り、優先する理由が無かった。 |
| アプリ枠組み | SvelteKit | `create-tauri-app` の svelte テンプレートの既定がこれ（`@sveltejs/kit` + `adapter-static`）だが、ルーティング・SSR 機構・adapter は単一ウィンドウの Tauri SPA には過剰で、依存最小方針とずれる。雛形は素の Svelte + Vite へ組み替えた（`src-tauri` は流用）。 |
| ビルド系 | 無ビルドの vanilla | doc-7・doc-8・doc-9 の画面は状態を持つ動的 SPA であり、無ビルドで書くと状態管理を自前で持つことになる。ビルド段が既に要るという前提のもとでは、SCSS も併せて使えるビルドありの方が総量で小さい。 |
| UI 記述層 | Astro | 静的サイト生成向けであり、動的 SPA には不適。ユーザー方針上は SCSS との相性が良い選択肢だが、本アプリの画面要件と合わない。 |

## Consequences

- 望ましい帰結
  - 本番依存が Tauri・`serde`・`@tauri-apps/api` に収まり、UI フレームワーク由来の
    ランタイム依存が増えない。
  - スコープドスタイル方針（Tailwind 不採用）が、追加依存なしに言語機能だけで
    満たされる。
  - dev 依存はツールに限定される（`vite`, `@sveltejs/vite-plugin-svelte`, `svelte`,
    `svelte-check`, `sass`, `typescript`, `tslib`, `@tauri-apps/cli`）。
- 費用・制約
  - ルーティングが要る画面構成になった場合、SvelteKit を入れ直すか、軽量ルータを
    別途選定する必要がある（本 ADR の再検討事項）。
  - `create-tauri-app` の既定テンプレートから外れているため、テンプレート更新の
    恩恵を自動では受けられない。
- 後続への影響
  - エディタ部品は doc-8 の前提に従い Ace を vendored + `textarea` フォールバックで
    導入し、npm 依存にはしない（後続の editor タスク）。
  - 外部エディタ・URL オープン（`tauri-plugin-opener` 等）は未導入。導入時は
    AGENTS の依存ゲートに掛ける。
