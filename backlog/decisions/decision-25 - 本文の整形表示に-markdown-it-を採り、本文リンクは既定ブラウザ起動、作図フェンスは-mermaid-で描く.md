## Decision

判断は 1 つではなく 3 つある。まとめて「Markdown 対応」と呼ぶと却下理由がどれに掛かるか
分からなくなるため、**decision-8 が 1 ADR に 3 判断を並べた形に倣って**別々に扱う。

- **整形手段の判断** … 本文の Markdown 記法を何で解釈して描くか。
- **本文リンクの判断** … 整形表示の中に現れた `<a>` を押したとき何が起きるか。
- **作図の判断** … 作図フェンスを描くか、描くなら何で描くか。

### 判断 1 — 整形手段は markdown-it

**`markdown-it` を本番依存として採り、導入範囲を 整形表示 に限る**（採った版は 15.0.0）。
**dev 依存は増えない** — mallow は `@types/markdown-it` を持つが、**15.0.0 は型定義を同梱する**
（`dist/markdown-it.d.mts`。2026-08-11 に導入して確認した）ので別パッケージが要らない。

- **整形表示 にするのは 5 か所**: タスクの Description・実装計画・実装ノート、文書の本文、
  マイルストーンの説明。**画面ごとの割当は doc-8 §9 が持つ。**
- **そのまま表示 のまま残すのは 2 つ**: 未知セクションの 本文断片（doc-4 §4）と、編集セッションの
  入力欄（AC #6）。前者は不整合区画の中の「Atlas が解さなかった断片をそのまま見せる」項目なので、
  整形すると区画自身の主張と反する。
- **AC 項目は 整形表示 にしない。** doc-8 §2.1 は AC を「4 区画の本文ブロック」の 1 つとして
  数えているが、実装は行の中のインライン文字列として描いており、**整形の対象を数えると単位が
  分かれる**（区画で数えれば 4 分の 1、値で数えれば項目 N 個）。実測でインライン記法を使う AC が
  1% であることを添えてユーザーへ出し、**含めない**で確定した。48rem の行長上限（doc-8 §2.1）は
  従来どおり AC にも掛かる — あの上限が対象にしているのは 1 行の長さであって、整形の有無ではない。
- **生 HTML は解釈しない**（`html: false`）。escape すると **現在と同じ見え方になる**（いまも文字と
  して見えている）一方、解釈すると散文の中の `<details>` が本物の開閉部品になる。
- **裸 URL はリンクにする**（`linkify: true`）。実測 0 件だが、これから書かれる。
- **画像は描かず alt を文字として出す。** 実測 0 件であり、ローカル画像を描くには `asset:` の
  capability を足すことになって導入範囲が広がり、リモート画像は**台帳の内容がネットワークを叩く**
  ことになる。
- **タスクリストは自前の core 規則 1 本で描く**（プラグインを足さない）。
- **整形が例外を投げたら そのまま表示 へ落とす。** 画面が本文を失わないことを、レンダラの
  正常動作に依存させない。

### 判断 2 — 本文リンクは既定ブラウザ起動

**`http`／`https` の 本文リンク だけをリンクとして描き、押下で 既定ブラウザ起動 を発行する。
新規依存は入れない** — 既存の関連付け起動（doc-8 §7、`editor.rs`）の launcher を、URL を取る
入口から再利用する。

- **それ以外（相対パス・`#`・`mailto:`・`file:`・`javascript:` など）はリンクとして描かず、
  文字として出す。** 押しても何も起きない控えを置かないためで、doc-11 §5 が無効化に理由を要求して
  いるのと同じ筋である（あちらは理由を書かせ、こちらは押せる見た目そのものを作らない）。
- **scheme 検査は Rust 側（境界）に置く。** 画面側の分類は防御の 2 枚目であって、唯一の門にしない。
- **新しい性質が 1 つ入る。** `commands.rs` の註が言う「The path is Atlas's own — resolved here,
  never taken from the frontend」を、URL は初めて破る（値が利用者の本文から来る）。**だから
  検査を境界へ置く**、が本判断の中身である。渡し方は従来どおり argv 1 要素または `lpFile` の 1 つで、
  シェル文字列を作らない（AGENTS）。
- **References・Pull Request・Git 履歴 が値として出している 参照 URL 4 か所は、本決定の範囲外**
  （`TaskDetail.svelte:701`・`:1597`・`:1631`、`GitHistory.svelte:153`）。TASK-142 AC #4 が言うのは
  本文リンク だけである。**測って報告し、直さない。**

### 判断 3 — 作図フェンスは mermaid で描く

**`mermaid` を本番依存として採り、導入範囲を 作図結果 の描画に限る。**

- **遅延読込 に限る。** 作図フェンス が現に本文にあったときだけ読む。実測 2.9MB は全部が遅延
  chunk なので、**起動時費用は 0** である。
- **`securityLevel: 'strict'`**（mermaid 自身の既定）。Atlas は作図の `click` 指令を使わないので、
  ここを緩める理由が無い。`'sandbox'` は各図を iframe に入れるのでテーマ追随ができなくなる。
- **CSP との関係は本 PR で実測し、doc-11 §14.5 が記録した。****`style-src` に `'unsafe-inline'` が
  要る。** mermaid は描いた SVG の中へ `<style>` を入れるので、出荷物の形（外部 CSS 1 本）を CSP ヘッダ
  付きで配って測ると、`style-src 'self'` では**図は描かれるが色を失い**（`fill` が
  `rgb(236, 236, 255)` → `rgb(0, 0, 0)`）、違反が WebKit 111 件・Chromium 192 件出る。`'unsafe-inline'`
  を足すと 0 件で色も戻る。**要求しているのは mermaid だけで、Atlas 自身ではない** — 同じ CSP で
  作図フェンスを持たない 整形表示 の本文は両エンジンとも違反 0 件、外部 CSS もインライン style 属性も
  効いたままだった。**TASK-98 の選択は「`'unsafe-inline'` を入れる」か「作図結果 の色を捨てる」の 2 つ**
  である（前者は `style-src` 全体に効くので、この 1 か所のために全画面のインライン style を許すことになる）。
  **最初の見積りは外れていた** — `insertRule` が CSP の対象外であることから「要らない可能性」を残して
  いたが、効いていたのは `<style>` 要素の側だった。
- **この台帳に 作図フェンス は 0 件である。** 入れる根拠は「利用者がこれから書く」ことと
  「backlog.md ブラウザ表示 が現に描く（準拠の相手が持っている）」ことで、**いま読めない本文が
  あることではない。** ユーザーは 2026-08-11 に、この事実を添えたうえで「入れる」を確定した。

### 却下した候補と却下理由

**採用時に比較した候補**（decision-8 の定義: その依存を採用した時点で実際に俎上へ載せ、比較のうえ
却下した選択肢）を判断ごとに分ける。

## Consequences

- 望ましい帰結
  - タスクの Description・実装計画・実装ノート、文書の本文、マイルストーンの説明が、
    見出し・強調・表・コード・タスクリストとして読める。**doc-10 §5・§6 の「整形しない」は
    本決定で反転する。**
  - **整形についての契約が doc に載る。** 着手時、「整形しない」を述べていたのは doc-10 §5・§6 と
    `TaskDetail.svelte:15` のコード註だけで、doc-10 が「タスク詳細が Description に対して取って
    いるのと同じ扱い」と帰属させた先（doc-8）には整形の語が 1 度も無かった。doc-8 §9 がそこを埋める。
  - 本文リンクが押せる。Atlas には URL が無い（doc-8 §2.2）ので、外へ出る導線は本文と References に
    しか無く、そのうち本文の側が届くようになる。
- 費用・制約
  - **本番依存が 2 本増える**（`markdown-it`・`mermaid`）。`mermaid` は推移的に `d3`・`cytoscape`・
    `katex`・`marked`・`dompurify`・`roughjs` 等を伴う。導入範囲は前者が 整形表示、後者が
    作図結果 の描画に限る。**dev 依存は増えない**（`markdown-it` 15.0.0 が型を同梱する）。
    採った版は `markdown-it` 15.0.0・`mermaid` 11.16.1 である。
  - **出荷物が増える。** `markdown-it` は起動時に読む側へ入り（配布物の ESM は 117.5KB、
    同梱の minified UMD は 114.1KB。現行の出荷 JS は 297KB）、`mermaid` は 遅延読込 の chunk として
    増える（起動時 0）。**実バンドルでの増分は実装後に測る** — 上の 2 値はパッケージの配布物の
    大きさであって、tree shaking を経たこのアプリの出荷物の増分ではない。
  - **`{@html}` が Atlas に初めて入る。** 注入面は 整形表示 の 1 か所に閉じる。安全性は
    `html: false`（生 HTML を DOM にしない）と markdown-it の `validateLink`（`javascript:` 等を
