## Context

TASK-103 は UI の文言を英語と日本語で切り替えられるようにすることを求め、切替の既定を OS の
言語に追随させ、選択をアプリ設定へ永続することと、抽出漏れを検出する手段を持つことを受入条件に
挙げている。本 ADR は、そのための手段の選定と、訳す範囲の境界を決める。

本 ADR は次の 4 語を導入する。

- **表示言語** … Atlas 自身が描く画面文の言語として `settings.toml` が持つ選択を指す。
- **言語未選択** … 表示言語が選ばれておらず、OS の言語に追随している状態を指す。
- **文言表** … 1 つの言語について、文言鍵 から画面へ出す文字列への対応を持つ記録を指す。
- **文言鍵** … 文言表を引く識別子を指す。
- **失敗理由符号** … Rust が失敗の理由を文ではなく serde の variant token と引数の組で渡す値を指す。

### 対象の規模と源泉

コメントを剥がして数えた画面文の量は **46 ファイル・941 行**である（剥がし方は
`screen-text.test.ts` の同じ手順を使った。最大は `ProjectDetail.svelte` 185・`TaskDetail.svelte`
105・`edit.ts` 88）。

**画面文の源泉は 4 つあり、その一覧は `screen-text.test.ts` が既に持っている** — フロントエンドの
`.ts` と `.svelte`、crate の `.rs`、`index.html` の `<title>`、`tauri.conf.json` の窓 `title` である。
語の一覧より先に源泉の一覧を数えたのは、フロントエンドだけを見ると crate が組み立てる失敗の理由を
数え落とすためで、あの走査が同じ理由で 4 つを分けて舐めている。

**crate の側の画面文は 4 ファイル・約 28 本である** — `editor.rs` 17（`ShellExecuteW` の失敗理由と
SE_ERR の表）・`history.rs` 7（`git`・`gh` の失敗）・`external.rs` 3（外部コマンドの起動失敗）・
`update.rs` 1（`MILESTONE_DESCRIBE`）。これらは `CommandError` などの `detail` に載り、画面がその
まま描いている（`TaskDetail.svelte` の 保存できませんでした と 通知、`GitHistory.svelte` の
Git 履歴を読めません、`Swimlane.svelte` の ルート読取不能）。

### 依存の候補

AGENTS.md Dependencies の依存ゲートに掛かるので、候補の直接依存数を実測したうえでユーザーへ
提示した（2026-08-16）。

| 候補 | 版 | 直接依存 |
|---|---|---|
| 依存を増やさない（型付きの文言表 ＋ `Intl.PluralRules`） | — | 0 |
| `typesafe-i18n` | 5.27.1 | 0（コード生成を挟む） |
| `svelte-i18n` | 4.0.1 | 7（`intl-messageformat`・`esbuild`・`cli-color`・`tiny-glob` ほか） |
| `@inlang/paraglide-js` | 2.24.1 | 7（`@inlang/sdk`・`unplugin`・`commander` ほか） |

## Decision

### 1. 新規依存を増やさない

**多言語対応のために production dependency を増やさない。** 文言表は言語ごとの
`Record<文言鍵, string>` として TypeScript で持ち、複数形は標準の `Intl.PluralRules` で選ぶ。

- **複数形が要るのは英語の可算名詞だけである。** 日本語は数で語形が変わらないので、ICU
  messageformat の表現力はこの木ではほぼ余る。`Intl.PluralRules` は webview に載っている標準の
  ものなので、これに依存を払う理由が無い。
- **抽出漏れの検出は、ライブラリを入れるより型のほうが強い。** 文言鍵 の集合を日本語の文言表から
  導き、英語の文言表をその集合で型付けすれば、**訳の欠落は `pnpm run check` が落とす**。多くの
  i18n ライブラリは鍵の欠落を実行時にしか言わず、その画面を開くまで分からない。
- **書式化は `Intl` が持つ。** 日付と数の書式は本 ADR の対象外である（下の「訳さないもの」）。
- `typesafe-i18n` は直接依存 0 だが、生成物と生成器という 2 つ目のビルド段を増やす。得られる型
  安全は上の tsc による判定と実質同じものなので、段を増やす側を採らない。

### 2. 表示言語はアプリ設定へ持ち、既定は 言語未選択 とする

**表示言語は `settings.toml` の `language` として持つ**（decision-13 のアプリ設定ファイル）。
**型は表示テーマと同じく「選ばれていない」を表せるもの**（Rust は `Option<String>`）で、値が無い
状態が 言語未選択 である。

- **言語未選択 のとき、画面文は `navigator.language` の先頭 subtag で選ぶ** — `ja` なら日本語、
  それ以外は英語。OS 側が変われば次の起動で追随する。
- **OS の言語を読むために Tauri のプラグインを入れない。** `@tauri-apps/plugin-os` は npm と cargo
  の両方に依存を足すが、`navigator.language` は webview が既に持っている。
- **画面の語は「システム設定に従う」と対にする** — 表示テーマの 未選択 が同じ語を使っており
  (`THEME_UNSET_LABEL`)、同じ性質の選択肢を 2 通りに呼ばない。
- **項目の追加なので `schema_version` を 4 から 5 へ上げる**（decision-13 の Consequences が
  項目の追加をスキーマ版の管理対象と定めている）。上げないと、この項目を知らない旧ビルドが新しい
  ファイルを自分の版として読み、serde が未知キーを捨てたうえで次の保存が値を消す。
- **decision-13 の項目表に 表示言語 の行を足す。** 「読んだものをどう見せ、どう操作するか」に
  属し、特定の台帳エントリに紐づかないという、あの表の帰属条件をそのまま満たす。

### 3. Rust の失敗理由は 失敗理由符号 で渡す

**crate は失敗の理由を日本語の文として組み立てるのをやめ、失敗理由符号 で渡す。画面へ出る文は
フロントエンドが文言表から組む。**

- **`detail` は診断用の文として残す。** **この形はこの木に既にある** — `CommandError` の
  `ledgerRefused` が `reason: LedgerRefusal` と `detail` を分けて持ち、`wire.ts` の註が
  「画面の文は `reason` から来る」と述べている。本 ADR がするのは、`detail` が画面へ届いている
  残りの variant を同じ形へ揃えることである。
- **crate に言語を渡す案は採らない。** wire は変わらずに済むが、文言の置き場が 2 言語 × 2 実装へ
  分かれ、抽出漏れの走査も 2 系統要る。**規則を書く場所は 1 か所にするという既存の方針**に反する。
- **日本語のまま残す案も採らない。** 英語表示のとき失敗の理由だけ日本語で出ることになり、
  TASK-103 が求める「全画面の文言」を満たさない。
- **`editor.rs` の SE_ERR の表は既に数値の `match` である**ので、符号化の相手は数値そのものでよい。

### 4. 抽出漏れの検出は 2 段で持つ

TASK-103 AC #3 の手段は 2 つの判定の組である。**片方だけでは足りない** — 前者は文言表に鍵が在る
ことしか見ず、後者は鍵が引かれているかを見ないためである。

- **訳の欠落は tsc が落とす**（`pnpm run check`）。英語の文言表を日本語の文言表から導いた 文言鍵 の
  集合で型付けし、欠けた鍵と余った鍵の両方をコンパイル時の誤りにする。
- **源泉に残った日本語は `screen-text.test.ts` の走査が落とす。** 既存の 3 種（設計文書参照・
  版表記・設計語）に 4 本目として足す。**走査する範囲は既存の 4 つの源泉と同じ**で、この走査が
  源泉を数え落とさないための検査（`scans the crate and both titles too`）も既に在る。
- **除外するのは 文言表 の 2 ファイルだけで、それが唯一の例外である。** `src/lib/messages/ja.ts` は
  日本語を持つのが役目なので、除外しなければこの走査は必ず落ちる。`en.ts` も同じ扱いにする —
  あちらは言語名を自称で持ち（`languageName.ja` が `日本語`）、**それは訳し漏れではなく訳さないと
  決めた値だからである。** 除外の単位はファイルであって語ではない: 語で除くと、同じ字を含む本物の
  訳し漏れまで通る。**2 つのファイルの項目が同じかどうかは除外の根拠にならない** — 字の並びを見る
  走査は一致を参照しないので、**そこに理由を置くと、除外が要るのに要らないと読める。**

### 5. 訳さないもの

**Atlas が訳すのは Atlas 自身が描く画面文だけである。** 次は表示言語 が何であっても原文のまま出る。

- **読み取り対象の Backlog 管理ファイルの中身** — タスク本文・title・status の綴り・ラベル・
  assignee・文書と決定事項の本文。これらは対象プロジェクトのものであって Atlas のものではない。
- **日付** — `updatedDate` などは Backlog が書いた文字列のまま画面へ届く。**この木には
  `Intl.DateTimeFormat` が 1 か所も無く**、Atlas は日付を書式化していない。表示言語 で書式が
  変わるように読める記述を足さない。
- **識別子** — `TASK-N`・`<project-slug>:<TASK-ID>`・doc と decision の id。

## Consequences

- 望ましい帰結
  - production dependency が 4 件のまま変わらない（decision-8 の 素の Svelte + Vite、decision-9・
    decision-13 の「新規依存を増やさない」と同じ帰結）。
  - 訳の欠落がコンパイル時に落ちるので、その画面を開くまで分からない状態にならない。
  - 失敗の理由が符号になることで、画面が理由ごとに違う扱いをする余地が開く（いまはどの理由も
    文として同じ場所に出るだけである）。
- 費用・制約
  - 画面文を足す回は、日本語と英語の 2 つを書く。TASK-103 より後ろのタスクはすべてこれに当たる。
  - `CommandError` の形が変わるので、`wire.ts`・`wire_fixtures.rs`・`wire-fixtures/*.json`・
    `wire_tokens.json` が同じ PR で動く。**符号は serde が綴るので、`wire_tokens.json` の完全性は
    既存の網羅 `match` が保つ。**
  - 複数形と語順は文言表の中で解く。英語の 1 件・複数の差は `Intl.PluralRules` で選ぶが、**選ぶのは
    どの文言鍵を引くかであって、文の組み立てではない。**
  - アプリ設定の項目が 1 つ増え、`mergeDraft` と `normalize` の両方を通す必要がある。
- 後続への影響
  - decision-13 の項目表と `schema_version` が動く（4 → 5）。置き場と縮退の規則はあちらのままで、
    本 ADR は項目を 1 つ足すだけである。
  - decision-12 の 未選択 と本 ADR の 言語未選択 は同じ形の選択肢になる。**片方の語を変える回は
    もう片方も見る。**
  - 画面文を持つ既存の doc（doc-7・doc-8・doc-10・doc-11）は、文そのものを日本語で引用している。
    **doc が引用する文は日本語の文言表の側を指す**ものとし、英語の綴りを doc へ二重に書かない。
