## Context

Backlog.md の cross-branch 集約を Atlas が初期版でどこまで再現するかを決める
（TASK-3・TASK-5 に依存、TASK-6）。**cross-branch 集約**とは、現在 checkout 以外の
ブランチにあるタスクファイルも読み集め、1 つの盤面へ束ねる扱いを指す。対して
**現在 checkout 限定**とは、読み取り対象を現在 checkout の作業ツリー上のファイルに
限り、他ブランチを読まない範囲設定を指す。

前提は decision-2（読み取りは Backlog 管理ファイルの直接解析、更新は Backlog CLI へ
委譲）と doc-4（読み取り層は台帳エントリの各 Backlog ルートを走査し、現在 checkout
のファイルを解析してドメインモデルを構築する）。decision-2 は既に
「初期版は現在の checkout のみに限定する（範囲確定は TASK-6）」と方向を示しており、
本決定はその範囲を確定し、限定に伴う扱いと将来拡張の余地を明示する。

cross-branch 集約を初期版で再現しないと判断する根拠。

- 直接解析（decision-2）は、作業ツリー上に現在存在するファイルを読む。他ブランチの
  タスクを集めるには、各 Backlog ルートで `git show <branch>:<path>` 相当や
  worktree 列挙といった Git 追加操作が要り、読み取り層が Git のブランチ状態へ依存
  する。これは「ファイルを解析するだけ」という decision-2 の単純さを崩す。
- Atlas は複数プロジェクト（複数 Backlog ルート）を同時に購読読みする。各ルートで
  さらに複数ブランチを畳み込むと、同一 id が別ブランチに別内容で存在する場合の
  重複解決という新たな争点が生じ、初期版の範囲を過度に広げる。
- 個人利用の初期版（doc-2）では、日常の閲覧・優先順位判断はまず現在 checkout の
  盤面で足りる。cross-branch は Backlog.md 側にも存在する高度な状態で、初期版の
  完了を遅らせてまで先取りする必要が薄い。

## Decision

cross-branch は初期版で**現在 checkout 限定**を採用する。読み取り層は、各 Backlog
ルートについて現在 checkout の作業ツリー上のファイルだけを走査対象とし、他ブランチ
のタスクファイルは読まない（decision-2・doc-4 と整合）。スイムレーンほか横断表示は、
現在 checkout の盤面を対象とする。

将来 cross-branch 集約を扱うための拡張余地を次のとおり残す。

- 走査対象の決定を読み取り層の一箇所（doc-4 の「ディレクトリ走査」段）に閉じ込め、
  「現在 checkout の作業ツリー」を走査ソースの一実装として扱う。ブランチ指定や
  worktree 列挙を別の走査ソースとして後から差し込めるようにし、ドメインモデルと
  上位の表示層は走査ソースの違いに依存させない。
- ドメインモデルのタスクに、由来ブランチを持たせられる余地を残す（初期版は
  現在ブランチ固定で省略可）。cross-branch を導入する際に、同一 id が複数ブランチに
  現れた場合の重複解決規則を別途決める前提とする。
- ファイル監視による再読み込み（TASK-14）は現在 checkout を単位に設計し、将来
  ブランチ切替を再走査契機として追加できるようにする。

## Consequences

- 望ましい帰結
  - 読み取り層が Git のブランチ状態へ依存せず、decision-2 の「ファイルを解析する
    だけ」を保てる。初期版の実装と検証が単純になる。
  - 同一 id の複数ブランチ重複という解決困難な争点を初期版から外せる。
- 費用・制約
  - 現在 checkout 外のブランチにのみ存在するタスクは初期版の盤面に現れない。
    利用者はブランチを checkout して Atlas を再読み込みする必要がある。
- 後続への影響
  - 走査ソースを差し替え可能にする内部境界を読み取り層に設ける（doc-4 の走査段）。
  - cross-branch 導入時は、由来ブランチの保持と同一 id 重複解決を別決定で扱う。
  - ファイル監視・再読み込み（TASK-14）は現在 checkout を再構築単位とする。
